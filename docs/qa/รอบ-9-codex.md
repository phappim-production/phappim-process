## สิ่งที่ต้องบอกคนหน้างานวันอบรม

- ถ้าเครื่องเต็ม ให้ดูเลขงานในข้อความใต้คิว งานพักและงานที่ส่งออกไม่นับว่าใช้เครื่อง ถ้าแก้ปัญหาเสร็จตอนเครื่องเต็ม งานจะกลับไปรอคิว
- ใช้ป้ายเครื่องและตัวเลขแยกสถานะบนหัวสถานีเป็นหลัก หัวคอลัมน์ “กำลังทำ” ในรุ่นนี้รวมบัตรงานพัก
- ตอนเริ่มเย็บตรวจรหัสบนตัวจักรจริงก่อนยืนยัน จักรใช้ร่วมไม่ต้องเลือก ถ้าคืนแล้วจะเหลือไม่ครบ ให้พักงานก่อน
- พนักงานใช้บัญชีตามสถานีที่จับคู่ ให้ฝ่ายผลิตจัดคิว จัดจักร และกดแก้แล้วทำต่อ ฝ่าย QC ตรวจยอดผ่านให้ครบก่อนปิดงานผลิต
- แอดมินบันทึกรับฟิล์มก่อนเริ่มรีดฟิล์ม และแนบ PDF ใบยืนยันที่เซ็นแล้วภายหลังได้ ใช้ QR บนใบปะงานเพื่อเปิดรายละเอียดหลังล็อกอิน

## ผลตรวจของ Claude (19 พ.ย. ค่ำ)

- รันซ้ำบน branch ของ Codex: ฐานข้อมูล 1,023 ผ่าน · Vitest 361 · node 119 · lint และ build ผ่าน ตรงกับรายงาน
- **แก้บั๊กระดับ 3 แล้ว:** หัวคอลัมน์บอก "กำลังทำ 2 งาน · พักงาน 1 งาน" (นับแยก) · กรณี `BUG:` เปลี่ยนชื่อเป็น "หัวคอลัมน์กำลังทำนับเฉพาะงานกำลังทำ · งานพักแยกบอก" และผ่านแล้ว
- Chrome บนเครื่อง Claude ผ่าน 30/31 · ข้อที่ไม่ผ่านคือ `1440/ใบปะงานและ QR` เพราะเครื่องนี้ไม่มีโปรแกรม `pdfinfo` (ไม่ใช่ปัญหาของระบบ · เครื่อง Codex ผ่าน)
- ยังไม่ได้ทดสอบ: แย่งเครื่องสุดท้ายจากสองเซสชันบน PostgreSQL จริง · สแกน QR จากใบพิมพ์ด้วยมือถือ (อยู่ในงาน Antigravity G10)
