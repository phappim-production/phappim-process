## ส่วน A — รูปยืนยันงานสถานี (PR 205 · ใหม่ ยังไม่มีใครใช้จริง · ฟีเจอร์ยังปิดบนระบบจริง) — ละเอียดที่สุด
เปิดฟีเจอร์ด้วยบัญชีเจ้าของ: ตั้งค่า → สถานี → รูปยืนยันงานที่สถานี → เปิดใช้ (หรือใช้ `demo-v3.mjs`) · ใช้รูปจริงหลายแบบ: JPG / PNG / HEIC ถ้ามี / ภาพแนวตั้ง-นอน / ภาพใหญ่ 10 MB+ / ภาพเล็กมาก / ไฟล์ที่ไม่ใช่รูปแต่ตั้งชื่อ .jpg
1. **ชิ้นแรก ทุกสถานีที่ติ๊ก** (พิมพ์ · รีด · รีดฟิล์ม · ตัด · ปัก · สกรีน): เริ่ม → ถ่าย 1 / 3 / 6 / 7 รูป → ส่ง (พร้อม/ไม่มีข้อความถึงแอดมิน) → กดเสร็จต้องไม่ได้ ระหว่างรอ → แอดมินผ่าน → ส่งรูปงานเสร็จ → กดเสร็จได้ · ไม่ผ่าน (เลือกเหตุผล / พิมพ์เอง / ทั้งสอง / ไม่ใส่) → หน้างานเห็นเหตุผล → ส่งใหม่ → ผ่าน
2. **สถานีที่ไม่ติ๊ก** (เย็บ · QC + Packing): ส่งรูปงานเสร็จอย่างเดียว · ส่งรูปชิ้นแรกต้องไม่ได้ · เย็บ: ฝ่ายผลิตส่งจากแท็บจักรเย็บ · QC: ต้องครบทั้งยอดตรวจและรูป
3. **ทุกบทบาท:** staff สถานีเดียว / หลายสถานี / สถานีอื่น (ต้องส่งไม่ได้) · หัวหน้าเฟส 1/2 · ฝ่ายผลิต · QC (ส่งได้เฉพาะ QC) · แอดมิน / ผู้จัดการ / เจ้าของ อนุมัติได้ · staff / QC / ฝ่ายผลิต อนุมัติต้องไม่ได้ (ลองเรียก RPC ตรงด้วย token ของบทบาทนั้นในระบบจำลองด้วย)
4. **ตัวดูรูปของแอดมิน:** ปัดซ้าย-ขวา · ลูกศรคีย์บอร์ด · เทียบม็อคอัพ (เลื่อนเส้นแบ่ง · งานไม่มีม็อคอัพ) · ซูม/ดับเบิลคลิก · รูปเปิดไม่ได้ (ลบไฟล์ในที่เก็บจำลอง / ลิงก์หมดอายุ) → ปุ่มผ่านต้องล็อก · **เน็ตช้า (หน่วงรูป 10 วิ)** → ปุ่มผ่านต้องรอจนรูปโหลดครบทุกรูป · 2 แอดมินตัดสินรูปเดียวกันพร้อมกัน
5. **ขอบเขตที่ยาก:** พักงานระหว่างรออนุมัติ → แก้แล้วทำต่อ / เครื่องเต็มกลับเข้าคิว (ต้องยังอยู่ในรายการรออนุมัติ) · **แบ่งงานระหว่างรอ** แล้วยกเลิกงานต้นทาง (ส่วนที่แบ่งต้องไม่ค้าง) · ส่งงานออกข้างนอกจากสถานีที่มีรูปค้าง · งานแก้จาก QC กลับมาสถานีเดิม (รอบใหม่ต้องถ่ายใหม่ · รูปรอบเก่าใช้ไม่ได้) · งานตัวอย่าง / Develop · งานยกเลิกระหว่างรอ · เจ้าของปิดฟีเจอร์ระหว่างมีรูปรอ (กดเสร็จได้ · ไม่เตือนต่อ) · เลิกติ๊กสถานีระหว่างรอ · งานที่เริ่มก่อนเปิดฟีเจอร์ (ต้องไม่บังคับรูป)
6. **เวลามาตรฐาน:** ช่วงรออนุมัติไม่นับเวลาสถานี/ช่วง · ช่วงที่พักงานซ้อนไม่หักซ้ำ · เทียบตัวเลขในรายละเอียดงาน / ป้ายเตือนบนการ์ด / รายงาน
7. **กล่องจดหมาย:** รออนุมัติ (แอดมิน ผู้จัดการ) · รอนานเกินเวลาที่ตั้ง 5/15/60 นาที (ผู้จัดการ ฝ่ายผลิต · เตือนครั้งเดียว) · ไม่ผ่าน (หัวหน้า พนักงาน ฝ่ายผลิต) · ปิดการแจ้งเตือนแต่ละชนิดในตั้งค่าแล้วไม่ส่ง
8. **ประวัติงาน + บันทึกการเปลี่ยนแปลง:** ทุกครั้งที่ส่ง/ผ่าน/ไม่ผ่าน/ส่งรูปเสร็จ อยู่ในประวัติพร้อมรูป · เปิด/ปิดฟีเจอร์ + เปลี่ยนเวลาเตือน + ติ๊กสถานี อยู่ในบันทึกการเปลี่ยนแปลง
9. **โหมดพม่า + มือถือ 375 px:** ทุกข้อความของขั้นรูป (ปุ่มถ่าย · ส่ง · รอ · ไม่ผ่าน + เหตุผล · error จากฐานข้อมูล) เป็นพม่า + ไทยตัวเล็ก · ปุ่มกล้องเปิดกล้องหลังบนมือถือ (ลองใน Chrome DevTools device + ถ้ามีมือถือจริงในวงแลน ใช้ IP เครื่องในวงแลนแทน 127.0.0.1 ได้ แต่ห้ามออกอินเทอร์เน็ต)
10. **ความปลอดภัยของรูป:** คนที่ไม่เห็นงานเปิดรูปได้ไหม · ลิงก์รูปแชร์ต่อแล้วหมดอายุไหม · อัปโหลดรูปเข้าโฟลเดอร์ของงานอื่น / สถานีอื่น / รอบอื่น แล้วส่งต้องถูกปฏิเสธ · ส่งรูปเดิมซ้ำ 2 ครั้ง

## ส่วน B — ของที่เพิ่มหลังรอบ 18 (PR 194–207)
1. **หน้าตา v3 (PR 205):** สีแบรนด์/สีสถานี/ลาย/ไอคอนครบทุกสถานี · เส้นทางงานบนการ์ด · สีสถานะยังตรงความหมาย (แดง/ส้ม/ฟ้า/เขียว) ไม่ชนสีสถานี · ทองใช้เฉพาะแบรนด์ · ภาพรวม "สถานีตอนนี้"
2. **รีวิว UI (PR 202–203):** ปุ่มเสร็จในคิวสถานีเห็นโดยไม่ต้องเลื่อนที่ 375 px (ไทย + พม่า) · งานที่กำลังทำขึ้นก่อนงานพัก · เมนูไทยทั้งหมด (ไม่มี Station / Audit Log / Roles ภาษาอังกฤษ) · "เลยกำหนด" / "รายงานปัญหา" ใช้คำเดียวกันทั้งระบบ + คู่มือ · พนักงานยังไม่จับคู่สถานี · supervisor เมนูคิวงาน/บอร์ด · ช่องจำนวน QC
3. **ฟอร์มใบยืนยัน:** ปุ่ม "เปิดฟอร์มใบยืนยัน (ใบใหม่)" ได้ฟอร์มว่าง + กล่องเปิดใบที่กรอกค้างกลับมา / ไม่ใช้ใบเดิม (PR 204) · ใบที่บันทึกเข้าระบบแล้วไม่ถูกเก็บแยก · เปิด `/confirmation` ตรงๆ ได้ใบเดิม · คำอธิบายใต้ตัวเลือก · ชื่อตัวเลือกที่เปลี่ยน (แขนแร็กแลน · ม้วนริม ซม.) ใบเก่าเปิดแล้วเป็นชื่อใหม่ · เลขเดิมคนละสินค้าบันทึกไม่ได้ (บอกให้ต่อท้ายเลข) · "อื่นๆ" แสดงข้อความที่พิมพ์ทั้งในฟอร์ม PDF และม็อคอัพ · ทำสินค้าถัดไป / ล้างฟอร์ม · หลายแบบ + หลายรูป (PR 197–199) · หน่วย ซม./นิ้ว (PR 195)
4. **งาน Develop / ตัวอย่าง (PR 200):** รับงาน Develop → ผ่านตัวอย่าง = จบไม่ผลิตจริง · คืนจักร / ยกเลิกการจอง · สลับ Develop ↔ ผลิตจริงในใบแก้ต้องไม่ได้
5. **กฎคิว (PR 200):** เริ่มงานที่ไม่ใช่คิวแรกต้องใส่เหตุผลทุกทาง (คิวสถานี · รายละเอียดงาน · จักรเย็บ) · เรียก `start_station` / `start_sewing` ตรงโดยไม่มีเหตุผลต้องถูกปฏิเสธ
6. **รูปย่อบนการ์ด + ลิงก์รูปคงที่ + โหลดบอร์ดครั้งเดียว (PR 200):** การ์ดใช้รูปย่อ · รูปไม่กระพริบเมื่อบอร์ดโหลดใหม่ · กด 1 ครั้งบอร์ดโหลดรอบเดียว (ดู network)
7. **ปิดงานที่ค้างจากรอบ 18:** R18-01 ถึง 04 ยังไม่กลับมา

## ส่วน C — ครบระบบ: ทุกบทบาท × ทุกเส้นทาง (ทำตามคู่มือทีละขั้น · ถ่ายภาพทุกจุดที่ติด) · **เปิดฟีเจอร์รูปไว้ตลอดส่วนนี้**
1. **ทุกเส้นทาง** (รวมผลิตข้างนอก · มีตัวอย่าง · Develop · ส่งออกต่างประเทศ) เดินครบจนจัดส่ง ด้วยคนที่จะกดจริง · หลังแต่ละขั้นตรวจบอร์ด ภาพรวม คิว กล่องจดหมาย ประวัติ รายงาน ของทุกบทบาทว่าตรงกัน
2. **แอดมิน:** ใบยืนยัน 1 ใบต่อกลุ่มสินค้า (ทั้ง 38 สินค้าผ่าน `confirmation-all.mjs` + กดมือ 8 กลุ่ม) → บันทึกเข้าระบบ → รับงาน → แนบ PDF → ฟิล์ม → ส่งออก/รับกลับ → แบ่งงาน → ผลตัวอย่าง → แก้ใบหลังรับงาน → จัดส่ง / ยกเลิกจัดส่ง → ม็อคอัพ ทำ/แก้/อนุมัติ · อนุมัติรูปชิ้นแรก
3. **ฝ่ายผลิต 2 คนพร้อมกัน:** เริ่ม/เสร็จ/พัก · เริ่มก่อนคิว · แทรกงานด่วน · จักร (เลือก/เสีย/คืน) · รายงานเกินเวลา · รูปงานเสร็จของเย็บ
4. **staff มือถือ 375 px โหมดพม่า:** สถานีเดียว / หลายสถานี / ยังไม่จับคู่ · รับทราบสเปก · ดูม็อคอัพ · ถ่ายรูป · รายงานปัญหา · คนอ่านไทยไม่ออกทำงานได้ครบจากไอคอน สี เลขสถานี คำพม่าไหม
5. **QC + Packing โหมดพม่า:** ผ่าน · ส่งแก้ทุกสถานี (รวมผลิตข้างนอก) · ผ่านไม่ครบกดเสร็จไม่ได้ · รูปงานเสร็จ · ข้อความ error เป็นพม่า
6. **ผู้บริหาร / เจ้าของ / ผู้ควบคุมเฟส 1–2:** ภาพรวม · คิว · ยกเลิกงานทุกสถานะ · รายงาน · ตรวจย้อนหลัง · ตั้งค่าทุกแท็บ · บัญชี (เปิด/ปิด · บัญชีที่ปิดเข้าไม่ได้/อ่านไม่ได้) · จับคู่สถานี · ทำแทนทุกบทบาท
7. **คำบนจอ vs คู่มือ:** ปุ่ม/เมนูตรงกันไหม · คู่มือยังไม่มีเรื่องรูปยืนยันตรงไหนบ้าง · ภาพคู่มือที่ล้าสมัยหลัง v3

## ส่วน D — ทุกมิติที่เหลือ
1. **สิทธิ์และความปลอดภัย:** ทุกบทบาทเปิด URL หน้าที่ไม่ใช่ของตัวเองตรงๆ (`#/…`) · เรียก RPC ทุกตัวด้วย token ของทุกบทบาทในระบบจำลอง (ต่อยอด `tools/qa-r13` / ตาราง 39 RPC รอบ 13 + RPC ใหม่ `submit_first_piece` `decide_first_piece` `add_finish_photos` `set_station_photos_enabled` `station_photo_flags`) · เขียนตารางตรงผ่าน REST (ต้องไม่ได้) · บัญชีที่ปิดใช้ · XSS (`<script>` `<img onerror>`) ในทุกช่องที่แสดงผลและพิมพ์ รวมเหตุผลไม่ผ่านและข้อความถึงแอดมิน
2. **ความถูกต้องของข้อมูล:** ยอดรวมบอร์ด = ภาพรวม = รายงาน · งานที่แบ่งไม่นับซ้ำ · events 1 แถวต่อการเปลี่ยนสถานะ · ไม่มีงานค้างสถานะแปลก (`station_status` กับ `phase` ขัดกัน) หลังทุกเส้นทาง — เขียน SQL ตรวจในระบบจำลองแล้วแนบผล
3. **หน้าจอ:** ทุกหน้าที่ **375 / 768 / 1440 px**: ไม่ล้นด้านข้าง · ปุ่มหลัก ≥ 48 px · ตัวอักษรหลัก ≥ 16 px · ปุ่มที่กดไม่ได้บอกเหตุผล · ไม่มี `NaN` `undefined` `null` `Invalid Date` · console ไม่มี error (ยกเว้น Realtime) · สถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด (ปิดหลังบ้านกลางคันแล้วเปิดใหม่) · ใช้คีย์บอร์ดอย่างเดียวได้ในหน้าหลัก
4. **เน็ตและการใช้งานจริง:** เน็ตช้า (หน่วง 3 วิ) · ออฟไลน์กลางคันตอนส่งรูป/กดเสร็จ/บันทึกใบยืนยัน · กดรัว · ย้อนกลับเบราว์เซอร์ · 2 แท็บแก้สิ่งเดียวกัน · ปิดแท็บกลางคัน · แถบ "มีระบบรุ่นใหม่" (build ใหม่ระหว่างเปิดอยู่) แล้วกดโหลด · ข้อความ "Failed to fetch" ภาษาอังกฤษหลุดขึ้นจอไหม (รีวิว UI ข้อ 15)
5. **พิมพ์ / PDF:** ใบยืนยัน (ก่อนและหลังแก้ใบ · หลายแบบหลายรูป · "อื่นๆ") · ใบปะงาน A5 · ใบม็อคอัพ A4/A3 · ตรวจไม่มีข้อความขาด / ทับรูป / ล้นหน้า · เก็บเป็นหลักฐาน
6. **ทำผิดแบบคนจริง:** จำนวน 0 / ติดลบ / ทศนิยม / ใหญ่มาก · ชื่อยาวมาก · อีโมจิ · วางจาก Excel · ไฟล์ผิดชนิด / 0 ไบต์ / ใหญ่เกิน 20 MB · วันที่ย้อนหลัง / วันอาทิตย์ / ข้ามปี
7. **เวลา:** งานข้ามเที่ยงคืน / ข้ามวันอาทิตย์ · เลยกำหนด X วัน นับถูก · เวลาไทย (ตั้งเขตเวลาเครื่องเป็นอย่างอื่นแล้วดูว่าตัวเลขยังถูก)
8. **ข้อมูลเยอะ:** สร้างงาน 300+ งาน + events หลายพันในระบบจำลอง → บอร์ด/ภาพรวม/รายงาน/ประวัติยังเปิดเร็ว (จับเวลา) · รายการรออนุมัติรูป 20 งาน
9. **ชุดทดสอบเดิมต้องผ่าน:** `npm test` (app · supabase/tests · workers/files) · `node --test tools/qa-r14/server.test.mjs` · `qa-part-a/b/c.mjs` · `confirmation-all.mjs` · `e2e-photos.mjs` (ผลลง `docs/qa/img/r19-ag/` ด้วย `QA_IMG_DIR`) · ข้อที่ล้ม แยกให้ชัดว่าบั๊กระบบหรือสคริปต์ล้าสมัย
