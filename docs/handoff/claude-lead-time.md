# เวลาผลิตทั้งงาน 10 / 15 / 20 วันทำงาน (แทนเวลามาตรฐานรายสถานี)

## เจ้าของตัดสิน (25 พ.ย.)
- จำนวนตามใบยืนยัน (ไม่รวมชิ้นเผื่อเสีย): 1–499 = 10 · 500–999 = 15 · 1,000 ขึ้นไป = 20 วันทำงาน
- ไม่นับวันอาทิตย์ · นับวันที่แอดมินรับงานเข้าโรงงานเป็นวันที่ 1 (รับวันอาทิตย์ = เริ่มนับวันจันทร์) · เวลาไทย
- รวมทุกช่วง: ตัวอย่าง ส่งข้างนอก พักงาน รออนุมัติชิ้นแรก
- ใช้ไป 80% = การ์ดส้ม · เกินวันครบ = การ์ดแดง + แจ้งเตือน + ต้องรายงานสาเหตุ 1 ครั้งก่อนกด QC + Packing เสร็จ
- กำหนดส่งลูกค้ายังกรอกเอง แยกจากเวลาผลิต · ระบบเตือนถ้ากำหนดส่งเร็วกว่า
- เลิกใช้เวลามาตรฐานรายสถานี/รายช่วง ("ข้อมูลเชื่อได้ยาก")

## เปลี่ยนอะไร
**ฐานข้อมูล** `supabase/migrations/20261201000000_job_lead_time.sql`
- `private.lead_days` · `lead_day_n` · `lead_used` · `lead_state(job, today)` · งานที่แบ่งใบใช้วันรับงานของงานแม่ + จำนวนรวมทั้งครอบครัว (ส่วนที่ยกเลิกไม่นับ) · งาน Develop / ยกเลิก ไม่มีเวลาผลิต
- รายงานสาเหตุนับเมื่อส่งตั้งแต่วันเตือน (80%) ขึ้นไป
- `finish_station`: บล็อกเฉพาะตอนปิดงานที่ QC + Packing (phase production) ถ้าเกินและยังไม่รายงาน · สถานีกลางทางกดเสร็จได้ · event `station_done` เก็บ `lead` แทน `sla`
- `submit_delay_report`: ส่งได้ทุกขั้นที่งานยังไม่ปิด (เดิมเฉพาะขั้นผลิตจริง) · ไม่บันทึก segment
- `job_sla_flags()` คืนทุกงานที่ยังไม่ปิด (ไม่ใช่ Develop) พร้อม `lead_days`, `lead_due`
- `job_live.sla` (ผ่าน `sla_state_api`) = สถานะเวลาผลิต
- `inbox_scan_all`: แจ้ง `sla_over` "เกินเวลาผลิต <เลขที่>" ครั้งเดียวต่องาน (dedupe `lead:<id>`)
- ลบฟังก์ชันเวลารายสถานีที่ไม่มีที่ใช้แล้ว (`sla_state`, `sla_for_qty`, `segment_of`, `hold_days`, `requeue_wait_days`, `first_piece_wait_days`) · คอลัมน์ `stations.sla_days/big_*` และตาราง `sla_segments` ยังอยู่ (ไม่ได้ลบข้อมูล) แต่ไม่มีอะไรใช้แล้ว

**หน้าเว็บ**
- `proto/leadTime.ts` + ทดสอบ: คำนวณตรงกับฐานข้อมูล (ทดสอบวันเดียวกันทั้งสองฝั่ง)
- รายละเอียดงาน: แถบ "ใกล้ครบ/เกินเวลาผลิต" บอกจำนวน วันครบ วันที่ใช้ไป · ฟอร์มรายงานสาเหตุ · ปุ่ม QC + Packing เสร็จบอกเหตุผลที่กดไม่ได้
- คิว QC (พนักงาน/QC ภาษาพม่า): งานเกินเวลายังไม่รายงาน ปุ่มหลักพาไปฟอร์มรายงาน · เย็บและสถานีอื่นไม่บล็อกแล้ว
- ภาพรวม: "เกินเวลาผลิต" พร้อมวันครบ · "คาดเกินเวลาผลิต X วัน" จากการจำลองคิว · วางแผนรับงานแสดงเวลาผลิตมาตรฐานของแต่ละจำนวน
- รับงาน: แสดง "ต้องผลิตเสร็จภายใน" + เตือนเมื่อกำหนดส่งเร็วกว่า (ไม่บล็อก)
- รายงาน: "เสร็จภายในเวลาผลิต" % · "รับงานถึงเสร็จเฉลี่ย" นับแบบเดียวกับกฎ (วันรับงาน = วันที่ 1) · เลิกเทียบเวลามาตรฐานรายสถานี
- ตั้งค่า: แท็บ "เวลาผลิต" (อ่านอย่างเดียว) แทน "เวลามาตรฐานของช่วง" · เอาช่องเวลามาตรฐานออกจากสถานี
- ข้อความไทย/พม่าใหม่ใน `i18n/my.ts`, `dbErrors.ts` · ลบคำแปลเก่าที่ไม่มีที่ใช้
