# เปิดใช้ / ย้อนกลับ ที่เก็บไฟล์ Cloudflare R2

ไฟล์แนบใหม่ (PDF ใบยืนยัน + รูปม็อคอัพ) เก็บใน R2 แบบส่วนตัว ผ่าน Worker `workers/files` · ข้อมูลใบงาน ล็อกอิน สิทธิ์ Realtime ยังอยู่ Supabase เหมือนเดิม

## ทำงานอย่างไร
1. หน้าเว็บส่งไฟล์ไปที่ Worker พร้อมโทเคนล็อกอิน (`PUT /upload/<ประเภท>/<path>`)
2. Worker ถามฐานข้อมูล (`file_upload_allowed`) ด้วยโทเคนของผู้ใช้ → ต้องเป็นบัญชีที่เปิดอยู่ + บทบาทแอดมิน/เจ้าของ + ชนิดไฟล์ถูก + ไม่เกิน 20 MB
3. Worker รับไฟล์ครบ ตรวจขนาดจริงและเนื้อไฟล์ (PDF / JPG / PNG / WEBP) → เก็บใน R2 → ตรวจว่าอยู่ใน R2 จริง
4. Worker เซ็นหลักฐาน (HMAC) ส่งให้ฐานข้อมูล (`record_file_upload`) → ฐานข้อมูลจดใน `private.file_objects`
5. ฟังก์ชันรับงาน / แนบ PDF / ใส่รูป / บันทึกฉบับม็อคอัพ ยอมรับเฉพาะไฟล์ที่จดไว้แล้ว
6. เปิดไฟล์: หน้าเว็บขอลิงก์ (`POST /sign`) → ฐานข้อมูลตอบว่าผู้ใช้เห็นไฟล์ไหนได้ (`file_read_allowed` ตาม RLS ของงาน) → Worker ออกลิงก์เซ็นแล้ว · PDF อายุ 9–10 นาที (ไม่เกิน 10) · รูป 1–2 ชั่วโมง (ดู "รูปย่อและ cache รูป")

- ชื่อไฟล์ = ลายนิ้วมือเนื้อไฟล์ → เน็ตหลุดแล้วส่งใหม่ได้ไฟล์เดิม ไม่สร้างไฟล์/รายการซ้ำ · หน้าเว็บลองส่งซ้ำเอง 2 ครั้ง (1 วิ, 3 วิ)
- เพดาน: PDF และรูป **20 MB = 20 × 1024 × 1024 ไบต์** ตรวจทั้งหน้าเว็บ Worker และฐานข้อมูล
- **ยังไม่ตั้งค่า = ทำงานแบบ Supabase Storage เดิม** (ไม่มี `VITE_FILES_URL` และไม่มีแถวใน `private.file_settings`)

## ควรเปิดเมื่อไร
- **ไม่แนะนำให้เปิด R2 ก่อนหรือระหว่าง ส. 21 (ทดลอง) / อา. 22 (เปิดใช้)** · เปิดวันที่งานเบา หลังระบบนิ่ง เช่น จ. 23 หลังเลิกงาน
- merge PR นี้แล้ว (ยังไม่ตั้งค่า R2) จะเปลี่ยนแค่: รูปม็อคอัพรับได้ถึง 20 MB · ลิงก์รูปอายุ 2 ชม. (เดิม 12) · ชื่อไฟล์ PDF ตั้งจากเนื้อไฟล์ · ลองส่งซ้ำเมื่อเน็ตหลุด → เสี่ยงต่ำ แต่ถ้าไม่อยากให้มีอะไรเปลี่ยนช่วงทดลอง ให้ merge หลัง อา. 22

## ขั้นตอนเปิดใช้ (เรียงตามนี้)
1. **ลงฐานจริง** migration `20261120260000_r2_files.sql` (Claude ทำเมื่อเจ้าของสั่ง "ลงฐานจริง") · ยังไม่เปลี่ยนพฤติกรรม แค่เพิ่มเพดาน bucket `mockups` เป็น 20 MB
2. merge PR → Cloudflare Pages deploy (ยังใช้ Storage)
3. Cloudflare → R2 → Create bucket `pp142-files` · Standard · **ไม่เปิด Public access / ไม่เปิด r2.dev**
4. สร้างค่าลับ 2 ค่า (คนละค่า) ในเครื่อง ห้ามใส่ git / ห้ามส่งในแชต:
   `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
5. deploy Worker:
   ```
   cd workers/files
   npx wrangler login
   npx wrangler secret put SUPABASE_URL        # https://<project>.supabase.co
   npx wrangler secret put SUPABASE_ANON_KEY   # anon key เดียวกับหน้าเว็บ
   npx wrangler secret put RECORD_SECRET       # ค่าลับที่ 1
   npx wrangler secret put LINK_SECRET         # ค่าลับที่ 2
   npx wrangler deploy                         # ได้ที่อยู่ https://pp142-files.<ชื่อบัญชี>.workers.dev
   ```
   ทดสอบ: เปิด `https://pp142-files.<…>.workers.dev/f/confirmations/x/a.pdf` ต้องขึ้น "ลิงก์ไม่ถูกต้อง" (403)
6. Supabase → SQL Editor (ทำข้อ 6 และ 7 ติดกัน · ระหว่างนั้นแนบไฟล์ไม่ได้ ~2 นาที):
   `insert into private.file_settings (record_secret) values ('<ค่าลับที่ 1>');`
7. Cloudflare Pages → Settings → Environment variables (Production) → `VITE_FILES_URL` = ที่อยู่ Worker → Retry deployment
8. ตรวจหลังเปิด (บัญชีแอดมิน): แนบ PDF ให้งานทดสอบ → กด "เปิด PDF ใบยืนยัน" · เปลี่ยนรูปม็อคอัพ → การ์ดขึ้นรูป · ฝ่ายผลิตเปิดรูป/ PDF ได้ · Cloudflare R2 เห็นไฟล์ใต้ `confirmations/` `mockups/`

## ย้อนกลับ
1. Cloudflare Pages → ลบ `VITE_FILES_URL` → Retry deployment
2. SQL Editor: `delete from private.file_settings;`
→ กลับไปใช้ Supabase Storage ทันที · **ไฟล์ที่เข้า R2 ระหว่างเปิดใช้จะเปิดจากระบบไม่ได้** (รูปเป็นกรอบว่าง / PDF เปิดไม่ขึ้น) จนกว่าจะแนบใหม่ หรือเปิดใช้ R2 อีกครั้ง · ไฟล์ใน R2 ไม่หาย · Worker ปล่อยไว้ได้

## รูปย่อและ cache รูป
- **รูปย่อ:** อัปโหลดรูปม็อคอัพจากหน้าเว็บ (เปลี่ยนรูปในใบงาน · รูปจากใบยืนยัน · รูปฉบับม็อคอัพ) แล้ว หน้าเว็บย่อรูปเป็น JPEG ด้านยาว 240 px ส่งตามไปที่ `<path รูป>.thumb.jpg` (เช่น `SC-1/ab12.png.thumb.jpg`) · ส่งไม่สำเร็จไม่ทำให้การบันทึกรูปล้ม
- Worker รับรูปย่อเมื่อ: ผู้ส่งอัปโหลดรูปต้นฉบับได้ (ถาม `file_upload_allowed` ด้วย path ต้นฉบับ) + มีรูปต้นฉบับใน R2 แล้ว + เป็น JPEG ไม่เกิน 1 MB · ไม่เขียนทับรูปย่อเดิม · **ไม่จดในฐานข้อมูล ไม่ต้องลง migration**
- เปิดรูปย่อ = ลิงก์รูปต้นฉบับที่เซ็นแล้ว + `&v=thumb` (สิทธิ์เดียวกับรูปต้นฉบับ) · ยังไม่มีรูปย่อ = ได้รูปต้นฉบับแทน ไม่ขึ้นรูปเสีย · หัว `X-File-Variant: thumb | original` บอกว่าได้อะไร
- การ์ดบนบอร์ด / คิว / ค้นหางาน / รูปในรายการแบบของงาน ใช้รูปย่อ · กดเปิดเต็มจอ · รูปใหญ่ในหน้างาน · หน้าม็อคอัพ · ใบติดงาน ใช้รูปต้นฉบับ
- **ลิงก์คงที่:** Worker ปัดเวลาหมดอายุขึ้นถึงขอบช่วง (รูป: ขอ 1 ชม. ช่วง 1 ชม. → ลิงก์จริงอยู่ 1–2 ชม. · PDF: ช่วง 1 นาที ขอได้สูงสุด 9 นาที → ไม่เกิน 10 นาที) · ขอลิงก์รูปเดิมในช่วงเดียวกัน = ได้ลิงก์เดิม · ไฟล์ส่ง `Cache-Control: private, max-age=<เวลาที่เหลือของลิงก์>, immutable` → เปิดแอปใหม่ เบราว์เซอร์ใช้รูปจาก cache ไม่โหลดใหม่ (ไม่เก็บใน cache กลาง)
- **รูปเก่าไม่มีรูปย่อ** จนกว่าจะอัปโหลดใหม่ หรือรัน `tools/r2-local/backfill-thumbs.mjs` (ย่อรูปด้วย Chrome ในเครื่อง ส่งผ่าน Worker ด้วยโทเคนแอดมิน ทางเดียวกับหน้าเว็บ · `--dry-run` = นับอย่างเดียว · ที่อยู่ที่ไม่ใช่เครื่องนี้ต้องใส่ `--live`)

### ขั้นตอนเปิดใช้รูปย่อ (เรียงตามนี้)
1. deploy Worker ก่อน: `cd workers/files` → `npx wrangler@4 deploy` (Claude / เจ้าของทำ · ค่าลับเดิมไม่ต้องตั้งใหม่)
2. ตรวจ: เปิดรูปบนการ์ดในแอป (รุ่นเดิม) ยังขึ้นปกติ
3. merge → Cloudflare Pages deploy หน้าเว็บ
4. (ไม่บังคับ) รูปเก่า: `FILES_URL=<Worker> SUPABASE_URL=<project> SUPABASE_ANON_KEY=<anon> ACCESS_TOKEN=<โทเคนแอดมิน> node tools/r2-local/backfill-thumbs.mjs --live --dry-run` ดูจำนวนก่อน แล้วรันซ้ำโดยไม่ใส่ `--dry-run` (เมื่อเจ้าของสั่ง)
- สลับลำดับได้โดยไม่เสีย: หน้าเว็บใหม่กับ Worker เก่า = `v=thumb` ถูกเมิน ได้รูปเต็มเหมือนเดิม · ส่งรูปย่อถูกปฏิเสธเงียบๆ (รูปที่อัปโหลดช่วงนั้นต้องรัน backfill)
- ย้อนกลับ: deploy Worker รุ่นก่อน → การ์ดได้รูปเต็มเหมือนเดิม · รูปย่อใน R2 ปล่อยไว้ได้

## ข้อจำกัดที่รู้
- ลิงก์ที่ออกไปแล้วใช้ได้จนหมดอายุ (PDF ≤ 10 นาที · รูป ≤ 2 ชม.) แม้บัญชีถูกปิดหลังจากนั้น · ลิงก์ใหม่ขอไม่ได้ทันที
- สำรองไฟล์ใน R2 ลงเครื่อง PC ด้วย `tools/r2-backup` (ต้องตั้งครั้งแรก) · รายการไฟล์ `private.file_objects` อยู่ในสำรองรายสัปดาห์ · ดู [`สำรองและกู้ข้อมูล.md`](สำรองและกู้ข้อมูล.md)
- `supabase/scripts/golive-cleanup.sql` ยังลิสต์แค่ไฟล์ใน Storage
- ค่าฟรีของ Cloudflare: R2 10 GB · Worker 100,000 คำขอ/วัน · คำขอละไม่เกิน 100 MB
