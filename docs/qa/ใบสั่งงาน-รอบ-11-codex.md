## ทำไม
20 พ.ย. ระบบเปลี่ยนเยอะและเริ่มใช้จริงแล้ว:
- **ฐานจริงถูกล้างแล้ว ไม่มีงานเลย** (งาน 0 · ประวัติ 0 · กล่องจดหมาย 0) → งานแรกของผู้ใช้จริงจะเริ่มจากตารางว่าง
- **บัญชีจริง:** เจ้าของ 1 · ผู้บริหาร 1 · แอดมิน 4 · ฝ่ายผลิต 2 · พนักงานสถานี (`staff`) — คนเดียวหลายสถานี (พิมพ์ + รีด + ตัด) · รีดอย่างเดียว · ตัดอย่างเดียว · QC + Packing · ยังไม่จับคู่ 5 คน · ไม่มีบัญชี QC (QC ใช้ staff ที่จับคู่ `qc_pack` หรือฝ่ายผลิต)
- **ม็อคอัพ:** วางจุดตั้งแต่ใบยืนยัน (`production-confirmation.html` → `receive_job` สร้างร่างให้) · กล่องข้อความวางนอกภาพได้ (−0.5 ถึง 1.5) · **แอดมินอนุมัติใช้ผลิตเองจากร่าง** (`approve_mockup_sheet(p_sheet, p_note, p_version)`) · บันทึก/อนุมัติทับกันต้องถูกปฏิเสธทันที (เคยใช้ errcode `40001` ทำให้ PostgREST ลองซ้ำไม่หยุด → เปลี่ยนเป็น `P0001`)
- **จัดส่ง:** `mark_delivered` / `undo_delivery` (แอดมิน) · การ์ด "เสร็จ · รอส่ง" / "จัดส่งแล้ว" · งานยังไม่ส่งค้างบนบอร์ด
- **แก้จาก QA รอบ 10:** หน่วย `ซม.` ไม่ซ้ำ · QC ล็อกสถานีในหน้าดูสเปก · Ctrl+Z / Ctrl+Y ในแผงสเปก (แป้นไทยด้วย) · ช่องกว้าง/สูงรับเฉพาะตัวเลข > 0 · รายการ Callout ไม่ล้น

## สิ่งที่ต้องทดสอบ

### A. ฐานข้อมูล (`flow-r11.mjs` · ธุรกรรมเดียว rollback ตอนจบ · ค่าเครื่องจริง: พิมพ์ 2 · รีด 1 · ตัด 2 · รีดฟิล์ม 2 · QC 1)
1. **เริ่มจากตารางว่าง:** ลบงานทั้งหมดในธุรกรรม (แบบ `golive-cleanup.sql`) แล้ว `receive_job` งานแรก → เลขคิว ลำดับ บอร์ด `job_live` `job_sla_flags` ทำงานถูก · งานที่ 2–5 เรียงคิวถูก · แทรกงานด่วน (`move_job_ahead`) ตอนมีงานน้อย
2. **บัญชีตามจริง:** สร้างผู้ใช้ตามข้อ "ทำไม" (รวม staff คนเดียว 3 สถานี · ฝ่ายผลิต 2 คน) แล้ว**เดินครบทุกเส้นทาง** (ปกติ · DTF · DTG · สกรีน · ปัก · พิมพ์+ปัก · ตัดงานลูกค้า · ไม่พิมพ์ · ขึ้นตัวอย่าง/ไม่ขึ้น) ด้วยคนที่จะกดจริง: แอดมินรับงาน/ฟิล์ม/ผลตัวอย่าง/ส่งออก/จัดส่ง · staff กดสถานีของตัวเอง · ฝ่ายผลิตเย็บ + "แก้แล้ว ทำต่อ" · **QC ด้วย staff ที่จับคู่ `qc_pack`** (บันทึกผ่าน · ส่งแก้ · เสร็จ) · ทุกขั้นมี `events` 1 แถว
3. **staff ทำเกินสิทธิ์ไม่ได้:** สถานีที่ไม่ได้จับคู่ · staff ที่ยังไม่จับคู่ · `close_issue` · `move_job_ahead` · `receive_job` · `start_sewing` · `mark_delivered` · `approve_mockup_sheet` · บัญชีที่ปิดแล้ว (`active = false`) ทำอะไรไม่ได้และอ่านอะไรไม่ได้
4. **ม็อคอัพครบวงจร:** ใบยืนยันมีจุด (`spec.callouts` + `spec.co_size` แบบที่ฟอร์มส่ง) → `receive_job` แล้วหน้าเว็บเรียก `start_mockup_sheet` + `save_mockup_draft` (`seedFromConfirmation` ใน `data/mockupSheets.ts` · จำลองลำดับเดียวกัน) → แอดมินแก้ + อนุมัติเองจากร่าง → ฉบับแก้ไขหลังเริ่มผลิต (แอดมินอนุมัติเองได้ · ฝ่ายผลิตไม่ได้) → staff/QC รับทราบเฉพาะสถานีตัวเอง · บันทึก/อนุมัติด้วยเลขฉบับเก่าถูกปฏิเสธ **และ errcode ไม่ใช่ `40001` / `40P01`** · ค่าจากใบยืนยัน (`8x8 ซม.` · `3 นิ้ว` · `10 × 12`) แสดงหน่วยถูก · กล่องข้อความ −0.5 / 1.5 ผ่าน · −0.6 / 1.6 ไม่ผ่าน
5. **จัดส่ง:** แอดมินบันทึก/ยกเลิก (ต้องมีเหตุผล) · ซ้ำไม่ได้ · ยังไม่เสร็จไม่ได้ · บทบาทอื่นไม่ได้ · งานแบ่ง (`split_job`) จัดส่งแยกกันได้ · งานส่งแก้หลังเสร็จ (ถ้าเป็นไปได้) ไม่ทำให้สถานะจัดส่งผิด
6. **เครื่องเต็ม + จักร:** ทุกสถานีที่จำกัด (แบบรอบ 9) โดยใช้ staff กด · เย็บด้วยฝ่ายผลิต 2 คนพร้อมกันคนละงาน (จักรไม่ถูกจ่ายซ้ำ) · จักรเสียระหว่างเย็บ
7. **สคริปต์:** รัน `supabase/scripts/golive-cleanup.sql` บนฐานที่**ไม่มีงาน TEST และไม่มีงานเลย** → ไม่ error · ตารางสรุปขึ้น · รันซ้ำได้ (อ่านอย่างเดียว ห้ามแก้สคริปต์)
8. ตรวจค่าคงที่หลังทุกขั้น (แบบ `invariant` ใน `flow-r8.mjs`): งาน `doing` ต่อ pool ไม่เกินจำนวนเครื่อง · จักรไม่ถูกจ่ายซ้ำ · `events` ไม่ถูกแก้ · ไม่มีงานค้างสถานะขัดกัน (พักแต่ไม่มีปัญหาเปิด · ข้างนอกแต่ไม่มีรอบส่งออก)

### B. หน้าเว็บ (Vitest `flow-r11.test.ts` + เบราว์เซอร์กับ API จำลอง `tools/qa-r11/`)
1. **ระบบว่าง:** ทุกหน้าของทุกบทบาทตอนไม่มีงานเลย → ขึ้นสถานะ "ไม่มีข้อมูล" ไม่ขาว ไม่ error · ภาพรวม/รายงานไม่หารศูนย์ (`NaN` / `Infinity`)
2. **เมนู + สิทธิ์ตามบัญชีจริง:** เจ้าของ · ผู้บริหาร · แอดมิน · ฝ่ายผลิต · staff 3 สถานี · staff 1 สถานี · staff ยังไม่จับคู่ (ขึ้น "ยังไม่ได้จับคู่สถานี") · ตรงกับ `docs/แบบเมนูตามบทบาท.md` และ `auth/permissions.ts`
3. **จัดส่ง:** กล่อง "จัดส่งให้ลูกค้า" (แอดมิน) · ยืนยัน · ยกเลิกต้องใส่เหตุผล · บทบาทอื่นเห็น "รอจัดส่ง" · การ์ด "เสร็จ · รอส่ง" / "จัดส่งแล้ว" · ภาพรวม "รอจัดส่ง n งาน" · ไทม์ไลน์
4. **ม็อคอัพ:** ปุ่ม "อนุมัติฉบับ n ใช้ผลิต" (ยืนยันก่อน · ยังไม่บันทึกต้องบันทึกให้) · ปุ่มกดไม่ได้บอกเหตุผล · แก้พร้อมกัน 2 แท็บ → แท็บ 2 ได้ข้อความ "มีคนบันทึก…" ทันที (API จำลองตอบ error ทันที) · QC/staff ล็อกสถานี · Ctrl+Z / Ctrl+Y ในช่องชื่อจุด (แป้นไทย: `e.code`) · ช่องกว้าง/สูงพิมพ์ `abc` / `0` ขึ้นข้อความแดง · รายการ Callout ยาวไม่ล้นคอลัมน์ที่ 1440 / 1920 px
5. **ฟอร์มใบยืนยัน `/confirmation`:** วางจุด → บันทึกเข้าระบบ → หน้ารับงาน → ม็อคอัพมีร่างจุดครบ · ตัวอย่าง PDF มีจุด
6. ทุกหน้าที่เกี่ยวข้อง 375 / 768 / 1440 px ไม่ล้น · console ไม่มี error · ภาพหลักฐาน `docs/qa/img/r11-cx-*.png`
