## 2. รายการบั๊กและข้อสังเกตที่พบในรอบ 3

### บั๊ก #1: `"เวลาที่ใช้ต่อสถานี"` ในรายละเอียดงานไม่หักเวลาพัก (`hold` → `resume`) ออก
- **ระดับ:** 2 (ตัวเลขเวลาทำงานจริงในรายละเอียดงานสูงเกินจริง และไม่สอดคล้องกับหน้า `#/reports`)
- **จุดที่พบ:** `app/src/data/history.ts` (บรรทัด 123–137 ฟังก์ชัน `visitLines`) ร่วมกับ SQL view/migration `supabase/migrations/20261119150000_station_visits_end.sql`
- **บทบาท / จอที่กระทบ:** ทุกบทบาทที่เปิดรายละเอียดงานแล้วดูบล็อก `"เวลาที่ใช้ต่อสถานี"`
- **ขั้นตอนทำซ้ำ:**
  1. เริ่มทำงานในสถานีหนึ่ง → กด `"พักงาน / ติดปัญหา"` ทิ้งไว้ → กด `"ทำต่อ"` → กด `"เสร็จ"`
  2. เปิดรายละเอียดงาน ดูส่วน `"เวลาที่ใช้ต่อสถานี"` ([ตัวอย่างส่วนแสดงผลในรายละเอียด TEST-G4-N](img/r3-sample-history.png))
- **ผลที่ได้:** `visitLines()` คำนวณ `const durationMs = Math.max(0, endTime.getTime() - startTime.getTime())` ตรงๆ โดยไม่ลบช่วงเวลาระหว่าง event `hold` กับ `resume` ออก (ต่างจากหน้า `#/reports` ที่หักเวลาพักออกแล้ว)
- **ผลที่ควรเป็น:** `"เวลาที่ใช้ต่อสถานี"` ต้องหักเวลาช่วง `hold` → `resume` ออกให้เหลือเฉพาะเวลาทำงานจริง และระบุหมายเหตุเวลาพักแยกต่างหาก
