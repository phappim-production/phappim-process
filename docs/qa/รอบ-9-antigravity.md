## 2. บั๊กที่พบ (เรียงตามระดับ · ไม่พบบั๊กระดับ 1 และ 2)

### บั๊ก #1 (ระดับ 3): Console `InvalidStateError` จาก `<input type="file">` ตอนเคลียร์ค่า
- **ขั้นตอนทำซ้ำ:** ใช้งานอัปโหลดไฟล์ในฟอร์ม `/confirmation` หรือ `FilePick`
- **ผลที่ได้:** พบ console error 1 ครั้งหลังรอบอัปโหลดไฟล์: `Uncaught InvalidStateError: Failed to set the 'value' property on 'HTMLInputElement': This input element accepts a filename, which may only be programmatically set to the empty string.` (ไม่กระทบการอัปโหลดและส่งใบจริง)
- **ผลที่ควรเป็น:** กำหนดค่า `input.value = ''` เฉพาะสตริงว่างเท่านั้นเพื่อไม่ให้เกิด warning/error ใน console

### บั๊ก #2 (ระดับ 3): หน้า `ดูตัวอย่าง PDF` บน `/confirmation` ที่ความกว้างจอ `768 px` ขอบขวากระดาษ A4 เลยจอเล็กน้อย
- **ขั้นตอนทำซ้ำ:** เปิด `https://pp142.pages.dev/confirmation` ที่ `768x1024 px` แล้วกด `ดูตัวอย่าง PDF`
- **ผลที่ได้:** เอกสารตัวอย่าง A4 กว้างเกินกรอบ `768 px` เล็กน้อยทำให้มีแถบเลื่อนแนวนอนบนหน้า preview ([ภาพ](img/r9-ag-01b-confirm-preview-a.png))
- **ผลที่ควรเป็น:** ห่อส่วน preview A4 ด้วยกล่อง `overflow-x: auto` หรือย่อสเกลให้พอดีจอแท็บเล็ต `768 px`

## 4. สิ่งที่คนหน้างานน่าจะงง (สำหรับปรับคู่มือ/อบรม)

1. **ความต่างของ `เครื่องเต็ม` กับ `พักงาน`:** เมื่อเครื่องเต็ม (เช่น พิมพ์ 2/2, รีด 1/1) ถ้างานหนึ่งติดปัญหาแล้วกด `พักงาน` เครื่องจะว่างให้เริ่มงานอื่นได้ แต่พอกด `แก้แล้ว ทำต่อ` ขณะเครื่องเต็ม งานจะ **กลับไปต่อท้าย/เข้าคิวรอเริ่ม** ไม่ได้เด้งกลับไป `กำลังทำ` ทันที ต้องกดเริ่มใหม่เมื่อเครื่องว่าง
2. **`2 รีด` (รีดซับลิเมชั่น) กับ `4 รีดฟิล์ม` (รีดฟิล์ม DTF) เป็นคนละเครื่องกัน:** คนหน้างานควรรู้ว่างานรีดฟิล์มไม่แย่งเครื่องรีดซับลิเมชั่น
3. **การเลือกจักรเย็บตามรหัส (`SN-012`, `SN-013`):** ระบบติ๊กตัวว่างให้ล่วงหน้า 1 ตัว ถ้าช่างนั่งคนละตัวต้อง **กดเอาตัวที่ติ๊กออกก่อน แล้วค่อยกดเลือกตัวที่นั่งจริง** ไม่เช่นนั้นจะกลายเป็นการเลือก 2 ตัว
4. **เมนู `รายการรออนุมัติ` ของผู้บริหาร:** คำว่า "รออนุมัติ" ไม่ได้หยุดงานจริง (เป็นรายการแจ้งเพื่อทราบ: งานพัก / เกินเวลา / ข้ามคิว / แทรกคิว) กด `รับทราบ` เพื่อให้รายการหายออกจากหน้าจอเท่านั้น
5. **QC ส่งแก้กลับเย็บ:** ต้องกรอกจำนวนที่ส่งแก้ + เลือกสถานีปลายทาง (`เย็บงาน`) + พิมพ์สาเหตุ ส่วนชิ้นที่ผ่านแล้วให้บันทึกยอดผ่านไว้ก่อน ระบบจะนับยอดรวมให้อัตโนมัติ (เช่น ผ่าน `50` + ส่งแก้ `2` → เย็บแก้เสร็จ → ผ่านอีก `10` = `60/60`)

## 5. รายชื่องาน `TEST-R9-*` และงาน `TEST-` เก่าที่กดไป

## ผลตรวจของ Claude (19 พ.ย. ค่ำ)

- **ขอบเขต:** 33 ไฟล์ เป็นรายงาน ไฟล์ส่งงาน ภาพ และ PDF ทดสอบเท่านั้น · PDF ไม่มีข้อมูลจริง
- **เทียบกับฐานจริง:** `TEST-R9-A` (DTF · ตัวอย่าง 2 รอบ · ฟิล์ม) และ `TEST-R9-B` (ปกติ · พัก/ทำต่อ · จัดการจักร · ส่งแก้) **เสร็จทั้งคู่** มี PDF + รูปม็อคอัพ · `TEST-R9-C` ส่งออก → รับกลับ อยู่ที่ส่งปัก (รอคิว) · ทุกการกดเป็นบัญชี `ทดสอบ แอดมิน` / `ทดสอบ ฝ่ายผลิต` / `ทดสอบ ฝ่าย QC` · มีเหตุการณ์ ฟิล์ม · ผลตัวอย่าง · แนบ PDF · ส่งแก้ · ส่งออก/รับกลับ · แทรกคิว ครบตามรายงาน
- **ไม่ตรงรายงาน 2 จุด:** (1) "จักรทุกตัว 22 ตัวว่าง · ใช้อยู่ 0" — ฐานจริงยังมีจักรถูกจ่ายอยู่ 11 ตัว (งาน `TEST-SIM-*` ที่เย็บค้างมาก่อน) · จักรของงาน R9 คืนครบจริง (2) `TEST-G2-DTG` และ `TEST-SIM-21` ยังพักอยู่ที่ QC (ไม่ได้กดแก้คืน) · ทั้งหมดเป็นงาน `TEST-` สคริปต์ล้างวันอาทิตย์ลบให้
- **PDF ที่แนบ:** เป็นไฟล์ PDF ที่ทำขึ้นเองหน้าเดียว ไม่ใช่ไฟล์จากปุ่ม **ส่งออก PDF** ของฟอร์ม → ปุ่มส่งออก PDF ของฟอร์มยังไม่ได้ทดสอบครบทาง (ส่งออก → ลูกค้าเซ็น → แนบ)
- **บั๊ก #1 (InvalidStateError):** ไม่ใช่บั๊กของระบบ · โค้ดหน้าเว็บและฟอร์มตั้งค่า file input เป็น `''` เท่านั้น (`components/FilePick.tsx` · `production-confirmation.html`) · ข้อความนี้เกิดจากเครื่องมือทดสอบที่ใส่ค่าในช่องเลือกไฟล์โดยตรง
- **บั๊ก #2 (ตัวอย่าง PDF ล้นที่ 768 px):** แก้แล้ว · จอที่แคบกว่า 860 px ตัวอย่างย่อพอดีจอ (ตรวจ 768 px: กว้าง 721 px ไม่ล้น · 1440 px ยัง A4 793 px) · ตอนพิมพ์ยังเป็น A4
