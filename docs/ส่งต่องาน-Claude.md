## วิธีรีวิวงานที่ส่งมา (ทำทุกครั้ง)
1. `git diff --stat` มีแต่ไฟล์ในใบสั่งงาน · ไม่มีไฟล์แปลกปลอม
2. รันทดสอบเองทุกชุดบน branch ที่ต่อจาก `main` ล่าสุด (ถ้า main เดินไปแล้ว ใช้โฟลเดอร์รีวิวแยก `git worktree add --detach ../pp142-review-xx origin/main` แล้ว merge/cherry-pick) · `supabase/tests`: `npm test` · `app`: `npm run lint && npm test && npm run build`
3. อ่านทุกไฟล์ที่เปลี่ยน · migration: RLS · grant/revoke (`anon` ห้าม) · กฎบังคับใน SQL · error ไทย · ชื่อไฟล์ตามที่จอง · หน้าเว็บ: ส่วนประกอบกลาง · ไม่มี hex / `any` / ปิด lint · ไม่มีข้อความอังกฤษ
4. เทียบกับระบบจริง (Supabase MCP `execute_sql` อ่านอย่างเดียว) · ภาพหน้าจอต้องเป็นข้อมูล `TEST-` / บัญชีทดสอบ
5. ลงฐานข้อมูลจริง: `apply_migration` → แก้แถวประวัติให้ version = ชื่อไฟล์ → ตรวจ `md5(replace(prosrc, chr(13), ''))` เทียบเนื้อฟังก์ชันในไฟล์ · ถ้าถูกปฏิเสธ ให้เจ้าของรันใน SQL Editor เอง
6. **ลง DB ก่อน merge** เมื่อหน้าเว็บใหม่อ่านคอลัมน์/ฟังก์ชันใหม่ (Cloudflare deploy ทันทีที่ merge) · merge ด้วย `gh pr merge <n> --merge` หลัง CI ผ่าน (repo ปิด auto-merge)
