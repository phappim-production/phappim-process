## สิ่งที่ต้องทดสอบ

### A. ฐานข้อมูล — กฎ workflow (ธุรกรรม rollback ตอนจบ · ค่าเครื่องจริง: พิมพ์ 2 · รีด 1 · ตัด 2 · รีดฟิล์ม 2 · QC/Packing ไม่จำกัด · เย็บตามจักร)
1. **ทุกเส้นทาง 9 เส้น** (ปกติ · DTF · DTG · สกรีน · ปัก · พิมพ์+ปัก · ตัดงานลูกค้า · ไม่พิมพ์ · ผลิตข้างนอกทั้งหมด) × ขึ้นตัวอย่าง/ไม่ขึ้น × ตัวอย่างไม่ผ่าน 1 รอบ → เดินจนจบ + จัดส่ง ด้วยบัญชีตามจริง (แอดมิน · ฝ่ายผลิต 2 คน · ผู้บริหาร · staff หลายสถานี · staff สถานีเดียว · staff จับคู่ `qc_pack` ทำ QC · เจ้าของ)
2. **ทุกฟังก์ชันใน `api-workflow.md` × ทุกบทบาท** (owner · manager · admin · production · supervisor เฟส 1/2 · qc · staff จับคู่/ไม่จับคู่ · บัญชีปิด) → ตารางผลอนุญาต/ปฏิเสธ เทียบกับเอกสาร · ข้อความ error เป็นไทยบอกสิ่งที่ต้องทำ · ไม่มี errcode `40001` / `40P01`
3. **ทุกจุดที่ทำให้สถานะงานเปลี่ยน** มี `events` 1 แถว (หรือตามที่ workflow กำหนด) · `events` แก้/ลบไม่ได้ทุกบทบาท · ไม่มีการเขียนตารางงานตรงจาก client (RLS)
4. **ผสมกรณียาก:** พักงาน → ส่งออก ไม่ได้ · แบ่งงานแล้วยกเลิกใบลูก · ส่งแก้จาก QC ไปสถานีที่ส่งออกได้ แล้วส่งออก · ยกเลิกงานระหว่างเย็บ (คืนจักร) · ยกเลิกงานที่มีม็อคอัพร่าง/รออนุมัติ · งานแทรกคิวแล้วเครื่องเต็ม · จักรเสียระหว่างเย็บ · แก้แล้วตอนเครื่องเต็ม · ฟิล์มยังไม่มา · งานเกินเวลามาตรฐาน (ต้องส่งรายงานก่อนเสร็จ) · ใบลูก `-2` ของใบลูก
5. **กดซ้ำ / กดพร้อมกัน:** คำขอซ้ำด้วย `p_request` เดิม · 2 คนกดเริ่มงานเดียวกัน · 2 คนเลือกจักรตัวเดียวกัน · บันทึก/อนุมัติม็อคอัพทับกัน · ยกเลิกงานพร้อมกับกดเสร็จ → ต้องไม่ได้สถานะผิดหรือข้อมูลซ้ำ
6. **ค่าคงที่หลังทุกขั้น** (แบบ `invariant` ใน `flow-r8.mjs`): งาน `doing` ต่อ pool ≤ จำนวนเครื่อง · จักรไม่จ่ายซ้ำ · งาน `out` มีรอบส่งออกเปิด 1 รอบ · พักงานมีปัญหาเปิด · งานยกเลิกไม่มีจักร/การจอง/ปัญหาค้าง · ไม่มีงาน `doing` ที่ `outside` · เลขคิวไม่ซ้ำ
7. **เวลา:** เขตเวลาไทย · วันทำงานจันทร์–เสาร์ · ของถึง/ฟิล์มมาวันอาทิตย์ · เวลามาตรฐานข้ามวันอาทิตย์ · งานกำหนดส่งวันอาทิตย์ · ข้ามเที่ยงคืน
8. **ไฟล์ (R2 + ฐานข้อมูล):** `record_file_upload` / `file_read_allowed` / `private.file_objects` · PDF ใบยืนยัน + รูปม็อคอัพ · ใครอ่านไฟล์ของงานไหนได้ (บัญชีปิด / staff / ลิงก์ไฟล์งานอื่น) · ไฟล์ที่ยังไม่อัปโหลดจริงใช้รับงานไม่ได้ · ชื่อไฟล์แปลก (ไทย เว้นวรรค `../`)
9. **สคริปต์:** `live-check.sql` (ทุกข้อผ่าน และย้อนกลับไม่เหลือข้อมูล) · `golive-cleanup.sql` บนฐานที่มีทุกสถานะ (ลบเฉพาะ `TEST-` · ไฟล์ R2 ที่ไม่มีงานอ้าง · รันซ้ำได้)

### B. ความปลอดภัย
1. **anon / ยังไม่ล็อกอิน:** อ่าน/เรียกอะไรไม่ได้ทุกตาราง/view/ฟังก์ชัน
2. **บัญชีปิด (`active = false`):** ทำ/อ่านอะไรไม่ได้ ยกเว้นโปรไฟล์ตัวเอง (ตั้งใจ)
3. **ยกระดับสิทธิ์:** staff/QC/แอดมินแก้ `profiles.role` / `staff_stations` / ตั้งค่า / บริษัทภายนอกของตัวเองไม่ได้ · เรียกฟังก์ชันใน schema `private` ตรงไม่ได้
4. **ข้อความที่ผู้ใช้พิมพ์** (ชื่อลูกค้า · เหตุผล · หมายเหตุ · ชื่อจุดม็อคอัพ · ช่องในใบยืนยัน รวมตาราง "ผ้าเพิ่ม") ใส่ `<script>` `"><img onerror>` → หน้าเว็บ ใบปะงาน ใบกำกับงานพิมพ์ PDF ใบยืนยัน ต้องไม่รันโค้ด
5. **Worker ไฟล์** (`workers/files` ด้วยชุดทดสอบเดิม + เพิ่มใน `tools/qa-r13`): ลิงก์หมดอายุ · ลายเซ็นปลอม · path ข้ามโฟลเดอร์ · ไฟล์ใหญ่เกิน 20 MB · ชนิดไฟล์ผิด · origin ไม่อนุญาต

### C. หน้าเว็บ — ทุกหน้า × ทุกบทบาท (Vitest + เบราว์เซอร์กับ API จำลอง)
1. **เมนูและการเข้าหน้า** ทุกบทบาทตรงกับ `docs/แบบเมนูตามบทบาท.md` / `auth/permissions.ts` · เปิด URL หน้าที่ไม่มีสิทธิ์ตรงๆ ได้ผลที่ถูก
2. **ทุกหน้า** (ภาพรวม · บอร์ด/สถานี · คิวงาน · จักรเย็บ · รับงานใหม่ · ใบร่างใบยืนยัน · รายละเอียดงาน · ประวัติงาน · ม็อคอัพกำกับสเปก · ใบกำกับงานพิมพ์ · ใบปะงาน · ปัญหา · รายงาน · กล่องจดหมาย · ตั้งค่าทุกแท็บ · บัญชีของฉัน · หน้าตรวจย้อนหลัง) มีสถานะ **กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด** · ไม่มี `NaN` `Infinity` `undefined` `null` บนจอ
3. **ทุกปุ่มที่กดไม่ได้บอกเหตุผล** · ปุ่มหลักหน้างานสูง ≥ 48 px · ตัวอักษรหลัก ≥ 16 px · ข้อความไทยทั้งหมด · สีตามความหมาย (แดง/ส้ม/ฟ้า/เขียว)
4. **375 / 768 / 1440 px** ทุกหน้า ไม่ล้นด้านข้าง · console ไม่มี error (ยกเว้น websocket realtime ของ API จำลอง)
5. **รายละเอียดงาน (PR 148):** มีม็อคอัพกำกับสเปกฉบับอนุมัติ → รูปปกติ + ข้อความ "กดที่รูปเพื่อดูม็อคอัพกำกับสเปก ฉบับ n" → กดแล้วไปหน้าม็อคอัพ · ไม่มีฉบับอนุมัติ → เปิดรูปเต็มจอ · ไม่มีรูป → "ยังไม่มีรูปม็อคอัพ" · ทุกบทบาท
6. **เน็ตช้า / หลุด / กดซ้ำ:** ปุ่มบันทึกกดรัวๆ ไม่สร้างข้อมูลซ้ำ · เน็ตหลุดระหว่างอัปโหลดไฟล์ · แถบ "มีระบบรุ่นใหม่" · แท็บรุ่นเก่าที่หาไฟล์หน้าจอไม่เจอโหลดรุ่นใหม่เอง
7. **ประมาณวันเสร็จ / คิว / คอขวด** ตรงกับข้อมูล (รวมงานส่งออก · ผลิตข้างนอก · ฟิล์ม · วันอาทิตย์)

### D. ฟอร์มใบยืนยัน `production-confirmation.html` (`/confirmation`)
1. **ทุกสินค้า 37 รายการ:** เลือกได้ · ช่องบังคับครบ · กรอกครบแล้วผ่าน · ตัวอย่าง PDF ไม่ว่าง ไม่ล้นหน้า
2. **ตาราง "ผ้าเพิ่ม" (PR 146) ทุกสินค้าที่มี:** เพิ่ม/ลบแถว · แถวไม่ครบถูกเตือน · ว่าง = ไม่พิมพ์ · มีข้อมูล = PDF มีตาราง · บันทึกไฟล์ → เปิดไฟล์คืนค่าครบ · **บันทึกเข้าระบบ** → หน้ารับงานได้ข้อมูลครบ (`spec` มี `fabric_rows`) · ใบร่างเก่าที่ไม่มี `fabric_rows` เปิดได้
3. วางจุดม็อคอัพในฟอร์ม → รับงาน → ม็อคอัพมีร่างจุดครบ (แบบรอบ 11)
4. 375 / 768 / 1440 px · ไม่มี error
