## ส่วน 0 — หลังบ้านในเครื่องที่ใช้ฐานข้อมูลจริง (ทำก่อน)
1. สร้าง `tools/qa-r14/server.mjs`: เปิดเว็บที่ build แล้ว + **API แบบ Supabase บน PGlite** ที่รัน `supabase/migrations/*.sql` ทั้งหมด (แบบ `supabase/tests/run.mjs` สร้าง schema `auth` `storage`)
   - `POST /rest/v1/rpc/<ฟังก์ชัน>` → เรียกฟังก์ชันจริงในฐานด้วยผู้ใช้ที่ล็อกอิน (`request.jwt.claim.sub` + `set local role authenticated` ให้ RLS ทำงาน)
   - `GET /rest/v1/<ตาราง/view>` → รองรับรูปแบบ query ที่หน้าเว็บใช้จริง (`select` `eq` `in` `order` `limit` `range` ฯลฯ · ไล่ดูจาก `app/src/data/*.ts`) ผ่าน RLS
   - ล็อกอินจำลองหลายบัญชี (เจ้าของ · ผู้บริหาร · แอดมิน 2 · ฝ่ายผลิต 2 · ผู้ควบคุมเฟส 1/2 · QC · staff หลายสถานี / สถานีเดียว / QC+Packing / ยังไม่จับคู่ · บัญชีที่ปิด) สลับได้ใน 1 คลิก
   - ไฟล์: ใช้ Worker จำลองแบบ `tools/r2-local/server.mjs` (R2 ในหน่วยความจำ) ให้อัปโหลด PDF / รูปม็อคอัพได้จริง
   - realtime ไม่ต้องมี (กดโหลดใหม่แทน) · บันทึกในรายงานว่ารองรับอะไรไม่ได้
2. ข้อมูลตั้งต้น: จักร 22 ตัว · บริษัทภายนอกจำลอง · เครื่องต่อสถานีตามจริง (พิมพ์ 2 · รีด 1 · ตัด 2 · รีดฟิล์ม 2) · ไม่มีงาน
3. รันซ้ำได้ ล้างข้อมูลด้วยคำสั่งเดียว · เขียนวิธีรันใน `tools/qa-r14/README.md`
**ถ้าทำส่วน 0 ไม่สำเร็จภายในเวลาที่เหมาะสม** ให้ต่อยอด `tools/qa-r13/api.mjs` ให้จำสถานะได้ แล้วบอกในรายงานว่าส่วนไหนทดสอบได้ไม่สมจริง

## ส่วน A — หนึ่งวันทำงานของแต่ละบทบาท (ทำตามคู่มือทีละขั้น · ถ่ายภาพทุกจุดที่ติด)
1. **แอดมิน:** กรอกใบยืนยันใน `/confirmation` ครบ 1 ใบต่อกลุ่มสินค้า (เสื้อ · ป้ายผ้า · กระเป๋า · หมวก · หมอน) รวม **ผ้าเพิ่ม** · **ลูกค้าส่งผ้ามาเอง** · วางจุดม็อคอัพ → บันทึกเข้าระบบ → รับงาน (แนบ PDF ทีหลัง) → สั่ง/รับฟิล์ม → ส่งออก / ส่งต่อ / รับกลับ (รวมเส้นทาง **ผลิตข้างนอกทั้งหมด**) → แบ่งงาน → บันทึกผลตัวอย่าง → จัดส่ง / ยกเลิกจัดส่ง → ทำ/แก้/อนุมัติม็อคอัพเอง
2. **ฝ่ายผลิต (2 คนพร้อมกันคนละแท็บ):** บอร์ด → สถานี → เริ่ม/เสร็จ/พักงาน · เริ่มก่อนคิว · แทรกงานด่วน · เลือกจักร/จัดการจักร/จักรเสีย · แก้แล้วทำต่อ · อนุมัติ/ส่งกลับม็อคอัพ · รายงานเกินเวลามาตรฐาน
3. **staff (มือถือ 375 px):** สถานีของตัวเองเท่านั้น · กดเริ่ม/เสร็จ/พัก · รับทราบสเปก · กดรูปม็อคอัพในรายละเอียดงาน → ม็อคอัพกำกับสเปก · staff ที่ยังไม่จับคู่
4. **QC (staff จับคู่ QC+Packing):** บันทึกผ่าน · ส่งแก้ไปสถานีต่างๆ (รวมสั่งผลิตข้างนอก) · ผ่านไม่ครบกดเสร็จไม่ได้ · ส่งตัวอย่าง
5. **ผู้บริหาร:** ภาพรวม · คิวงาน · ยกเลิกงาน (ทุกสถานะที่ทำได้/ไม่ได้) · อนุมัติม็อคอัพฉบับแก้ไข · รายงาน · ตรวจย้อนหลัง
6. **เจ้าของ:** ตั้งค่าทุกแท็บ · Station Assignment · บัญชีผู้ใช้ · ทำแทนทุกบทบาท
7. **ผู้ควบคุมงานเฟส 1 / เฟส 2:** เห็นและกดได้ตามเฟส
8. **ข้ามบทบาทต่อเนื่อง:** งานเดียวเดินครบทุกเส้นทาง 9 เส้นด้วยคนที่จะกดจริง · ตรวจบอร์ด ภาพรวม คิว กล่องจดหมาย ประวัติงาน ของทุกคนหลังแต่ละขั้น ว่าตรงกัน

## ส่วน B — ใช้งานได้จริงบนหน้างาน
1. ทุกหน้า × ทุกบทบาท ที่ **375 / 768 / 1440 px** · หน้าไม่ล้นด้านข้าง · ปุ่มหลัก ≥ 48 px · ตัวอักษรหลัก ≥ 16 px · ปุ่มที่กดไม่ได้บอกเหตุผล · สีตามความหมาย (แดง/ส้ม/ฟ้า/เขียว)
2. สถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด (ปิดหลังบ้านกลางคัน) · ไม่มี `NaN` `undefined` `Infinity` `null` บนจอ · ข้อความไทยทั้งหมด
3. เน็ตช้า (หน่วงหลังบ้าน 3 วินาที) · กดปุ่มรัวๆ · กดย้อนกลับของเบราว์เซอร์ · เปิด 2 แท็บแก้สิ่งเดียวกัน · ปิดแท็บกลางคันตอนกรอกฟอร์ม/แก้ม็อคอัพ (กู้งานที่ยังไม่บันทึก)
4. **พิมพ์ออกกระดาษ / PDF:** ใบยืนยัน (ทุกกลุ่มสินค้า) · ใบปะงาน · ใบกำกับงานพิมพ์ A4/A3 · ข้อมูลครบ ไม่ตกขอบ ไม่ซ้อน · เก็บไฟล์ PDF เป็นหลักฐาน
5. **คำบนจอ vs คู่มือ:** ทุกขั้นที่คู่มือบอก ปุ่ม/ข้อความ/เมนูมีจริงและชื่อตรงกัน · จดภาพในคู่มือที่ล้าสมัย

## ส่วน C — ลองทำผิดแบบคนจริง
คีย์ข้อมูลผิดรูปแบบ (จำนวน 0 / ติดลบ / ทศนิยม / ภาษาอังกฤษในช่องตัวเลข) · วันที่ย้อนหลัง · ชื่อยาวมาก · อีโมจิ · วางข้อความจาก Excel · อัปโหลดไฟล์ผิดชนิด/ใหญ่เกิน · ใส่ `<script>` ในทุกช่องข้อความ · ลืมกด "บันทึก" แล้วเปลี่ยนหน้า · กดอนุมัติทั้งที่ยังไม่ตรวจ → ระบบต้องกันหรือบอกให้ชัด
