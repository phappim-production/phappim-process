## ⛔ ห้ามแตะระบบจริงเด็ดขาด
ระบบใช้งานจริงอยู่ มีงานจริงและทีมจริง · **ห้ามเปิด / เรียก / ล็อกอิน** `pp142.pages.dev` · `*.supabase.co` · `*.workers.dev` · R2 จริง · ห้ามใช้บัญชีใดๆ ของระบบจริง · ห้ามอ่านโฟลเดอร์ `.pp142-r2` · ทุกอย่างรันบน `127.0.0.1` เท่านั้น
- เปิดระบบจำลองตาม `tools/qa-r14/README.md` แต่ **ใช้พอร์ต 5234 / 5235** (5214 อาจมีของ Claude เปิดอยู่ ห้ามใช้ร่วม):
  ```powershell
  npm.cmd --prefix app ci; npm.cmd --prefix supabase\tests ci; npm.cmd --prefix workers\files ci
  $env:VITE_SUPABASE_URL = 'http://127.0.0.1:5234'
  $env:VITE_SUPABASE_ANON_KEY = 'r14-local-anon-key'
  $env:VITE_FILES_URL = 'http://127.0.0.1:5235'
  npm.cmd --prefix app run build
  $env:QA_PORT = '5234'; $env:QA_FILES_PORT = '5235'; $env:QA_ORIGIN = 'http://127.0.0.1:5234'
  $env:QA_MATERIALS_CHECK = '1'           # เปิดขั้นรอผลิตเหมือนระบบจริง (ไม่ตั้ง = ปิด · ชุด QA เดิมใช้แบบปิด)
  $env:QA_IMG_DIR = "$PWD\docs\qa\img\r20-ag"
  node tools/qa-r14/server.mjs
  ```
- **ระบบจริงเปิดขั้นรอผลิตอยู่** → ส่วน A และ C ต้องรันด้วย `QA_MATERIALS_CHECK=1` · ชุดสคริปต์เดิม (`qa-part-a/b/c` ฯลฯ) เขียนไว้ตอนยังไม่มีขั้นนี้ ให้รันแบบไม่ตั้งค่านี้ (หรือ `Remove-Item Env:QA_MATERIALS_CHECK`) · สลับกลางทางได้ด้วย `/__qa/sql` (`update public.production_settings set materials_check = true/false`)
- build แบบ loopback **ทุกครั้ง** (`npm run build` เฉยๆ จะชี้ระบบจริง) · ก่อนเริ่มและก่อนส่งงาน ตรวจ bundle ใน `app/dist` ว่ามี `127.0.0.1:5234` และไม่มี URL ระบบจริงที่ถูกเรียก · ใส่ผลตรวจในรายงาน

## ส่วน A — ขั้นรอผลิต (PR 231 + 233 · ใหม่ล่าสุด) — ละเอียดที่สุด
ตั้ง `QA_MATERIALS_CHECK=1` · ผ้าหน่วย **หลา** (เช่น "ผ้าคอตตอน 32 สีขาว 150 หลา") · ใช้รูปจริงหลายแบบ (JPG / PNG / WEBP / แนวตั้ง-นอน / ใหญ่ 10 MB+ / เล็กมาก / ไฟล์ที่ไม่ใช่รูปแต่ตั้งชื่อ .jpg / HEIC ถ้ามี)
1. **รับงานทุกแบบแล้วต้องค้างที่ "รอผลิต":** ไม่ขึ้นตัวอย่าง · ขึ้นตัวอย่าง · Develop · ทุกเส้นทาง (รวม DTF / DTG / สกรีน · ผลิตข้างนอก) · รับจากฟอร์มใบยืนยัน / แนบ .json · ข้อความหลังรับงานบอกให้ไปเช็ควัตถุดิบ · คอลัมน์ + ปุ่ม "รอผลิต" อยู่ถัดจาก "ทุกสถานี" · การ์ดขึ้น "รอเช็ควัตถุดิบ" · เวลาผลิตยังไม่เริ่มนับ (รอนานเท่าไรก็ไม่ขึ้นส้ม/แดงเรื่องเวลาผลิต · ไม่ถูกนับเป็นงานเกินเวลาในภาพรวม/รายงาน)
2. **ใครเห็นอะไร:** staff (สถานีเดียว / หลายสถานี / ยังไม่จับคู่) · QC · ผู้ควบคุมเฟส 1/2 ต้องไม่เห็นงานรอผลิตบนบอร์ด/คิว/ต้องทำตอนนี้ของตัวเอง แต่เปิดจาก "ทั้งโรงงาน" แล้วเห็นแบบอ่านอย่างเดียว (โหมดพม่าต้องเป็นพม่า) · ฝ่ายผลิต / ผู้บริหาร เห็นรายการ + รูป แต่ไม่มีปุ่มแก้/ติ๊ก/ปล่อย · แอดมิน + เจ้าของ ทำได้ทุกอย่าง · **เรียก RPC ตรงด้วย token ของทุกบทบาท** (`set_job_materials` `check_material` `add_material_photos` `remove_material_photo` `release_job`) ต้องได้เฉพาะ admin / owner
3. **รายการวัตถุดิบ:** เพิ่มทีละรายการ (ปุ่มเพิ่ม + Enter) · ชื่อซ้ำ (ตัวพิมพ์เล็กใหญ่ / ช่องว่างหัวท้าย) · ชื่อว่าง · ยาว 80+ ตัว · 30 รายการแล้วเพิ่มอีก · อีโมจิ / `<script>` / วางจาก Excel · ลบ · ติ๊ก / เลิกติ๊ก · ลบรายการที่ติ๊กแล้ว รายการอื่นต้องคงติ๊ก · **กดเพิ่มรัวๆ หลายรายการติดกัน** ต้องไม่ขึ้น "แก้จากเครื่องอื่น" · **2 แท็บ / 2 แอดมินแก้รายการงานเดียวกันพร้อมกัน** ต้องไม่ทับกันเงียบๆ (ต้องบอกให้ดูรายการล่าสุด)
4. **รูปวัตถุดิบ:** ถ่าย / เลือกจากคลังรูป 1 รูป / หลายรูปพร้อมกัน / ครบ 12 แล้วเพิ่มอีก · รูปเดิมซ้ำ · ลบรูป (ปุ่มลบต้องไม่ทับรูปข้างๆ ที่ 375 px) · **ใช้รูปม็อคอัพของงานแทนรูปวัตถุดิบ** ต้องไม่ได้ · เน็ตหลุดกลางอัปโหลด · รูปเปิดดูเต็มได้ · คนที่ไม่เห็นงานเปิดรูปได้ไหม · อัปโหลดเข้าโฟลเดอร์งานอื่นแล้วส่ง (เรียก RPC ตรง) ต้องถูกปฏิเสธ
5. **ปล่อยเข้าไลน์:** ปุ่มกดไม่ได้ + บอกเหตุผลถูกต้องทุกกรณี (ไม่มีรายการ · ยังไม่ติ๊ก [บอกชื่อ] · ไม่มีรูป) · กล่องยืนยันบอกปลายทางถูก (สถานีแรกตามเส้นทาง / ขึ้นตัวอย่าง) · "ยังไม่ปล่อย" ยกเลิกได้ · หลังปล่อย: งานไปสถานีแรก/ตัวอย่างจริง · **คิวต่อท้าย** (หลังงานที่ปล่อยก่อน แม้รับมาทีหลัง) · เวลาผลิตเริ่มนับวันนี้ (เทียบ 10/15/20 วันตามจำนวน) · แก้รายการ/รูปไม่ได้แล้ว · ประวัติงานมี ตั้งรายการ / ติ๊ก / ถ่ายรูป / ลบรูป / ปล่อย (จำนวนรายการ + รูป) · กดปล่อยซ้ำ / 2 แท็บกดปล่อยพร้อมกัน
6. **ขอบเขตที่ยาก:** ผู้บริหารยกเลิกงานระหว่างรอผลิต (แล้วแอดมินกดอะไรต่อต้องบอกว่ายกเลิกแล้ว) · แก้ใบยืนยันหลังรับงานระหว่างรอผลิต · แนบ PDF / ม็อคอัพระหว่างรอผลิต · สั่งฟิล์ม / ได้รับฟิล์มระหว่างรอผลิต (งานต้องไม่หลุดเข้าไลน์เอง) · แบ่งงาน (ควรทำไม่ได้จนปล่อย) · **ปิดขั้นรอผลิตกลางทาง** (`/__qa/sql`): งานใหม่เข้าสถานีแรกทันที · งานที่ค้างอยู่กดปล่อยได้โดยไม่ต้องเช็ค · เปิดกลับแล้วงานใหม่ค้างอีก
7. **กล่องจดหมาย:** งานรอผลิตเกิน 2 วันทำงาน (ขยับ `stage_entered_at` ใน `/__qa/sql`) → แอดมินได้ "รอผลิตนาน" ทั้งงานที่ยังไม่มีรายการและที่ยังไม่ติ๊ก · บทบาทอื่นไม่ได้ · ไม่ส่งซ้ำวันเดียวกัน · ปิดชนิดนี้ในตั้งค่าแล้วไม่ส่ง · ข้อความ "เกินเวลาผลิต" บอกวันเริ่มนับ = วันปล่อย
8. **หน้าอื่นที่ต้องสอดคล้อง:** ภาพรวม (แถบ "รอผลิต" · ต้องตาม) · ต้องทำตอนนี้ · ค้นหางาน · หน้ากำหนดส่งลูกค้า (สถานะ + วันคาดว่าเสร็จของงานรอผลิตนับวันตัวอย่างด้วย) · รายงาน · วางแผนรับงาน · ใบปะงาน

1. **เวลาผลิตทั้งงาน (PR 215 · 221):** 10/15/20 วันตามจำนวนในใบ (ไม่รวมเผื่อเสีย) · วันอาทิตย์ไม่นับ · 80% ส้ม · เลยวันแดง + กล่องจดหมาย 1 ครั้ง · QC + Packing กดเสร็จไม่ได้จนรายงานสาเหตุ 1 ครั้ง · งานแบ่ง (นับจำนวนรวมของงานแม่) · ยกเลิกบางส่วน (เวลาต้องไม่หด) · ตัวอย่าง / ส่งออก / พัก นับต่อ · หน้ารับงานเตือนกำหนดส่งเร็วกว่าเวลาผลิต · ตัวเลขบนการ์ด = รายละเอียดงาน = รายงาน = กล่องจดหมาย
2. **ปี พ.ศ./ค.ศ. (PR 216 · 226):** พิมพ์ 2569 ลงช่องวันที่ทุกช่อง (กำหนดส่ง · ฟิล์ม · ส่งออก · ตัวอย่าง · จองจักร) ต้องถูกปฏิเสธพร้อมคำบอก · infinity / BC (เรียกตรง)
3. **ใบยืนยัน (PR 209–211 · 217–219 · 226):** ชนิดปก (ปกสำเร็จ / พิมพ์ / จีน / อื่นๆ · คอกลม/คอวีมีปก · โปโล) · **ฉบับลูกค้า** (PDF ที่ลูกค้าเซ็น) แสดงเฉพาะรายการที่อนุมัติ ไม่มีเผื่อเสีย/เทคนิค/สีหมึก/การเย็บ/สีผ้า · ม็อคอัพหน้าใหม่เหนือเงื่อนไข · **ฉบับโรงงาน** (เปิดจากระบบ) เห็นครบ · เปิดฟอร์ม 2 แท็บ (แต่ละแท็บจำใบของตัวเอง + เตือน) · ใบแก้ครั้งเดิมจาก 2 แท็บต้องไม่ทับกัน
4. **รับทราบใบแก้ (PR 212):** ทุกบทบาทดูใบยืนยันฉบับล่าสุดได้ · ป้าย "ใบแก้ครั้งที่ N" · สถานีต้องกดรับทราบก่อนกดเสร็จ · สถานีถัดไปต้องรับทราบอีก · งานแบ่งรับใบแก้ของงานแม่
5. **กันจอขาว (PR 222 · 229):** ระหว่างเปิดค้างแล้วมีรุ่นใหม่ (build ใหม่) → โหลดใหม่เองหรือมีปุ่ม · เน็ตช้าไม่ล้างแคชวน · ไฟล์หน้าโหลดไม่ได้ เมนูยังอยู่
6. **แอปมือถือ (PR 223):** การ์ดติดตั้งแอปในหน้าบัญชี (Android / iPhone / เปิดจาก LINE) · กันจอดับเฉพาะ staff/QC ที่หน้าบอร์ด · แอปที่ติดตั้งเปิดฟอร์มใบยืนยันในหน้าเดิม + ปุ่ม "กลับหน้าระบบ" (จำลองด้วย Chrome DevTools · ระบุว่าทดสอบไม่ได้บนเครื่องจริง)
7. **หน้ากำหนดส่งลูกค้า (PR 227):** เรียง เลยกำหนด → วันนี้ → พรุ่งนี้ → 14 วัน → หลังจากนั้น (วันไทย) · ตัวกรอง · วิธีรับสินค้า + ที่อยู่ · คาดว่าไม่ทัน · พิมพ์หลายหน้า · staff / QC เปิดไม่ได้ · เมนูมือถือไม่ดันปุ่มหลักออก
8. **ตรวจบั๊กรอบ 3–4 (PR 220 · 226 · 229):** ข้อที่แก้ใน `docs/handoff/claude-bug-sweep.md` ต้องไม่กลับมา (ลองทำซ้ำตามวิธีในไฟล์)

## ส่วน C — ครบระบบ: ทุกบทบาท × ทุกเส้นทาง (ทำตามคู่มือทีละขั้น · เปิดขั้นรอผลิตไว้ตลอดส่วนนี้ · ถ่ายภาพทุกจุดที่ติด)
1. **ทุกเส้นทาง** (รวมผลิตข้างนอก · มีตัวอย่าง · Develop · DTF/DTG/สกรีน) เดินครบ รับงาน → รอผลิต → ปล่อย → ทุกสถานี → QC → เสร็จ → จัดส่ง ด้วยคนที่จะกดจริง · หลังแต่ละขั้นตรวจบอร์ด ภาพรวม คิว กล่องจดหมาย ประวัติ รายงาน หน้ากำหนดส่ง ของทุกบทบาทว่าตรงกัน
2. **แอดมิน:** ใบยืนยัน (ทุกสินค้าผ่าน `confirmation-all.mjs <โฟลเดอร์ผล>` + กดมือ 8 กลุ่ม) → บันทึกเข้าระบบ → รับงาน → เช็ควัตถุดิบ → ปล่อย → แนบ PDF → ฟิล์ม → ส่งออก/รับกลับ → แบ่งงาน → ผลตัวอย่าง → แก้ใบหลังรับงาน → จัดส่ง / ยกเลิกจัดส่ง → ม็อคอัพ ทำ/แก้/อนุมัติ
3. **ฝ่ายผลิต 2 คนพร้อมกัน:** เริ่ม/เสร็จ/พัก · เริ่มก่อนคิว (ต้องใส่เหตุผลทุกทาง) · แทรกงานด่วน · จักร (เลือก/เสีย/คืน/จอง) · รายงานสาเหตุเกินเวลาผลิต
4. **staff มือถือ 375 px โหมดพม่า:** สถานีเดียว / หลายสถานี / ยังไม่จับคู่ · รับทราบสเปก/ใบแก้ · ดูม็อคอัพ · รายงานปัญหา · คนอ่านไทยไม่ออกทำงานได้ครบจากไอคอน สี เลขสถานี คำพม่าไหม
5. **QC + Packing โหมดพม่า:** ผ่าน · ส่งแก้ทุกสถานี (รวมผลิตข้างนอก) · ผ่านไม่ครบกดเสร็จไม่ได้ · รายงานสาเหตุเฉพาะงานที่อยู่ QC · error เป็นพม่า
6. **ผู้บริหาร / เจ้าของ / ผู้ควบคุมเฟส 1–2:** ภาพรวม · คิว · ยกเลิกงานทุกสถานะ (รวมรอผลิต) · รายงาน · ตรวจย้อนหลัง · ตั้งค่าทุกแท็บ · บัญชี (เปิด/ปิด · บัญชีที่ปิดเข้าไม่ได้/อ่านไม่ได้) · จับคู่สถานี · ทำแทนทุกบทบาท
7. **รูปยืนยันงานสถานี (ยังปิดบนระบบจริง):** เปิดฟีเจอร์ในระบบจำลอง (`demo-v3.mjs` หรือ ตั้งค่า → สถานี) แล้วเดิน 1 เส้นทางเต็ม ตรวจว่าไม่ชนกับขั้นรอผลิต (รูปวัตถุดิบ ≠ รูปชิ้นแรก / รูปงานเสร็จ)
8. **คำบนจอ vs คู่มือ:** ปุ่ม/เมนูตรงกันไหม · ภาพคู่มือที่ล้าสมัย · คู่มือฝ่ายผลิต/เจ้าของเรื่องรอผลิตตรงระบบไหม

## ส่วน D — ทุกมิติที่เหลือ
1. **สิทธิ์และความปลอดภัย:** ทุกบทบาทเปิด URL หน้าที่ไม่ใช่ของตัวเองตรงๆ (`#/…`) · เรียก RPC ทุกตัวด้วย token ของทุกบทบาท (ตาราง `supabase/tests/flow-r13-matrix.mjs` = 53 RPC เป็นคำตอบที่ถูก · ต่อยอด `tools/qa-r13`) · เขียนตารางตรงผ่าน REST (ต้องไม่ได้ รวม `job_materials` `job_material_photos` `production_settings`) · บัญชีที่ปิดใช้ · XSS (`<script>` `<img onerror>`) ในทุกช่องที่แสดงผลและพิมพ์ รวมชื่อวัตถุดิบ
2. **ความถูกต้องของข้อมูล:** ยอดรวมบอร์ด = ภาพรวม = รายงาน · งานที่แบ่งไม่นับซ้ำ · events 1 แถวต่อการเปลี่ยนสถานะ · ไม่มีงานค้างสถานะแปลก (`phase` กับ `station_status` ขัดกัน · งาน `materials` ที่มีสถานี) หลังทุกเส้นทาง — เขียน SQL ตรวจในระบบจำลองแล้วแนบผล
3. **หน้าจอ:** ทุกหน้าที่ **375 / 768 / 1440 px**: ไม่ล้นด้านข้าง · ปุ่มหลัก ≥ 48 px · ตัวอักษรหลัก ≥ 16 px · ปุ่มที่กดไม่ได้บอกเหตุผล · ไม่มี `NaN` `undefined` `null` `Invalid Date` · console ไม่มี error (ยกเว้น Realtime) · สถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด (ปิดหลังบ้านกลางคันแล้วเปิดใหม่) · ใช้คีย์บอร์ดอย่างเดียวได้ในหน้าหลัก
4. **เน็ตและการใช้งานจริง:** เน็ตช้า (หน่วง 3 วิ) · ออฟไลน์กลางคันตอนส่งรูป/กดเสร็จ/บันทึกใบยืนยัน/ปล่อยเข้าไลน์ · กดรัว · ย้อนกลับเบราว์เซอร์ · 2 แท็บแก้สิ่งเดียวกัน · ปิดแท็บกลางคัน · ข้อความภาษาอังกฤษ ("Failed to fetch" ฯลฯ) หลุดขึ้นจอไหม
5. **พิมพ์ / PDF:** ใบยืนยันฉบับลูกค้า + ฉบับโรงงาน (ก่อนและหลังแก้ใบ · หลายแบบหลายรูป · "อื่นๆ" · ชนิดปก) · ใบปะงาน A5 · ใบม็อคอัพ A4/A3 · หน้ากำหนดส่งลูกค้า · ตรวจไม่มีข้อความขาด / ทับรูป / ล้นหน้า · เก็บเป็นหลักฐาน
6. **ทำผิดแบบคนจริง:** จำนวน 0 / ติดลบ / ทศนิยม / ใหญ่มาก · ชื่อยาวมาก · อีโมจิ · วางจาก Excel · ไฟล์ผิดชนิด / 0 ไบต์ / ใหญ่เกิน 20 MB · วันที่ย้อนหลัง / วันอาทิตย์ / ข้ามปี / ปี พ.ศ.
7. **เวลา:** งานข้ามเที่ยงคืน / ข้ามวันอาทิตย์ · เลยกำหนด X วันนับถูก · เวลาไทย (ตั้งเขตเวลาเครื่องเป็นอย่างอื่นแล้วตัวเลขยังถูก · โดยเฉพาะวันเริ่มนับเวลาผลิตหลังปล่อยตอนตี 1)
8. **ข้อมูลเยอะ:** งาน 300+ งาน (รวม 50 งานค้างรอผลิต) + events หลายพัน → บอร์ด/ภาพรวม/รายงาน/ประวัติ/หน้ากำหนดส่งยังเปิดเร็ว (จับเวลา)
