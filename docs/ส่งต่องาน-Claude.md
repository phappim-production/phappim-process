## พฤติกรรมที่ผู้ใช้ยืนยันแล้ว

- **ล็อกอินพนักงาน** ใช้ Supabase Auth บัญชีต้องเปิดใช้งานและมีบทบาท เปลี่ยนรหัสผ่านจากหน้าบัญชีได้ ผู้ควบคุมงานแบ่งเฟส 1 พิมพ์–รีด–ตัด และเฟส 2 เย็บ–QC สิทธิ์เปลี่ยนสถานะงานตรวจที่ฐานข้อมูล
- **แดชบอร์ด** ภาพรวมแยกงานที่ต้องตาม ค้นหางาน และวางแผน บอร์ดเลือกสถานีหรือค้นหาได้ทันที ส่วนสถานะและเส้นทางอยู่ในตัวกรองเพิ่มเติม การเลือกทั้งโรงงานมีผลกับบอร์ด รายการ **ต้องทำตอนนี้** อิงขอบเขตของบทบาท
- **หน้าจักรเย็บ** แยกงานเย็บ ตารางจอง และสถานะจักร เฟส 2 เปิดที่งานเย็บ ฝ่ายผลิตเปิดที่ตารางจอง ฝ่ายผลิตแจ้งเสียได้และระบุอาการกับเวลาคาดว่าซ่อมเสร็จ
- **จองจักร** ฝ่ายผลิตจองและยกเลิกได้ เจ้าของระบบทำแทนได้ แสดงช่วงเวลาไทยและชุดจักรก่อนยืนยัน ฐานข้อมูลกันจองทับและจองไม่ครบชุด ยกเลิกตรงเวลาเริ่มได้ จักรที่กำลังใช้งานยังอยู่ในชุดจองล่วงหน้าได้เมื่อช่วงที่ขอไม่มีจองทับและจักรครบ พอถึงเวลาเริ่มต้องตรวจจักรที่ว่างจริงอีกครั้ง
- **ปุ่มหน้างานเย็บ** ใช้ **เริ่มเย็บ**, **รายงานปัญหา** และ **เย็บเสร็จ** รายงานแล้วทำต่อได้ หรือเลือกพักและกด **เย็บต่อ** หลังแก้ปัญหา ตรวจตัวแรก นับยอด และเก็บปลายไลน์ที่หน้างาน เมื่อยืนยันเย็บเสร็จ ระบบส่งต่อ QC + Packing และคืนจักร งานที่พักอยู่ต้องเย็บต่อก่อนยืนยันเสร็จ

## สิ่งที่ตรวจยืนยันแล้ว

- `npm run build` และ `npm run lint` ผ่าน ชุดทดสอบหน้าเว็บผ่าน **60 กรณี** และฐานข้อมูลใน PGlite ผ่าน **307 กรณี**
- ทดสอบเบราว์เซอร์ที่ **375, 768 และ 1440 px** ด้วยบัญชีและข้อมูลจำลอง ครอบคลุมเลือกสถานี จองและยกเลิกจักร เริ่มเย็บ รายงานแบบทำต่อ พัก เย็บต่อ ยืนยันเสร็จ ตรวจว่างานไป QC และเปิดดูประวัติรายงาน
- ตรวจ Supabase จริงแบบอ่านอย่างเดียวผ่าน MCP พบ `jobs` ส่วน `job_live`, `machine_bookings` และ `finish_sewing(uuid)` ยังไม่มี ดังนั้น A4/A5 ยังต้องต่อหน้าเว็บและทดสอบกับฐานข้อมูลทดลองก่อนใช้งานจริง

รันซ้ำจากโฟลเดอร์ `app/`

```powershell
npm run build
npm run lint
node --experimental-strip-types --test tests/*.test.mjs
```

รัน `npm test` จาก `supabase/tests/` เพื่อทดสอบ migration และ workflow

## ลำดับรับช่วงต่อ

1. ตรวจ working tree และรวม A1/A2 ตามสถานะ PR กับกติกาโปรเจกต์ก่อนเริ่มต่อ RPC
2. เทียบ schema และประวัติ migration ของฐานทดลอง แล้วลง migration ตามลำดับ ทดสอบด้วยบัญชีฝ่ายผลิต ผู้ควบคุมงานเฟส 2 และ QC
3. ต่อข้อมูลจริงและ RPC โดยให้ฐานข้อมูลเป็นแหล่งตัดสินสิทธิ์ สถานะงาน และจำนวนจักร ใช้รายการจักรจริงจากหน้างานก่อนเปิดใช้
4. ทดลองเดินงานจากเริ่มเย็บถึง QC รวมการจองพร้อมกัน การรายงานแล้วพัก การเย็บต่อเมื่อจักรครบ และการคืนจักรอัตโนมัติ
