## เปลี่ยนอะไร

- **ฐานข้อมูล** `20261129000000_station_photos.sql`: ตาราง `station_checks` · `station_photo_settings` (เปิด/ปิด) · `stations.first_piece_check` · RPC `submit_first_piece` / `decide_first_piece` / `add_finish_photos` / `set_station_photos_enabled` / `station_photo_flags` · `finish_station` ปฏิเสธเมื่อยังไม่มีรูป (ผ่าน `missing_substeps`) · หักเวลารออนุมัติออกจากเวลามาตรฐาน · กล่องจดหมาย 3 แบบ (รออนุมัติ · รอเกิน 15 นาที · ไม่ผ่าน) · รูปชนิด `station_photos` ใน R2
- **Worker** `workers/files`: รับชนิด `station_photos` (JPG ใน `งาน/สถานี/รอบ/`) · สิทธิ์อัปโหลดตัดสินที่ฐานข้อมูล (หัวหน้าสถานี / พนักงานสถานี / QC)
- **หน้าเว็บ**: แผงรูปบนการ์ดหน้าคิวสถานีและรายละเอียดงาน (ย่อรูป 1600 px ในเครื่อง) · การ์ด "รออนุมัติชิ้นแรก" บนสุดของทุกหน้าสำหรับแอดมิน/ผู้บริหาร + หน้าเทียบม็อคอัพ · หัวข้อ "รูปจากสถานี" ในประวัติงาน · ตั้งค่าเปิด/ปิด + เลือกสถานีในหน้าตั้งค่า · คำแปลพม่า
- **คู่มือ**: ฝ่ายผลิต 3.5 · QC 3.5 · แอดมิน 10.4 · ผู้บริหาร 5.4 · เจ้าของระบบ

## ตรวจทานก่อน commit (ตรวจเอง + ผู้ตรวจอิสระ) · แก้แล้วทั้งหมดพร้อมทดสอบ

- แท็บจักรเย็บ / รายละเอียดงานสถานีเย็บ ไม่มีช่องถ่ายรูป → ฝ่ายผลิตกดเย็บเสร็จไม่ได้และไม่มีที่ส่งรูป · เพิ่มแผงรูป + ปุ่มบอกเหตุผล
- ปิดฟีเจอร์ระหว่างรออนุมัติ → รายการค้าง "รอ" ตลอดไป หักเวลามาตรฐานสถานีถัดไป + เตือนงานที่ออกไปแล้ว · ไม่นับ/ไม่เตือนเมื่องานออกจากสถานี · ตัดสินไม่ได้
- เวลารออนุมัติซ้อนกับพักงาน / รอเครื่องว่าง ถูกหักซ้ำ · หักส่วนซ้อนออก
- เตือนรอเกิน 15 นาทีทำงานเฉพาะตอนมีคนเปิดเว็บ (pg_cron เรียก `inbox_scan_all` ตรง) · เพิ่ม `private.inbox_scan_cron()` และตั้ง cron ใหม่
- งานที่พักระหว่างรออนุมัติหายจากคิวอนุมัติของแอดมิน · แสดงพร้อมป้าย "พักงานอยู่"
- กดผ่านได้ทั้งที่รูปโหลดไม่ขึ้น · ต้องเห็นรูปอย่างน้อย 1 รูป
- เวลาเตือน 15 นาทีฝังในหน้าเว็บ · ใช้ค่าที่ตั้ง + เพิ่มตัวเลือกในหน้าตั้งค่า
- ส่งรูปงานเสร็จเพิ่มหลังส่งไปแล้วไม่ได้ · เพิ่ม "ส่งรูปงานเสร็จเพิ่ม"
- ข้อความ Worker บอก PNG/WEBP กับรูปสถานี · แก้เป็น JPG

ตรวจแล้วไม่ใช่บั๊ก: แผงรูปในรายละเอียดงานแสดงเฉพาะตอนกำลังทำอยู่แล้ว · ฟังก์ชันที่คัดลอกมาแก้ (`missing_substeps` `sla_state` `check_file_upload` `file_read_allowed` `inbox_scan`) พฤติกรรมเดิมครบ

## ก่อนเปิดใช้จริง (Claude ทำ · เจ้าของอนุมัติก่อน merge)

1. ลง migration `20261129000000` ที่ฐานข้อมูลจริง (ฟีเจอร์ยังปิดอยู่ ไม่กระทบงานที่กำลังเดิน)
2. Deploy Worker `workers/files` ใหม่ (รับชนิด `station_photos`) **ก่อน** เปิดใช้
3. Merge หน้าเว็บ → เจ้าของกด **เปิดใช้** ที่ ตั้งค่า → สถานีและขั้นย่อย
4. อบรมหน้างาน: ถ่ายชิ้นแรกแล้วหยุดรอ · แอดมินเปิดกระดิ่ง/การ์ดบนสุดตลอดวัน

## ยังไม่ได้ทำ / ข้อจำกัด

- ยังไม่ได้ลองบนมือถือจริง (กล้องจริง / ไฟล์ HEIC จาก iPhone): โค้ดแปลงเป็น JPG ด้วย canvas ถ้าเบราว์เซอร์เปิดรูปไม่ได้จะบอกให้ถ่ายใหม่ · ควรลองกับเครื่องหน้างาน 1 เครื่องก่อนเปิดใช้
- การเตือนรอเกินเวลาตรวจทุก 5 นาที (pg_cron + หน้าเว็บ) → เตือนช้าสุด ~5 นาทีหลังครบกำหนด · ถ้าฐานจริงไม่มี pg_cron จะเตือนเฉพาะตอนมีคนเปิดเว็บ (ต้องเช็กตอนลง migration)
- ไม่ได้บังคับ "ห้ามทำทั้งล็อตก่อนอนุมัติ" ทางกายภาพ ระบบบังคับแค่กดเสร็จ · หัวหน้าต้องคุมหน้างาน
- ติ๊ก/เอาติ๊กสถานีล็อกชิ้นแรกออกมีผลกับงานที่กำลังทำทันที (หน้าตั้งค่าเตือนไว้) · ควรเปลี่ยนตอนไม่มีงานรอ
- งานที่แบ่ง: ประวัติรูปของงานลูกไม่แสดงรูปก่อนแบ่ง (กฎยังนับรูปของงานต้นทางให้)
- แจ้ง "ชิ้นแรกไม่ผ่าน" ส่งถึงหัวหน้า/พนักงานทุกสถานี ไม่ใช่เฉพาะสถานีนั้น (กล่องจดหมายแยกตามบทบาท)
- การแก้รอบตรวจทานทดสอบด้วยชุดทดสอบ (ฐานข้อมูล + หน้าเว็บ) · ยังไม่ได้ลองซ้ำในเบราว์เซอร์ (จะลองก่อนเปิด PR)
