## ทำไม
19 พ.ย. ค่ำ ระบบเปลี่ยนเยอะ (PR 95–99) และยังไม่เคยเดินงานครบทุกสถานี **โดยเปิดกฎทั้งหมดพร้อมกัน**:
- **จำนวนเครื่องต่อสถานี** (`stations.machines` / `machine_pool` · `private.station_full`) — พิมพ์ 2 · รีด 1 · ตัด 2 · รีดฟิล์ม 2 · QC 1 · ปัก/เย็บไม่จำกัด · งานพัก/ข้างนอกไม่นับ · แก้ปัญหาตอนเครื่องเต็ม → กลับเข้าคิว
- **เย็บเลือกจักรตามรหัส** `start_sewing(p_job, p_codes)` + `assign_machines` / `release_machines`
- **บทบาท `staff`** กดได้เฉพาะสถานีใน `staff_stations` · **Audit Log** (`audit_log`) · **รับทราบของผู้บริหาร** (`ack_review`)
- ใน `run.mjs` ชุดทดสอบปกติ **ปิดจำนวนเครื่อง** (`update stations set machines = null`) เพราะชุดอื่นทิ้งงานกำลังทำไว้ → **รอบนี้ต้องเดินด้วยค่าเครื่องจริง** ในธุรกรรมของตัวเอง (ดูแบบ `flow-routes.mjs` ที่เดินในธุรกรรมแล้ว rollback)

## สิ่งที่ต้องทดสอบ

### A. ฐานข้อมูล (`flow-r9.mjs` · ธุรกรรมเดียว rollback ตอนจบ · ค่าเครื่องจริงตามข้อ "ทำไม")
1. **เดินครบทุกเส้นทาง** (ปกติ · DTF · DTG · สกรีน · ปัก · พิมพ์+ปัก · ตัดงานลูกค้า · ไม่พิมพ์) ตั้งแต่ `receive_job` → ขึ้นตัวอย่าง (ถ้ามี) → `record_sample_result` → ทุกสถานี → QC ผ่านครบ → เสร็จ · ใช้ผู้ใช้ตามบทบาทจริง (แอดมินรับงาน/ฟิล์ม/ตัวอย่าง · ฝ่ายผลิตเดินสถานี/เย็บ · QC บันทึกผล) · ทุกขั้นมี `events` 1 แถว
2. **เครื่องเต็มทุกสถานีที่จำกัด:** เปิดงานจนเต็ม → งานถัดไปเริ่มไม่ได้ (ทั้ง `start_station` และ `start_in_queue`) · ข้อความบอกรหัสงานที่ใช้เครื่อง · พักงาน 1 งาน → เริ่มงานใหม่ได้ · `close_issue` ตอนเครื่องเต็ม → `queued` + `requeued: true` · ส่งออกข้างนอก (`send_out`) ไม่นับเครื่อง · รีด กับ รีดฟิล์ม **ไม่** นับรวมกัน
3. **กดพร้อมกัน:** 2 คำขอเริ่มงานต่างกันที่สถานีเหลือเครื่องว่าง 1 ตัว → ผ่านแค่ 1 (ถ้า PGlite จำลองพร้อมกันไม่ได้ ให้เขียนว่าทดสอบไม่ได้และเหตุผล)
4. **เย็บเลือกจักร:** เลือกตัวว่าง · ตัวเสีย · ตัวงานอื่นใช้ · ตัวจองให้งานอื่น · ชนิดที่สินค้าไม่ใช้ · จักรใช้ร่วม · เลือกไม่ครบ · ไม่ส่ง `p_codes` (เลือกให้) · ระหว่างเย็บ `assign_machines` / `release_machines` จนเหลือไม่ครบชุด (ต้องถูกปฏิเสธ) · `finish_sewing` คืนจักรครบ · จักรเสีย 1 ตัวจากหลายตัวไม่พักงาน
5. **บทบาท `staff`:** จับคู่สถานีพิมพ์ → เดินพิมพ์ได้ · สถานีอื่นถูกปฏิเสธ · QC เฉพาะเมื่อจับคู่ `qc_pack` · `close_issue` / `move_job_ahead` / `receive_job` / `start_sewing` ถูกปฏิเสธ
6. **Audit Log:** เจ้าของแก้สถานี (จำนวนเครื่อง) / ผู้ใช้ / จับคู่สถานี → มีแถวพร้อมค่าเดิม-ค่าใหม่ · คนอื่นแก้ไม่ได้และไม่มีแถว · แก้/ลบ `audit_log` ไม่ได้
7. **รับทราบผู้บริหาร:** `ack_review` ทั้ง `delay_report` และ `queue_event` · บทบาทอื่นถูกปฏิเสธ · รายการที่ไม่ใช่ประเภทนั้นถูกปฏิเสธ
8. **PDF ใบยืนยัน + ใบปะงาน:** `attach_confirmation_pdf` ตามกฎ `private.check_confirmation_pdf` (path ผิดรูปแบบต้องถูกปฏิเสธ) · งานที่ไม่มี PDF ยังเดินได้ · ข้อมูลที่หน้าใบปะงานใช้ (`job-label`) อ่านได้ทุกบทบาท
9. ตรวจค่าคงที่หลังทุกขั้น (แบบ `invariant` ใน `flow-r8.mjs`): งาน `doing` ต่อ pool ไม่เกินจำนวนเครื่อง · จักรไม่ถูกจ่ายซ้ำ 2 งาน · `events` ไม่ถูกแก้

### B. หน้าเว็บ (Vitest `flow-r9.test.ts` + เบราว์เซอร์กับ API จำลอง `tools/qa-r9/`)
1. **เมนูตามบทบาท** ทั้ง 7 บทบาท (`roleMenu`) ตรงกับ `docs/แบบเมนูตามบทบาท.md` · ทุกเมนูเปิดได้ · หน้าที่ไม่มีสิทธิ์ขึ้นข้อความ
2. **หน้าสถานี:** แถบสถานี 1–7 · หัวสถานี "สถานีที่ n จาก 7" · ป้าย "เครื่อง x/y" ตรงกับ `station_full` · ปุ่มเริ่มเปลี่ยนเป็นเหตุผลเมื่อเครื่องเต็ม · รีดไม่เต็มเพราะงานรีดฟิล์ม
3. **เย็บ:** กด "เริ่มเย็บ" → ผังจักร เลือกตัวว่างไว้ตามสูตร · กดเปลี่ยน → ปุ่ม "เริ่มเย็บด้วย …" ส่ง `p_codes` ถูก · เลือกไม่ครบ ปุ่มบอกว่าขาดอะไร · "จัดการจักร" กดตัวว่าง = `assign_machines` · กดของงานนี้ = `release_machines`
4. **ใบปะงาน** (`#/label?id=`): ขึ้นข้อมูลงาน + QR ที่ลิงก์ไป `https://pp142.pages.dev/#/board?job=<id>` (ฝังโดเมนเว็บจริงไว้ใน `LabelPage.tsx`) · พิมพ์ A5 (print CSS) ไม่ล้นหน้า · สแกน/เปิดลิงก์ QR แล้วเปิดรายละเอียดงานถูกงาน
5. ทุกหน้าที่เกี่ยวข้อง 375 / 768 / 1440 px ไม่ล้น · console ไม่มี error · ภาพหลักฐาน `docs/qa/img/r9-cx-*.png`
