### ระดับ 1 (Critical)
- **ไม่พบเพิ่มจากฝั่ง UI ในการทดสอบส่วน A–C** *(หมายเหตุ: Codex C17 พบบั๊ก R16-01 ระดับ 1 กรณีเปิดใบเก่ารุ่นก่อน PR 175 ของกางเกงช้าง/มวยไทยแล้วค่าขนาดไม่แสดงในฟอร์มและ PDF)*

### ระดับ 2 (Major)
- **ไม่พบ**

### ระดับ 3 (Minor / UX / คู่มือ)
1. **[R16-AG-01] แอดมินกด `"เปลี่ยนเป็น PDF ใบใหม่"` แล้วไม่มีแถบแจ้งผลสีเขียว**
   - **ที่ไหน:** `app/src/pages/JobActions.tsx` (`AttachPdf` เมื่อ `replace = true`)
   - **อาการ:** หลังเลือกไฟล์และกด `"เปลี่ยนเป็น PDF ใบใหม่"` สำเร็จ ปุ่มรีเซ็ตกลับเป็น `"เปลี่ยนเป็น PDF ใบใหม่ (เลือกไฟล์ก่อน)"` โดยไม่มีข้อความสีเขียวแจ้งว่าเปลี่ยนสำเร็จแล้ว (ต่างจากปุ่มอื่นในลิ้นชักงาน) แอดมินอาจสับสนว่าบันทึกแล้วหรือยังจนต้องเลื่อนไปดูประวัติงาน
2. **[R16-AG-02] พื้นที่ติ๊ก `"มาตรฐาน"` ในตารางกระเป๋าบนมือถือ 375 px สูงเพียง 20 px**
   - **ที่ไหน:** `production-confirmation.html` (`.std` ในตาราง `itemTable`)
   - **อาการ:** บนมือถือ `375 px` พื้นที่คลิก `label.std` วัดได้ `73 × 20 px` กดยากกว่าเกณฑ์หน้างาน 48 px
3. **[R16-AG-03] ถ้าแอดมินแก้สเปกการผลิตตอนใช้ `"ลูกค้าขอแก้ใบยืนยัน"` ฝ่ายผลิตจะไม่เห็นอัตโนมัติ**
   - **จุดที่ต้องย้ำทีม:** ข้อความใต้ปุ่มแจ้งชัดว่า *"สเปกงานในระบบไม่เปลี่ยนตาม · ถ้าแก้สเปกการผลิต ต้องแจ้งฝ่ายผลิตด้วย"* แต่ในทางปฏิบัติแอดมินควรเปลี่ยน PDF ใบใหม่ **และ** อัปเดตฉบับแก้ไขในหน้าม็อคอัพกำกับสเปกด้วย เพื่อให้ฝ่ายผลิต/QC กดรับทราบสเปกใหม่
