# ส่งออกทั้งงานจากสถานีรีดฟิล์ม (28 พ.ย. · เจ้าของขอ)

เจ้าของ (ภาพลิ้นชักงาน SC691512 เสื้อคนงาน 60 ตัว คิว 1 ที่รีดฟิล์ม): "ต้องการให้งานที่อยู่สถานีรีด DTF ที่ยังไม่ได้รันงาน ต้องส่งออกไปนอก ได้ทั้งหมด ไม่ใช่ได้แค่แบ่ง"

## สาเหตุ
`dtf_press` ไม่อยู่ในรายชื่อสถานีที่ส่งออกได้ ทั้งฐาน (`private.outsourceable` · `20261121000000_outside_route`) และหน้าเว็บ (`OUTSOURCEABLE` ใน `app/src/proto/model.ts`) → แผงส่งออกซ่อนปุ่ม "ส่งออกบริษัทภายนอก" เหลือแค่ "แบ่งจำนวน" · ถ้าแบ่งแล้วส่งงานที่แบ่ง ก็ส่งไม่ได้อยู่ดี (ฐานปฏิเสธ "ทำที่โรงงานเท่านั้น")

## เปลี่ยนอะไร
- migration `20261215000000_outsource_dtf_press.sql`: `private.outsourceable` เพิ่ม `dtf_press` · ข้อความ error ใน `private.out_span` / `public.add_vendor` เพิ่ม "รีดฟิล์ม" ในรายชื่อสถานีที่ส่งได้ (คัดลอกจาก `20261120020000_outsourcing.sql` ไฟล์เดียวที่นิยาม)
- `OUTSOURCEABLE` เพิ่ม `dtf_press` (ตรงกับฐาน) → ปุ่มส่งออกทั้งงานขึ้นเมื่องานรอเริ่มที่รีดฟิล์ม · ขั้นรอผลิตของเส้นทาง DTF อย่างเดียว (สถานีแรก = รีดฟิล์ม) ก็ส่งออกได้
- กฎเดิมไม่เปลี่ยน: ส่งได้เฉพาะงานที่ยังไม่เริ่มสถานี (`station_status = 'queued'`) · เริ่ม/พักแล้วถูกปฏิเสธ "ส่งออกได้เฉพาะงานที่ยังไม่เริ่มสถานีนี้ (ตอนนี้: กำลังทำ / พักงาน)" · ส่งได้หลายสถานีติดกัน (ตัด → รีดฟิล์ม → เย็บ) · QC + Packing ยังส่งไม่ได้

## ทดสอบ
- ฐาน 2130 ผ่าน (ใหม่ `supabase/tests/outsource-dtf-press.mjs`: ส่งทั้งงาน 60 ตัว · ฝ่ายผลิตส่งไม่ได้ · รับกลับไปรอเย็บ · รีดฟิล์ม→เย็บ · ตัด→รีดฟิล์ม · เริ่มแล้วถูกปฏิเสธ · เลยไป QC ถูกปฏิเสธ · บริษัทรับรีดฟิล์มได้ / รับ QC ไม่ได้) + golive 106
- ปรับเทสต์เดิมที่ล็อกพฤติกรรมเก่า: `outsource-waiting.mjs` (DTF อย่างเดียวจากรอผลิต ส่งได้แล้ว) · `flow-r5.mjs` (สถานะ J รอเริ่มที่รีดฟิล์ม ส่งออกได้) · `outsourcing.mjs` (ข้อความใหม่)
- app vitest 649 + node 220 · lint · build
- qa-r14 (loopback): แอดมินเปิดลิ้นชักงาน DTF ที่รีดฟิล์ม → ปุ่ม "ส่งออกบริษัทภายนอก" ขึ้น → ส่ง 60 ตัว → อยู่ที่บริษัทภายนอก → รับเข้า → ไปรอที่เย็บ · งานที่เริ่มรีดฟิล์มแล้วไม่มีปุ่ม และเรียก `send_out` ตรงถูกปฏิเสธข้อความไทย · 375 px ไม่ล้น · console มีแค่ Realtime WebSocket (ระบบจำลองไม่มี)
