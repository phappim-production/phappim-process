## Flow การทำงานจริงในโรงงาน (เจ้าของอธิบาย 17 พ.ย. · ระบบทำตามนี้แล้ว)
1. แอดมินดีลงานกับลูกค้า → ทำใบยืนยันการผลิต (`production-confirmation.html`) → ลูกค้าเซ็น · **แอดมินเตรียมวัตถุดิบให้ครบก่อนส่งใบยืนยัน** (ยกเว้นฟิล์ม DTF / DTG / สกรีนที่นำเข้าภายหลัง)
2. **แอดมินกด "รับงานใหม่"** (แนบ PDF ที่เซ็น + ไฟล์ `.json`) → **งานไปสถานีแรกทันที** (หรือขึ้นตัวอย่างถ้างานนั้นต้องขึ้น) · ไม่มีขั้นรอวัตถุดิบ
3. ฝ่ายผลิตเดินตามเส้นทาง เช่น งานปกติ: พิมพ์ → รีด → ตัด → เย็บ → QC + Packing → พร้อมส่ง · **แต่ละสถานีมีแค่ "เริ่ม" → "เสร็จ"** + "พักงาน / ติดปัญหา" · ไม่มีเช็คลิสต์ขั้นย่อย
4. เงื่อนไขที่ระบบยังบังคับ: รีดฟิล์มเริ่มได้เมื่อแอดมินบันทึก "ได้รับฟิล์ม" (บันทึกสั่ง/รับได้ทุกช่วงของงาน) · QC + Packing (ผลิตจริง) กรอกผ่าน/ไม่ผ่าน ต้องผ่านครบจำนวนก่อนกดเสร็จ · ชิ้นไม่ผ่านส่งกลับแก้ · เกินเวลามาตรฐานต้องรายงานก่อนกดเสร็จ

## วิธีรีวิวงานที่ส่งมา (ทำทุกครั้ง)
1. `git diff --stat` มีแต่ไฟล์ในใบสั่งงาน · ไม่มีไฟล์แปลกปลอม
2. รันทดสอบเองบนโฟลเดอร์รีวิวที่ต่อจาก `main` ล่าสุด (`git worktree add --detach ../pp142-review-xx origin/main` แล้ว merge branch งาน) · `supabase/tests`: `npm test` · `app`: `npm run lint && npm test && npm run build`
3. อ่านทุกไฟล์ที่เปลี่ยน · migration: RLS · grant/revoke (`anon` ห้าม) · กฎบังคับใน SQL · error ไทย · ชื่อไฟล์หลังไฟล์ล่าสุด · หน้าเว็บ: ส่วนประกอบกลาง · ไม่มี hex / `any` / ปิด lint · ไม่มีข้อความอังกฤษ
4. ลองหน้าจริง: ตั้ง config ชั่วคราวใน `.claude/launch.json` (dev server พอร์ต **5176** · แผงเบราว์เซอร์ล็อกอินไว้ที่ origin นี้) · 375 / 768 / 1440 px · คืนไฟล์ด้วย `git checkout -- .claude/launch.json` เมื่อเสร็จ · **แผงเบราว์เซอร์อาจล็อกอินด้วยบัญชีเจ้าของจริง ห้ามกดปุ่มที่บันทึกข้อมูล**
5. ลงฐานข้อมูลจริง: `apply_migration` → แก้แถวประวัติ `update supabase_migrations.schema_migrations set version = '<ชื่อไฟล์>' where name = '<ชื่อ>'` → เทียบ `md5(replace(prosrc, chr(13), ''))` กับเนื้อ `$$…$$` ในไฟล์ (สคริปต์ Python อ่านไฟล์ · อย่าเขียน regex ใน `python -c` ใน bash เพราะ `$` ถูกแปลง)
6. **ลง DB ก่อน merge** เสมอเมื่อหน้าเว็บใหม่พึ่งกฎ/ฟังก์ชันใหม่ (Cloudflare deploy ทันทีที่ merge) · merge ด้วย `gh pr merge <n> --merge` หลัง CI ผ่าน
