## Flow จริงในโรงงาน (ระบบทำตามนี้แล้ว)
1. แอดมินกรอก `/confirmation` → **บันทึกเข้าระบบ** (เปิดแท็บระบบ · ไม่เปิดให้กดลิงก์ "กดเปิดหน้าระบบ") → **รับงานใหม่** (PDF ลูกค้าเซ็นแนบทีหลังได้) → งานต่อท้ายคิว
2. ทุกหน้าเรียง**ตามคิว** ไม่ใช่กำหนดส่ง · งานด่วน = แทรกคิว (ฝ่ายผลิต / ผู้บริหาร / เจ้าของ · ต้องมีเหตุผล) · เริ่มงานที่ไม่ใช่คิวแรกได้แต่ต้องมีเหตุผล
3. คนหน้างานใช้มือถือส่วนตัว: เปิดแอปเจอ **บอร์ด** → แถบสถานี 1–7 กดสถานี (เครื่องจำไว้) → หน้าคิวสถานี (เริ่ม → เสร็จ · พักงาน) · เมนูแต่ละบทบาทต่างกัน (`auth/menus.ts`)
   - **เครื่องต่อสถานี:** เครื่องเต็มเริ่มงานใหม่ไม่ได้ · งานติดปัญหา "ยกลง" (พักงาน) แล้วเครื่องว่าง รันงานอื่นได้ · แก้แล้วตอนเครื่องเต็ม = กลับเข้าคิว
   - **เย็บ:** แท็บจักรเย็บ → รอเย็บ กด **เริ่มเย็บ** → กดเลือกจักรตัวที่นั่งจริงตามรหัส (ระบบเลือกตัวว่างไว้ให้) → "เริ่มเย็บด้วย …" · ระหว่างเย็บ "จัดการจักร" กดจักรว่าง = เพิ่ม · กดของงานนี้ = คืน · จักรใช้ร่วม (โพ้ง ลา กระดุม รังดุม) ไม่ต้องเลือก · จักรเสียแล้วพักงานเฉพาะเมื่อเหลือไม่ครบชุด
4. **พักงาน:** ใครก็แจ้งได้ · **"แก้แล้ว ทำต่อ" เฉพาะฝ่ายผลิต / ผู้บริหาร** (งานเย็บ = ฝ่ายผลิต "เย็บต่อ") · แอดมินเห็นป้าย "ติดปัญหา · รอผู้บริหารแก้"
5. **เวลาผลิตทั้งงาน (PR 215):** 10 / 15 / 20 วันทำงานตามจำนวน นับตั้งแต่วันรับงาน · การ์ดส้ม (80%) / แดง (เลยวัน) อัปเดตเองทุก 5 นาที · เลยวันแล้วต้องรายงานสาเหตุ 1 ครั้งก่อน QC + Packing กดเสร็จ (สถานีอื่นไม่บล็อก) · พักงานเวลาก็ยังนับ

3. **migration:** ชื่อหลัง `20261210000000` · `supabase/tests/sweep-leftovers.mjs` ลง `20261204000000` + `20261205000000` ซ้ำตอนเริ่ม (ชุดเก่ากว่ารันไฟล์เก่าทับ) · ฟังก์ชันที่ล็อกแถวงานหลายแถว + คิว ต้องล็อกคิว (`pp142.job_queue`) ก่อนแถวเสมอ · `supabase/tests/sweep-fixes.mjs` รัน `20261128000000` ซ้ำแล้วทับฟังก์ชันรุ่นหลังในฐานทดสอบ → ชุดทดสอบใหม่ที่ทดสอบฟังก์ชันเหล่านั้นต้องลงไฟล์ของตัวเองซ้ำก่อน (แบบ `bug-sweep.mjs`) · **ห้ามใช้ errcode `40001` / `40P01`** (PostgREST ลองซ้ำไม่หยุด) · `start_sewing` ตอนนี้คือ `(uuid, text[])` · ห้ามแก้ไฟล์เดิม · ฟังก์ชันที่ `create or replace` คัดลอกจากไฟล์ล่าสุดที่นิยามมัน · เพิ่มพารามิเตอร์ = `drop function` แล้วสร้างใหม่ + ให้สิทธิ์ `authenticated` ใหม่ · มีทดสอบทั้งผ่านและปฏิเสธ
4. **ลงฐานข้อมูลจริง:** **ต้องให้เจ้าของสั่ง "ลงฐานจริง" ในข้อความล่าสุดทุกครั้ง** (ไม่สั่ง = ระบบสิทธิ์บล็อก) · ลอง `apply_migration` ก่อน (ใช้ได้กับ `130000`–`170000` และ `200000` · `180000` `190000` `210000` ถูกปฏิเสธที่หน้าต่างอนุญาต เจ้าของรันเองใน SQL Editor · ได้ version เป็นเวลาตอนรัน ต้อง `update supabase_migrations.schema_migrations set version = '<ชื่อไฟล์>'` แล้วตรวจเนื้อฟังก์ชัน) · ถ้าถูกปฏิเสธ → เจ้าของรันไฟล์ทั้งไฟล์ใน Supabase → SQL Editor ("ลงเองใน Supabase") → Claude ตรวจ `md5(replace(prosrc, chr(13), ''))` เทียบเนื้อ `$$…$$` ในไฟล์ (สคริปต์ Python ใน scratchpad · bash heredoc ยาวมักพัง) → `insert into supabase_migrations.schema_migrations (version, name) …` → อัปเดต memory prod-migration-state → แล้วค่อย merge (**ลงก่อน merge เสมอ** · Cloudflare deploy ทันทีที่ merge)
5. **ปรับค่าในฐานข้อมูลจริงชั่วคราว** (เช่น ย่อเวลามาตรฐานให้ AI ทดสอบ): จดค่าเดิมก่อน · เขียน memory เตือนคืนค่า · คืนทันทีที่ตรวจเสร็จ · ลบ memory
6. **ลองหน้าจอ (ในเครื่องเท่านั้น · ห้ามสร้าง/แก้ข้อมูลบนระบบจริง):** ฟอร์มใบยืนยันลองที่ dev server · หน้าระบบลองกับ **`tools/qa-r14` (หลัก · ดูแถว "ระบบจำลองในเครื่อง")** หรือตัวจำลองเก่า `tools/r2-local` (build ด้วย `VITE_SUPABASE_URL=http://127.0.0.1:5199` · ล้าง service worker ก่อนดูรุ่นใหม่) · (ฟอร์ม `/confirmation.html` ไม่ต้องล็อกอิน · ใส่ภาพ/จุดผ่าน `state` ใน javascript ได้) · `.claude/launch.json` ชั่วคราวพอร์ต **5176** (`npm --prefix app run dev -- --port 5176 --strictPort`) → `preview_start` → คืนด้วย `git checkout -- .claude/launch.json` · แผงเบราว์เซอร์ล็อกอิน**บัญชีเจ้าของจริง** = ดูอย่างเดียว ห้ามกดบันทึก · หลุดล็อกอินให้เจ้าของล็อกอินให้ · ฟอร์มดูที่ `/confirmation.html`
7. ไฟล์ `docs/ใบมอบหมายงานฝึกงาน-ทดลองระบบผลิต.pdf` ไม่อยู่ใน git · **ห้าม `git add docs`** add ทีละไฟล์
8. ตรวจงาน AI: อ่าน diff ทุกไฟล์ + รายงาน + ไฟล์ส่งงาน · ตรวจขอบเขตไฟล์ · ยืนยันคำกล่าวอ้างกับโค้ด/ระบบจริง · merge branch ของ AI เข้า branch แก้ของ Claude แล้วแก้บั๊ก (ทดสอบ `BUG:` ต้องผ่านแล้วเปลี่ยนชื่อ)

## เรื่องค้าง / ข้อจำกัดที่รู้
- ช่วงเวลามาตรฐานหลายสถานี (segment) ที่บางสถานีส่งออก ยังนับเวลาข้างนอกรวมในช่วง

- ภาพคู่มือ: 9 ภาพที่รอบ 14 บอกว่าเก่าจับใหม่แล้ว (PR 182) · ภาพอื่นที่หน้าจอเปลี่ยนภายหลังให้จับด้วย `tools/manual-shots/` · ภาพมีชื่อบัญชีจำลอง (`… จำลอง` · `@r14.invalid`)
