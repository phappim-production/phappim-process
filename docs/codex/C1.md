## ต้องทำ
1. ติดตั้ง Vitest · เพิ่มสคริปต์ `"test": "vitest run"` ใน `app/package.json` · ใน `vitest.config.ts` ตั้ง `include: ['src/**/*.test.ts']` เท่านั้น (branch ล็อกอินของ Claude มี `app/tests/*.test.mjs` แบบ `node:test` ที่ Vitest รันไม่ได้ · Claude จะย้ายมาเป็น Vitest เองหลัง C1 merge)
2. เขียนทดสอบ (ใช้วันที่ตายตัว ห้ามพึ่งเวลาปัจจุบัน):
   - `proto/capacity.test.ts`
     - `workdayToDate`: เสาร์ + 0.3 → เสาร์ · เสาร์ + 1.0 → เสาร์ · เสาร์ + 1.2 → จันทร์ (ข้ามอาทิตย์) · อาทิตย์ + 0.5 → จันทร์ · ศุกร์ + 3 → จันทร์ · ค่าติดลบ → วันนี้ (ถ้าเป็นวันทำงาน)
     - `workdaysUntil`: เสาร์ → จันทร์ = 1 · วันที่ผ่านมาแล้ว = 0
     - `lateDays` · `verdict` ทั้ง 3 ระดับ (ok / tight / full) และกรณีมีงานเสี่ยง
     - `simulate`: โรงงานว่าง (วันเสร็จงานใหม่ = เวลาเผื่อ + ผลรวมชิ้น ÷ กำลังผลิตทุกสถานี) · งานเสร็จหมด (ไม่มีผลคาดการณ์) · งานที่เสร็จแล้วไม่อยู่ในผล · งาน DTF ที่ยังไม่ได้ฟิล์มเสร็จไม่ก่อน ETA · จำนวนมาก (1,000,000) ได้ค่าจำกัด · งานผลิตที่ไม่มีสถานีไม่ทำให้พัง
   - `proto/model.test.ts`: `isOverdue` (ครบกำหนดวันนี้ = ยังไม่เลย · เมื่อวาน = เลย · ข้ามเที่ยงคืน) · `isDueSoon` · `isWaitingFilm` · `isFilmLate` · `isDoneToday` · `missingDepts` · `columnOf` ทุก phase
   - `proto/format.test.ts`: `duration` (59 นาที · 2 ชม. · 25 ชม. = "1 วัน 1 ชม.") · `stageSteps` จำนวนขั้นตามเส้นทาง (ปกติ 8 · DTF 7 · ไม่พิมพ์ 6) และตำแหน่งปัจจุบันทุก phase · `stageText` ทุก phase รวมงานที่ไม่มีสถานี
   - `proto/mockJobs.test.ts`: ข้อมูลจำลองทุกงานผ่านเงื่อนไขพื้นฐาน (เลขที่ไม่ซ้ำ · qty > 0 · งานผลิตมีสถานีที่อยู่ในเส้นทาง · งาน DTF มีข้อมูลฟิล์ม)
3. แก้ `.github/workflows/ci.yml` งาน `app-build` ให้รันตามลำดับ: `npm ci` → `npm run lint` → `npm test` → `npm run build`
