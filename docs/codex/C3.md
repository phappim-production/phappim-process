## หลักการออกแบบ (ห้ามเปลี่ยน)
1. **ระบบหลักต้องไม่ช้าหรือพังเพราะแจ้งเตือน:** trigger แค่เพิ่มแถว · ห้ามเรียก HTTP · trigger พังต้องไม่ทำให้การกดงานล้ม (ห่อด้วย `begin … exception when others then null end` และไม่ทิ้ง error เงียบ: เก็บข้อความลง `inbox_errors`)
2. **ไม่ซ้ำ:** ทุกข้อความมี `dedupe_key` unique · insert แบบ `on conflict do nothing`
3. **อ่านแล้ว = ของแต่ละคน:** ข้อความเดียวกันส่งถึงหลายบทบาท แต่ละคนกดอ่านแยกกัน
4. **ไม่ต้องมีงานตั้งเวลา:** การตรวจตามรอบ (`inbox_scan`) เรียกจากหน้าเว็บของใครก็ได้ที่ล็อกอินอยู่ (ทุก 5 นาที) · ใช้ `dedupe_key` กันซ้ำจึงเรียกพร้อมกันหลายเครื่องได้ · ถ้ามี `pg_cron` ให้ตั้งรอบเพิ่ม **ห่อด้วยเงื่อนไขว่ามี extension** (PGlite ไม่มี)

## ต้องทำ
### ก. ฐานข้อมูล
- `inbox_messages(id bigserial pk, kind text not null, job_id uuid null references jobs on delete cascade, dedupe_key text unique not null, title text not null, body text not null, audience text[] not null, created_at timestamptz default now())`
- `inbox_reads(message_id bigint references inbox_messages on delete cascade, user_id uuid references auth.users, read_at timestamptz default now(), primary key (message_id, user_id))`
- `inbox_errors(id, at, source text, message text)` · อ่านได้เฉพาะ owner
- `inbox_settings(kind text pk, enabled boolean default true)` · owner แก้ได้ (หน้าตั้งค่า C2 จะเพิ่มแท็บทีหลัง)
- **RLS:** เห็นข้อความเมื่อ `private.my_role() = any(audience)` หรือเป็น owner · `inbox_reads` เห็นของตัวเองเท่านั้น · **ไม่มี policy เขียน** (เขียนผ่านฟังก์ชันเท่านั้น)
- **เกิดทันที** (trigger `after insert` บน `events` และ `machine_status_log`):

  | kind | เมื่อ | ถึงใคร (audience) | dedupe_key |
  |---|---|---|---|
  | `hold` | event `hold` | production · admin · manager | `hold:{payload.issue_id}` |
  | `delay_report` | event `delay_report` | production · admin · manager | `delay:{payload.report_id}` |
  | `rework` | event `rework` | production · qc · admin | `rework:{event id}` |
  | `sewing_issue` | event `sewing_issue_reported` | production | `sewissue:{event id}` |
  | `machine_broken` | `machine_status_log` status `broken` (ไม่นับแถวเลื่อนเวลาซ่อม) | production | `machine:{log id}` |
  | `sample_failed` | event `sample_result` ที่ `payload.pass = false` | production · admin | `sample:{event id}` |

- **ตรวจตามรอบ** `public.inbox_scan()` (security definer · ทุกบทบาทที่ล็อกอินเรียกได้ · คืนจำนวนข้อความใหม่):

  | kind | เงื่อนไข | ถึงใคร | dedupe_key |
  |---|---|---|---|
  | `sla_over` | `private.sla_state(job)` มี `station_over` หรือ `segment_over` และยังไม่รายงาน | production · admin · manager | `sla:{job}:{visit}` |
  | `film_late` | DTF ยังไม่ได้รับฟิล์ม และเลย `dtf_film_eta` (วันที่ไทย) | admin · production | `film:{job}:{วันที่ไทย}` |
  | `materials_late` | อยู่ขั้นวัตถุดิบเกิน 2 วันทำงาน (`private.work_days`) | ฝ่ายที่ยังไม่ติ๊ก (admin/qc/production) | `mat:{job}:{วันที่ไทย}` |
  | `due_soon` | ยังไม่เสร็จ และกำหนดส่งคือวันนี้หรือพรุ่งนี้ (วันที่ไทย) | production · admin · manager | `due:{job}:{วันที่ไทย}` |

  owner เห็นทุกข้อความอยู่แล้วจาก RLS ไม่ต้องใส่ใน audience · kind ที่ปิดใน `inbox_settings` ไม่สร้างแถว
- **ฟังก์ชันสำหรับหน้าเว็บ:** `public.inbox_mark_read(p_ids bigint[])` (เฉพาะข้อความที่ตัวเองเห็นได้ · กดซ้ำไม่ error) · `public.inbox_mark_all_read()` · `public.inbox_unread_count()` · grant เฉพาะ `authenticated` · revoke จาก `public, anon`
- เพิ่ม `inbox_messages`, `inbox_reads` เข้า Realtime publication (ห่อด้วยเงื่อนไขว่ามี publication เหมือน migration อื่น)
- **ข้อความภาษาไทยสั้น** · `title` บอกเรื่อง + เลขที่ใบ · `body` บอกลูกค้า สินค้า จำนวน และสิ่งที่ต้องทำ เช่น
  - title `งานติดปัญหา SC691521` · body `มูลนิธิรักษ์ป่า · ถุงผ้า 1,000 ใบ · สถานีเย็บงาน · สาเหตุ: จักรเสีย รอช่างซ่อม`
  - title `เกินเวลามาตรฐาน SC691513` · body `ช่วงพิมพ์ + รีด + ตัด ใช้ไป 3.4 จาก 3 วันทำงาน · ต้องส่งรายงานปัญหาก่อนกดเสร็จ`

### ข. หน้ากล่องจดหมาย (`app/src/pages/inbox/index.tsx` · `export default function InboxPage()`)
- รายการใหม่สุดก่อน · ยังไม่อ่าน = ตัวหนา + จุดสี · สีตามความหมาย (`TONE`): แดง = `hold` `sla_over` `film_late` `rework` `machine_broken` `sample_failed` · ส้ม = `due_soon` `materials_late` `delay_report` `sewing_issue`
- ตัวกรอง: ยังไม่อ่าน / ทั้งหมด · ปุ่ม "อ่านแล้วทั้งหมด"
- กดข้อความ = ทำเครื่องหมายอ่านแล้ว + เปิดงาน `#/board?job=<job_id>` (Claude ทำลิงก์นี้ใน S8)
- อัปเดตสดด้วย Realtime (`inbox_messages`, `inbox_reads`) · เรียก `inbox_scan()` ตอนเปิดหน้าและทุก 5 นาที
- สถานะ กำลังโหลด / ไม่มีข้อความ / ผิดพลาด · ข้อความผิดพลาดใช้ `rpc()` จาก `app/src/data/useFactoryData.ts` (แปลไทยให้แล้ว)
- 375 / 768 / 1440 px ไม่ล้น · ปุ่มสูง ≥ 48 px · ตัวอักษร ≥ 16 px
- `app/src/pages/inbox/InboxBell.tsx` · `export function InboxBell()` ไอคอนกระดิ่ง + ตัวเลขยังไม่อ่าน (ซ่อนเมื่อ 0 · เกิน 99 แสดง 99+) · ลิงก์ไป `#/inbox` · ใช้ข้อมูลเดียวกับหน้ากล่องจดหมาย (แยกเป็น hook `useInbox()` ใน `app/src/pages/inbox/useInbox.ts`)
- ส่วนคำนวณ (สี · ข้อความเวลา "5 นาทีก่อน" · จัดกลุ่มวันนี้/เมื่อวาน/ก่อนหน้า) เป็น pure function ใน `app/src/pages/inbox/format.ts` มีทดสอบ

### ค. ทดสอบ
1. **ฐานข้อมูล `inbox.mjs`** (ทั้งกรณีผ่านและถูกปฏิเสธ):
   - พักงาน 1 ครั้ง → 1 ข้อความ `hold` · trigger ซ้ำด้วย issue เดิม → ยัง 1
   - `inbox_scan()` 2 ครั้งติดกัน → ไม่ซ้ำ · งานที่ไม่เข้าเงื่อนไข → ไม่มีข้อความ
   - ปิด kind ใน `inbox_settings` → ไม่สร้าง
   - QC เห็นข้อความ `rework` แต่ไม่เห็น `machine_broken` · ผู้บริหารเห็น `hold` · owner เห็นทุกข้อความ
   - ผู้ใช้ไม่มีบทบาท / คนไม่ล็อกอิน เห็น 0 ข้อความ และเรียกฟังก์ชันไม่ได้
   - `inbox_mark_read` ของคนหนึ่งไม่ทำให้อีกคนเห็นว่าอ่านแล้ว · ทำเครื่องหมายข้อความที่ตัวเองมองไม่เห็นไม่ได้
   - insert / update / delete ตาราง inbox ตรงไม่ได้ทุกบทบาท
   - **ชุดทดสอบเดิมทุกข้อยังผ่าน** (ตอนนี้ 383 ข้อ)
2. **หน้าเว็บ** `app/tests/inbox.test.mjs` สำหรับ `format.ts`
3. ลองจริงที่ http://localhost:5174 ด้วยบัญชีทดสอบ `production@` และ `qc@` (ห้ามบัญชีเจ้าของระบบ) · งานทดสอบใช้เลขขึ้นต้น `TEST-` · migration ยังไม่ได้ลงฐานข้อมูลจริง จึงลองหน้าเว็บได้หลัง Claude ลงให้ (แจ้งในไฟล์ส่งงานว่าพร้อมให้ลง)
