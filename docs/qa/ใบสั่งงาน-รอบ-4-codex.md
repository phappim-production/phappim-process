## ตรวจอะไร (เขียนทดสอบให้ได้ผลจริง ไม่เดา)
1. **แทรกคิวซ้ำๆ:** แทรกระหว่างสองงานเดิม 60 ครั้ง (numeric หารครึ่งเรื่อยๆ) · ลำดับยังถูก · ไม่มีเลขซ้ำ
2. **แทรกพร้อมกัน:** 2 งานแทรกก่อนงานเดียวกันพร้อมกัน (หรือติดกัน) → เลขชนกันได้ไหม · ถ้าเท่ากัน `byQueue` ตัดสินด้วยอะไร · หน้าเว็บกับฐานข้อมูล (`note_queue_skip` ใช้ `queue_seq <`) เห็นลำดับตรงกันไหม
3. **`note_queue_skip` กับสถานีเดียวกันต่างเส้นทาง / ตัวอย่างปนผลิตจริง / งานพัก / งานแก้ (rework)** ตรงกับ `waitingAt` ในหน้าเว็บทุกกรณีไหม
4. **สิทธิ์:** ทุกบทบาท (owner · admin · production · qc · manager · supervisor · ไม่ได้ล็อกอิน · บัญชีปิดใช้) เรียก `move_job_ahead` / `note_queue_skip` · แก้ `queue_seq` ตรง · ใช้ sequence `job_queue_seq` ตรง
5. **งานใหม่ต่อท้ายคิวเสมอ** แม้ก่อนหน้ามีการแทรกเป็นคิวแรก (เลขติดลบ / ทศนิยม) · งานที่ส่งกลับแก้ (rework) และตัวอย่างไม่ผ่านขึ้นรอบใหม่ คงเลขคิวเดิม — ตรงกับที่ควรเป็นไหม (เขียนความเห็นในรายงาน)
6. **`simulate`:** เรียงตามคิวแล้วผลวันเสร็จของงานที่แทรกเป็นคิวแรกเร็วขึ้นจริง · งานใหม่ (`extra`) อยู่ท้ายคิว · เวลาคำนวณ 300 งานยังไม่เกิน 0.3 วิ (เทียบ PR 49)
7. **หน้าเว็บ (อ่านโค้ด + ทดสอบฟังก์ชัน):** `StationQueue` ส่งคำสั่งถูกฟังก์ชันทุกสถานี (เย็บใช้ `start_sewing` / `finish_sewing` / `resume_sewing`) · กด "บันทึกและเริ่ม" แล้ว `note_queue_skip` ผ่านแต่เริ่มไม่ผ่าน → ผลคืออะไร (บันทึกเหตุผลค้างโดยงานไม่เริ่ม?) · ลิงก์ `#/board?station=xxx` ที่ไม่มีจริง
8. **อื่นๆ ที่เห็นใน diff** (ข้อความไทย · สถานะโหลด/ผิดพลาด · 375 px)
