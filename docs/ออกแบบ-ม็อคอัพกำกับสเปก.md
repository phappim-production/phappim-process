## 2. ปรับโจทย์ให้เข้ากับระบบเรา

1. **"สเปกการผลิต" มี 2 แหล่ง ไม่เก็บซ้ำ**
   - **อ้างช่องในใบยืนยัน** (`jobs.spec`) เช่น Callout "อกซ้าย" → `placements.หน้าอกซ้าย` ดึงเทคนิค/ขนาด/หมายเหตุมาแสดงเอง · แก้ที่ใบยืนยันที่เดียว
   - **สเปกเพิ่มเติม** (ตารางใหม่ `mockup_specs`) สำหรับสิ่งที่ใบยืนยันไม่มี เช่น "ขอบคอกว้าง 2 ซม." "Pantone 7727 C" · ใช้ซ้ำหลาย Callout ได้
2. **ไม่มี API endpoint** → ทุกการเขียนเป็น RPC · Backend ตรวจสิทธิ์ใน RPC + RLS ทุกครั้ง
3. **ไฟล์ต้นฉบับ**: ไม่ย่อ ไม่แปลง · จำกัด 5 MB ตาม bucket เดิม (ใหญ่กว่านี้บอกให้ย่อก่อน · ถ้าต้องการ 10 MB ต้องแก้ bucket = ถามก่อน)
4. **PDF** = หน้า "ใบกำกับงานพิมพ์ (Artwork Sheet)" ที่สั่งพิมพ์ A4/A3 ได้ · Callout ใช้พิกัดชุดเดียวกับตัวแก้ไข (SVG viewBox 0–1) ตำแหน่งจึงตรงกัน
5. **ชื่อบนจอเป็นภาษาไทย**: ร่าง · รออนุมัติ · อนุมัติแล้ว · ถูกแทนที่ (ในฐานข้อมูลเก็บ `draft / pending / approved / superseded`)
6. **ฉบับ (Revision) ของม็อคอัพแยกจาก `confirmation_rev`** แต่บันทึกว่าทำจากใบยืนยันฉบับไหน · ถ้าใบยืนยันถูกแก้ทีหลัง หน้าจอเตือน "ใบยืนยันเปลี่ยนหลังอนุมัติม็อคอัพ"

## 3. ฐานข้อมูล (migration ใหม่ 1 ไฟล์ · ชื่อหลัง `20261120180000`)

```
mockup_sheets      ชุดม็อคอัพ 1 ฉบับ
  id uuid · job_id → jobs · rev int (1,2,3…) · status draft|pending|approved|superseded
  version int (กันบันทึกทับ) · based_on uuid (ฉบับก่อนหน้า) · confirmation_rev int
  change_reason text · created_by/at · updated_by/at · submitted_by/at · approved_by/at
  snapshot jsonb (เติมตอนอนุมัติ · ห้ามแก้) 
  unique (job_id, rev) · ร่างได้ทีละ 1 ฉบับต่องาน · อนุมัติใช้งานได้ทีละ 1 ฉบับต่องาน (partial unique)

mockup_views       ภาพแต่ละมุม
  sheet_id · view text (front|back|left|right|detail) · label · image_path · width · height · sort

mockup_specs       สเปกเพิ่มเติม (ระดับงาน ใช้ซ้ำข้ามฉบับ)
  id · job_id · code (S-01…) · name · kind (พิมพ์/ปัก/เย็บ/วัสดุ/อื่นๆ) · position
  detail · width · height · unit (ซม./มม./นิ้ว) · color · color_code · material · method
  artwork_path (ไฟล์ใน Storage) · artwork_ref (ที่อยู่บน NAS) · note · stations text[]

mockup_callouts    จุดกำกับบนภาพ
  sheet_id · view_id · no (เลขอัตโนมัติ) · sort
  x, y (จุดบนภาพ 0–1) · box_x, box_y (กล่องข้อความ 0–1) · title
  spec_ref text (ช่องในใบยืนยัน เช่น placements.หน้าอกซ้าย)  หรือ  spec_id → mockup_specs
  text (ข้อความเพิ่ม) · stations text[] (ว่าง = ทุกสถานี)

mockup_acks        รับทราบสเปก (ห้ามแก้/ลบ)
  sheet_id · rev · user_id · station_code · at
```

**ฟังก์ชัน RPC**
| ฟังก์ชัน | ทำอะไร |
|---|---|
| `start_mockup_sheet(p_job, p_reason)` | สร้างฉบับร่าง (ถ้ามีฉบับอนุมัติแล้ว = คัดลอกเป็น rev ถัดไป · ต้องมีเหตุผล) |
| `save_mockup_draft(p_sheet, p_version, p_payload)` | บันทึกภาพ/Callout/สเปกทั้งชุดในครั้งเดียว · `p_version` ไม่ตรง = ปฏิเสธ "มีคนบันทึกฉบับใหม่กว่าแล้ว กดโหลดใหม่ก่อน" |
| `submit_mockup_sheet(p_sheet, p_version)` | ร่าง → รออนุมัติ (ตรวจ: มีภาพหน้า ≥ 1 · ทุก Callout มีสเปกหรือข้อความ) |
| `approve_mockup_sheet(p_sheet, p_note, p_version)` | **แอดมิน: ร่าง → อนุมัติแล้วได้เลย** (ส่ง `p_version` · ตรวจเหมือนส่งอนุมัติ · เจ้าของเปลี่ยน 20 พ.ย.) · ฉบับรออนุมัติ: แอดมิน/ฝ่ายผลิต/ผู้บริหาร → อนุมัติแล้ว · สร้าง `snapshot` (ภาพ + Callout + สเปก + ค่าใบยืนยันที่อ้าง ณ ตอนนั้น) · ฉบับเดิม → ถูกแทนที่ · 1 แถวใน `events` · ถ้างานเริ่มผลิตแล้ว ส่งกล่องจดหมายถึงสถานีที่เกี่ยวข้อง |
| `return_mockup_sheet(p_sheet, p_reason)` | รออนุมัติ → ร่าง (ส่งกลับแก้ พร้อมเหตุผล) |
| `ack_mockup_sheet(p_sheet, p_station)` | รับทราบสเปก (บันทึก ผู้ใช้ · สถานี · ฉบับ · เวลา) |

**กฎใน SQL (ทดสอบทั้งผ่านและถูกปฏิเสธ)**
- ฉบับ `approved` / `superseded` แก้ไม่ได้ (trigger กัน update/delete ทั้ง sheet, views, callouts ของฉบับนั้น)
- `snapshot` เขียนได้ครั้งเดียวตอนอนุมัติ
- ฉบับที่เก่ากว่าฉบับอนุมัติล่าสุด ส่งอนุมัติไม่ได้ (กันฉบับเก่าทับฉบับใหม่)
- พิกัดต้องอยู่ใน 0–1 · `image_path` ต้องอยู่ในโฟลเดอร์ของงานนั้นและมีไฟล์จริง (ใช้ `private.mockup_folder` / `private.check_mockup` เดิม)
- staff อ่านได้เฉพาะงานที่ผ่านสถานีที่จับคู่ และเห็นเฉพาะ Callout ที่สถานีตรง (หรือไม่ระบุสถานี)
- ไม่แตะตาราง/ฟังก์ชันเดิม ยกเว้น **เพิ่ม** policy อ่านไฟล์ (ถ้าเจ้าของเลือกจำกัด · หัวข้อ 9 ข้อ 4)

## 4. ตารางสิทธิ์ที่เสนอ (รออนุมัติ)

✓ = ได้ · — = ไม่ได้ · ทุกข้อบังคับใน SQL ไม่ใช่แค่ซ่อนปุ่ม

| สิทธิ์ | เจ้าของ | ผู้บริหาร | แอดมิน (4 คนเท่ากัน) | ฝ่ายผลิต | ผู้ควบคุมงาน | QC | พนักงานสถานี |
|---|---|---|---|---|---|---|---|
| ดูม็อคอัพ + สเปก (ฉบับอนุมัติ) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | เฉพาะงาน/Callout ของสถานีที่จับคู่ |
| ดูฉบับร่าง / รออนุมัติ | ✓ | ✓ | ✓ | ✓ | ✓ | — | — |
| อัปโหลดภาพ · สร้าง/แก้ฉบับร่าง · สร้างสเปก | ✓ | — | ✓ | — | — | — | — |
| ส่งอนุมัติ | ✓ | — | ✓ | — | — | — | — |
| **อนุมัติ / ส่งกลับแก้** | ✓ | ✓ | — | ✓ | — | — | — |
| เปลี่ยนฉบับ เมื่องานเริ่มผลิตแล้ว | สร้างร่าง: แอดมิน/เจ้าของ (ต้องมีเหตุผล) · อนุมัติ: **เจ้าของ / ผู้บริหารเท่านั้น** | | | | | | |
| รับทราบสเปก | ✓ | — | — | ✓ | ✓ (เฟสที่ดูแล) | ✓ (QC) | ✓ (สถานีที่จับคู่) |
| พิมพ์ Artwork Sheet | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | — (ดูบนจอเท่านั้น) |

เหตุผล: แอดมินคือคนรับใบยืนยันและแนบรูปอยู่แล้ว (สิทธิ์ `admin` เดิม) · คนอนุมัติไม่ควรเป็นคนทำร่าง → แอดมินอนุมัติเองไม่ได้ · ฝ่ายผลิตอนุมัติได้เพราะรู้ว่าผลิตได้จริงไหม (ถ้าไม่ต้องการ ตัดออกได้)

## 5. Workflow

```
(ไม่มี) ─start─▶ ร่าง ─submit─▶ รออนุมัติ ─approve─▶ อนุมัติแล้ว ─(มีฉบับใหม่อนุมัติ)─▶ ถูกแทนที่
                  ▲                 │
                  └───return────────┘
อนุมัติแล้ว ─start (เหตุผล)─▶ ร่าง rev+1   (ฉบับเดิมยังใช้ผลิตจนกว่าฉบับใหม่จะอนุมัติ)
```
- หน้างานเห็นเฉพาะ **ฉบับอนุมัติล่าสุด** · มีฉบับใหม่รออนุมัติ = แถบส้ม "มีฉบับแก้ไขรออนุมัติ · ยังผลิตตามฉบับ n"
- อนุมัติฉบับใหม่หลังงานเริ่มผลิต → ทุกสถานีที่เกี่ยวข้องต้องกด **รับทราบ** ฉบับใหม่ (ป้ายแดงบนการ์ดจนกว่าจะรับทราบ · **ไม่หยุดงาน** เหมือนกติกา "รับทราบ" ของผู้บริหาร)
- ไม่มีม็อคอัพกำกับ = งานเดินได้ตามเดิม (โมดูลเสริม ไม่บังคับ) · ถ้าเจ้าของต้องการบังคับ ทำเป็นตัวเลือกทีหลัง

## 9. ความเสี่ยง + สิ่งที่ต้องให้เจ้าของตัดสิน

**ความเสี่ยง**
- ช่วงเปิดใช้: ถ้าสร้างก่อน 22 พ.ย. เสี่ยงกระทบวันทดลอง → **เสนอเริ่มจันทร์ 23 พ.ย.** และลงฐานจริงทีละ migration ตามขั้นตอนเดิม
- ตัวแก้ไขบนแท็บเล็ต (ลากด้วยนิ้ว + ซูม) ต้องลองบนเครื่องจริงของโรงงาน
- PDF จากเบราว์เซอร์: หน้าตาขึ้นกับเบราว์เซอร์เล็กน้อย (ใช้ Chrome ตามที่ใช้พิมพ์ใบปะงาน)
- ไฟล์ Artwork ตอนนี้อยู่บน NAS (`\\192.168.1.119\…`) เปิดจากเว็บนอกโรงงานไม่ได้ → เก็บเป็นที่อยู่อ้างอิง + แนบไฟล์ตัวอย่างขึ้น Storage ได้ถ้าต้องการ

**คำถาม**
1. อนุมัติตารางสิทธิ์หัวข้อ 4 ไหม · **ใครอนุมัติม็อคอัพ**: เจ้าของ + ผู้บริหาร + ฝ่ายผลิต (เสนอ) หรือเฉพาะเจ้าของ + ผู้บริหาร
2. แอดมินที่ทำร่าง **อนุมัติเองได้ไหม** (เสนอ: ไม่ได้)
3. ต้องบังคับว่างานต้องมีม็อคอัพอนุมัติก่อนเริ่มผลิตไหม (เสนอ: ไม่บังคับช่วงแรก)
4. ไฟล์รูปใน bucket `mockups` ตอนนี้ทุกบัญชีอ่านได้ · จะจำกัดพนักงานสถานีให้อ่านเฉพาะงานของสถานีตัวเองไหม (กระทบรูปบนการ์ดงานเดิมด้วย)
5. เริ่มสร้างหลังเปิดใช้ (จันทร์ 23 พ.ย.) ได้ไหม
