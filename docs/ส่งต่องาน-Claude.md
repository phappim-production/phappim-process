- Claude ทำเองได้ทั้งหมดตามที่เจ้าของสั่งในแชต · **ถามก่อน merge ทุกครั้ง** (เจ้าของตอบ "merge เลย")

- ลงฐานข้อมูล**ก่อน merge** เสมอ (Cloudflare deploy ทันทีที่ merge · หน้าเว็บใหม่อ่านตาราง/ฟังก์ชันใหม่ ไม่มีจะโหลดไม่ขึ้น)

## Flow จริงในโรงงาน (ระบบทำตามนี้แล้ว)
1. แอดมินกรอก `/confirmation` → บันทึกเข้าระบบ → **รับงานใหม่** (PDF ที่ลูกค้าเซ็นไม่บังคับ แนบทีหลัง) → งานต่อท้ายคิว
2. ทุกหน้าเรียง**ตามคิว** ไม่ใช่กำหนดส่ง · งานด่วน = แทรกคิว (production / manager / owner · ต้องมีเหตุผล) · เริ่มงานที่ไม่ใช่คิวแรกได้แต่ต้องมีเหตุผล
3. คนหน้างานใช้**มือถือส่วนตัว**: หน้างาน → บอร์ด → เลือกสถานี (จำไว้) → หน้าคิวสถานี
4. แอดมินส่งออกได้ทุกสถานี พิมพ์/รีด/ตัด/เย็บ/ปัก ที่งานยังไม่เริ่ม · ส่งต่อบริษัทถัดไป · รับกลับ → สถานีถัดไป (งานแก้ → QC) · ระหว่างอยู่ข้างนอก trigger กันปุ่มของโรงงาน
5. ยังบังคับเดิม: รีดฟิล์มรอได้รับฟิล์ม · QC ผ่านครบจำนวน · เกินเวลามาตรฐานต้องรายงาน · ข้ามสถานีไม่ได้

1. **รับผล QA รอบ 5** เมื่อเจ้าของบอก "ส่งงานแล้ว": อ่าน diff + `docs/qa/รอบ-5-*.md` ใน worktree · merge branch ของ AI เข้า branch แก้ของ Claude · แก้บั๊กจนทดสอบ `BUG:` ผ่าน · ทำเหมือน PR 57 / 58
2. **ระหว่าง QA รอบ 5 ข้อ 13:** เมื่อ Antigravity แจ้งว่า `TEST-R5-A` อยู่ QC + Packing → ย่อเวลามาตรฐานสถานี `qc_pack` ชั่วคราว (**จดค่าเดิมก่อน** `select sla_days from stations where code='qc_pack'`) → ตรวจเสร็จคืนค่าทันที
3. **ก่อนอบรม ส. 21:** คู่มือ `docs/คู่มือ/*.md` + ภาพ `docs/คู่มือ/img/` ยังเป็นหน้าจอเดิม (ไม่มีคิวสถานี / ส่งออก / หน้าบัญชีใหม่) · ผังระบบ artifact ยังไม่อัปเดต
4. **วันทดลอง ส. 21:** ทุกเครื่อง**ปิดแท็บทั้งหมดแล้วเปิดใหม่** (รีเฟรชเฉยๆ ไม่พอ · ยืนยันใน QA รอบ 4) · บั๊กระดับ 1 แก้ภายในวัน
5. **ก่อนเปิดใช้ อา. 22:** ยกเลิก/ลบงาน `TEST-` ทั้งหมด (รวม `TEST-R4-*` `TEST-R5-*` และงานแบ่ง `-2`) · **รับกลับรอบส่งออกของงานทดสอบก่อน** (trigger กันการยกเลิกงาน `out`) · ใบร่าง `confirmation_drafts` ทดสอบ · ไฟล์ PDF ทดสอบใน Storage · ข้อความกล่องจดหมาย · **อย่าลบบริษัทจริง 28 เจ้า** (ลบเฉพาะที่ AI สร้างตอนทดสอบ) · ปิดบัญชี `@pp142.test` · สร้างบัญชีทีมจริง
6. **รอเจ้าของ:** ผล `/spec-check` จากแอดมิน (ไฟล์ `.json`) → ตัด/เพิ่มตัวเลือกใน `production-confirmation.html` · เบอร์/ที่อยู่ "เบลสยามโกลเด้น" · Leaked password protection · เวลาเย็บต่อชิ้นสินค้าอื่น (`SEW_MINUTES` ใน `app/src/proto/capacity.ts`)
7. **ทำได้ถ้ามีเวลา:** หน้าแก้ข้อมูลบริษัทภายนอก (ตอนนี้เพิ่มได้จากฟอร์มส่งออกอย่างเดียว) · บทบาท "หัวหน้าฝ่ายผลิต" แยก (ตอนนี้ทุกบัญชีฝ่ายผลิตแทรกคิวได้) · ปุ่มย้อนสถานะงาน · ช่องเซ็น "ผู้ควบคุมงานรับงาน" ใน PDF ใบยืนยัน

## วิธีทำงาน (ทำทุกครั้ง)
1. `cd app && npm run lint && npm test && npm run build` · `cd supabase/tests && npm test`
2. migration ใหม่ชื่อหลัง `20261120030000` · ห้ามแก้ไฟล์เดิม · ฟังก์ชันที่ `create or replace` คัดลอกจากไฟล์ล่าสุดที่นิยามมัน · มีทดสอบผ่าน/ปฏิเสธ
3. ตรวจ md5 หลังเจ้าของรัน: เทียบ `md5(replace(prosrc, chr(13), ''))` กับเนื้อ `$$…$$` ในไฟล์ (สคริปต์ Python เขียนลง scratchpad แล้วรัน · bash heredoc ยาวมักพัง)
4. ลองหน้าจริง: `.claude/launch.json` ชั่วคราวพอร์ต **5176** (`npm --prefix app run dev -- --port 5176 --strictPort`) → `preview_start` → คืนด้วย `git checkout -- .claude/launch.json` · แผงเบราว์เซอร์มักล็อกอิน**บัญชีเจ้าของจริง** = ดูอย่างเดียว ห้ามกดบันทึก
5. ไฟล์ `docs/ใบมอบหมายงานฝึกงาน-ทดลองระบบผลิต.pdf` ไม่อยู่ใน git · **ห้าม `git add docs`** add ทีละไฟล์

## เรื่องค้าง / ข้อจำกัดที่รู้
- ช่วงเวลามาตรฐานหลายสถานี (segment) ที่เริ่มในโรงงานแล้วมีบางสถานีส่งออก ยังนับเวลาข้างนอกรวมในช่วง
- `#/board?job=` ของงานที่ไม่อยู่บนบอร์ด ไม่แสดงข้อมูลส่งออก · Realtime ไม่ฟัง `machine_types` / `confirmation_drafts` / `vendors`
- ไม่มีปุ่มย้อนสถานะงาน ("แจ้งว่ากดผิด" แค่บันทึก) · `resume_sewing` ไม่ตรวจจักรใช้ร่วม (ตั้งใจ)
- เจ้าของยังไม่ได้ตอบ SOP: พิมพ์ข้อ 13 · ตัดข้อ 1 · เวลาเย็บ/QC งานเกิน 100 ชิ้น · เวลามาตรฐานรีด DTF · เวลาร้านปัก
