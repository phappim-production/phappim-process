## ต้องทำ
### ก. ฐานข้อมูล (migration)
1. `public.owner_list_users()` → `table(user_id uuid, email text, created_at timestamptz, name text, role text, active boolean)` · `security definer` · `set search_path = ''` · **owner เท่านั้น** (ใช้ `private.require_role('owner')` · คนอื่น error ภาษาไทย) · รวมผู้ใช้ใน `auth.users` ที่ยังไม่มี profile ด้วย (name/role เป็น null)
2. revoke จาก `public, anon` · grant execute ให้ `authenticated`
3. ทดสอบใน `settings.mjs`: owner เห็นผู้ใช้ทุกคนรวมคนที่ยังไม่มี profile · supervisor เรียกแล้วถูกปฏิเสธ · anon เรียกไม่ได้ · owner แก้ `stations.sla_days` ได้ · supervisor แก้ไม่ได้ (แถวไม่เปลี่ยน)

### ข. หน้าจอ (6 แท็บ)
| แท็บ | ตาราง | ทำได้ |
|---|---|---|
| **ผู้ใช้และบทบาท** | `owner_list_users()` + `profiles` | กำหนดชื่อ · บทบาท (owner / supervisor / admin / qc / production / manager) · เปิด/ปิดใช้งาน · ผู้ใช้ที่ยังไม่มีบทบาทแสดงด้านบนพร้อมปุ่ม "กำหนดบทบาท" · ข้อความอธิบายว่า **การสร้างบัญชีใหม่ทำใน Supabase → Authentication → Add user** (หน้าเว็บสร้างบัญชีไม่ได้) · ห้าม owner ปิดหรือลดบทบาทตัวเอง · **ผู้ควบคุมงาน** เลือกเฟส (`profiles.section`: เฟส 1 พิมพ์-รีด-ตัด / เฟส 2 เย็บ-QC / ทุกเฟส = null) ช่องนี้แสดงเฉพาะบทบาท supervisor · เปลี่ยนเป็นบทบาทอื่นต้องตั้ง section = null ในการบันทึกเดียวกัน (ฐานข้อมูลบังคับ) · ป้ายใช้ `SECTION_LABELS` |
| **สถานีและขั้นย่อย** | `stations` | แก้ชื่อสถานี · เฟส (`section` 1/2) · `sla_days` (ว่าง = ไม่จับเวลา · ทศนิยม 1 ตำแหน่ง · > 0) · `warn_pct` (1–100) · แก้ขั้นย่อย: เพิ่ม / ลบ / เลื่อนลำดับ / แก้ชื่อ / เลือกชนิด (`req` ต้องติ๊ก · `num` กรอกค่า · `appr` ต้องอนุมัติ · `opt` เช็คลิสต์) · **`key` ของขั้นเดิมห้ามแก้** (งานที่เดินอยู่อ้างถึง) · ขั้นใหม่สร้าง key อัตโนมัติ (a–z, 0–9, _ ไม่ซ้ำในสถานี) · ห้ามแก้/ลบขั้นชนิด `lock` และขั้นที่ระบบใช้ (`sew_count`, `first_piece`, `inspect`, `sort_count`) ให้แก้ได้แค่ชื่อ |
| **เวลามาตรฐานของช่วง** | `sla_segments` | แก้ชื่อ · `sla_days` · `warn_pct` · (สร้าง/ลบช่วงยังไม่ต้องทำ) |
| **แม่แบบวัตถุดิบ** | `material_templates` | เพิ่ม / แก้ / ลบ: ชื่อ · ฝ่าย (แอดมิน / QC / ฝ่ายผลิต) · ใช้กับสินค้า (ทั้งหมด หรือเลือก 1 จาก `product_types`) · ใช้กับเส้นทาง (ทั้งหมด หรือเลือก) · ลำดับ · แถวที่มี `key` (เช่น ฟิล์ม DTF) **ห้ามลบ** แก้ได้แค่ชื่อ |
| **รหัสสาเหตุ** | `reason_codes` | เพิ่ม (รหัสตัวอักษรใหญ่+ตัวเลข ไม่ซ้ำ) · แก้กลุ่ม/ชื่อ/ลำดับ · **ไม่ลบ ใช้ปิดการใช้งานแทน** (รายงานเก่าอ้างถึงอยู่) |
| **จักรเย็บ** (S14) | `sewing_machines` · `product_machine_needs` · `machine_types` | เพิ่ม/แก้จักรทีละเครื่อง (รหัส A–Z 0–9 - ไม่ซ้ำ · ชนิด) · ลบได้เฉพาะจักรที่ไม่เคยถูกจ่าย (มีประวัติ = ปิดใช้งานแทน) · ตารางสินค้า × ชนิดจักร × จำนวน · **สถานะเสีย/ใช้ได้ไม่ต้องทำในหน้านี้** (ผู้ควบคุมงานเฟส 2 แจ้งผ่าน `set_machine_status`) |

แสดง**เส้นทางผลิต**แบบอ่านอย่างเดียว (ลำดับสถานีของแต่ละเส้นทาง) ใต้แท็บสถานี พร้อมข้อความ "แก้ลำดับเส้นทางต้องให้ผู้พัฒนาทำ"

### ค. พฤติกรรมที่ต้องมี
- **ล็อกอินและสิทธิ์เข้าหน้า A2 ทำไว้แล้วใน `App.tsx` ห้ามทำซ้ำ:** ยังไม่ล็อกอิน → `App.tsx` แสดงหน้าล็อกอินเอง · ไม่ใช่ owner → `App.tsx` แสดง "หน้านี้สำหรับเจ้าของระบบ" และไม่ render `SettingsPage` เลย (`canOpenPage` ใน `app/src/auth/access.ts`) · ดังนั้นหน้าตั้งค่า**ไม่ต้อง**ตรวจบทบาทเอง และห้ามเขียน hook อ่าน `profiles` ของตัวเองซ้ำ
- ต้องรู้ `user_id` ของตัวเอง (เพื่อห้าม owner ปิด/ลดบทบาทตัวเอง) → อ่านจาก `supabase.auth.getSession()` ครั้งเดียวในหน้า · ป้ายชื่อบทบาทภาษาไทยใช้ `ROLE_LABELS` จาก `app/src/auth/access.ts` (import ได้ ห้ามแก้ไฟล์นั้น)
- สิทธิ์จริงบังคับที่ฐานข้อมูล (RLS + `private.require_role`) · หน้าเว็บซ่อนปุ่มอย่างเดียวไม่พอ
- แก้แล้วกด **บันทึก** ทีละรายการ (ไม่บันทึกอัตโนมัติ) · ระหว่างบันทึกปุ่มกดซ้ำไม่ได้ · สำเร็จ = แจ้งสั้นๆ · ผิดพลาด = ข้อความภาษาไทยจาก error · มีการแก้ค้างแล้วจะออกจากแท็บ → ถามยืนยัน
- แสดง**คำเตือน**บนแท็บสถานี: "แก้ขั้นย่อยมีผลกับงานที่อยู่ในสถานีนั้นทันที (ขั้นที่เพิ่มใหม่จะต้องติ๊กก่อนกดเสร็จ)"
- ใช้ส่วนประกอบกลาง (`Card`, `CardHeader`, `Pill`, `TONE`, ไอคอนใน `icons.tsx`) · ปุ่มหลักสูง ≥ 48 px · ใช้ได้ที่ 375 px
- ไม่มีข้อมูล / กำลังโหลด / ผิดพลาด ครบทุกแท็บ
