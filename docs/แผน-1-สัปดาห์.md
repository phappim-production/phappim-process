## 3. กฎที่ระบบบังคับ (ต้องมีชุดทดสอบที่ "พยายามข้ามแล้วโดนปฏิเสธ" ครบทุกข้อ)
1. ไม่มี PDF ใบยืนยันเซ็นครบ → รับงานไม่ได้
2. วัตถุดิบไม่ครบทุกฝ่าย → ขึ้นตัวอย่างไม่ได้
3. ตัวอย่างยังไม่ "ผ่าน" → ผลิตจริงไม่ได้
4. ข้ามสถานีไม่ได้ · สถานีถัดไปเริ่มได้เมื่อสถานีก่อน "เสร็จ" ทั้งก้อน
5. ยังไม่ติ๊กขั้นย่อย [บังคับ]/[กรอกค่า] → กดเสร็จไม่ได้
6. DTF ยังไม่ได้รับฟิล์ม → เริ่มรีด DTF ไม่ได้
7. ตัวแรกยังไม่ผ่าน → กรอกยอดเย็บทั้งก้อนไม่ได้
8. QC ส่งกลับแก้ ต้องมีจำนวน + สาเหตุ + สถานีต้นเหตุ
9. พักงานต้องมีสาเหตุ · เวลาพักแยกจากเวลาทำงาน
10. **(ใหม่)** เกินเวลามาตรฐาน → กดเสร็จไม่ได้จนกว่าจะส่งรายงานปัญหา
11. **(ใหม่)** 2 คนกดงานเดียวกันพร้อมกัน → รับครั้งแรก อีกครั้งได้ข้อความ "สถานะเปลี่ยนแล้ว กรุณาโหลดใหม่"
12. **(ใหม่)** บทบาทที่ไม่มีสิทธิ์เรียกฟังก์ชัน → ปฏิเสธ · ข้อมูลงานเขียนตรงเข้าตารางไม่ได้ (ต้องผ่านฟังก์ชันเท่านั้น)

ทุกการกด = 1 แถวใน `events` (ห้ามแก้/ลบ)

## 4. คุมคุณภาพ (ไม่ให้มีบั๊ก)

### 4.1 ทุก PR ต้องผ่านก่อน merge
- [ ] CI เขียวทั้งหมด: ทดสอบฐานข้อมูล · typecheck · lint · ทดสอบหน้าเว็บ · build
- [ ] กฎหรือฟังก์ชันใหม่ มีทดสอบทั้งกรณีผ่านและกรณีต้องถูกปฏิเสธ
- [ ] เปิดลิงก์ทดลองของ PR แล้วลองจริงที่ 3 ขนาดจอ: มือถือ 375 px · แท็บเล็ต 768 px · คอม 1440 px · ไม่มีหน้าล้นด้านข้าง · ไม่มี error ใน console
- [ ] มีสถานะ กำลังโหลด / ไม่มีข้อมูล / เกิดข้อผิดพลาด ครบทุกหน้า
- [ ] Claude รีวิวโค้ดแล้ว (งาน Codex) · คำอธิบาย PR บอกว่าเปลี่ยนอะไร ทดสอบอะไร

### 4.2 ตรวจทุกวัน (17:00)
- Claude รันรายการตรวจหัวข้อ 4.3 บนลิงก์ทดลองล่าสุด แล้วรายงานผลในแชท: ผ่าน / ไม่ผ่าน / บั๊กใหม่
- เจ้าของโปรเจกต์ลองกด 15 นาที จดสิ่งที่ไม่เข้าใจหรือไม่สะดวก
- ตรวจ Supabase advisors (ความปลอดภัย/ประสิทธิภาพ) และ log error

### 4.3 รายการตรวจทั้งระบบ (เดินงาน 1 งานตั้งแต่ต้นจนจบ)
1. รับงานเส้นทางปกติ + DTF + ไม่พิมพ์ อย่างละ 1 งาน
2. ติ๊กวัตถุดิบทีละฝ่าย (ล็อกอินคนละบทบาท) · ลองขึ้นตัวอย่างก่อนครบ → ต้องถูกปฏิเสธ
3. ตัวอย่างไม่ผ่าน 1 รอบ → ผ่าน · ตรวจประวัติรอบ
4. เดินทุกสถานี · ลองกดเสร็จก่อนติ๊กขั้นบังคับ → ถูกปฏิเสธ · DTF ก่อนได้ฟิล์ม → ถูกปฏิเสธ
5. เย็บ: กรอกยอดก่อนตัวแรกผ่าน → ถูกปฏิเสธ
6. QC ไม่ผ่าน 5 ชิ้น → กลับเย็บพร้อมป้าย "งานแก้" → กลับ QC
7. พักงาน 30 นาที → เวลาทำงานไม่นับช่วงพัก
8. ปรับเวลามาตรฐานให้สั้นเพื่อทดสอบ → การ์ดส้ม → แดง → กดเสร็จไม่ได้จนกว่าจะรายงาน
9. เปิด 2 จอพร้อมกัน → อีกจอเห็นการเปลี่ยนภายใน 2 วินาที · กดพร้อมกัน → รับครั้งเดียว
10. ค้นหา SC → ขั้นปัจจุบันถูก · ไทม์ไลน์ครบ · เปิด PDF ได้

### 4.4 บั๊ก
- จดใน GitHub Issues (ป้าย `bug` + ระดับ) · ทุกบั๊กที่แก้แล้วต้องมีทดสอบกันกลับมาซ้ำ
- **ระดับ 1** ข้อมูลผิด/หาย, ทำงานต่อไม่ได้, กฎถูกข้ามได้ → แก้ภายในวันเดียวกัน
- **ระดับ 2** ใช้ได้แต่ผิดหรือสับสน → แก้ภายในวันถัดไป
- **ระดับ 3** ความสวยงาม/ความสะดวก → รวบรวมแก้หลังเปิดใช้

## 6. หลัก UI/UX
- **ผู้ใช้หลักคือคนหน้างานบนแท็บเล็ต:** ปุ่มหลักสูง ≥ 48 px · ตัวอักษรหลัก ≥ 16 px · กดผิดยาก (ปุ่มเสร็จ/ส่งแก้ ถามยืนยัน)
- **1 การ์ด = 1 สิ่งที่ต้องทำต่อ:** ปุ่มหลักเด่นที่สุดอันเดียว · ปุ่มที่กดไม่ได้ต้องบอกว่าทำไม ("ยังไม่ติ๊ก ตรวจงานพิมพ์")
- **สีมีความหมายตายตัวทั้งระบบ:** แดง = เลยกำหนด/ติดปัญหา · ส้ม = ใกล้ครบ/รอ · ฟ้า = กำลังทำ · เขียว = เสร็จ/ทัน · ห้ามใช้สีเหล่านี้เพื่อความสวยอย่างเดียว
- **ใช้ส่วนประกอบกลางเท่านั้น** (`app/src/components/ui.tsx`, `tone.ts`, `icons.tsx`) ไม่สร้างปุ่ม/การ์ดแบบใหม่เอง
- **คำศัพท์เดียวกันทั้งระบบ:** ใบยืนยัน · รับงาน · วัตถุดิบ · ขึ้นตัวอย่าง · สถานี · ขั้นย่อย · พักงาน · งานแก้ · รายงานปัญหา (ห้ามสลับเป็นคำอื่น)
- **ข้อความผิดพลาดภาษาไทย บอกว่าต้องทำอะไรต่อ** ไม่แสดงข้อความภาษาอังกฤษจากระบบ
- **ข้อมูลสดเสมอ:** ไม่ต้องกดรีเฟรช · แสดงเวลาอัปเดตล่าสุด · เน็ตหลุดขึ้นแถบเตือนชัดเจน
