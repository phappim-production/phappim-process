## ต้องทำ
### ก. หน้ารับงานอ่านคำตอบให้ถูกที่ (`confirmation.ts`)
- คำตอบของสินค้า = `d.p[d.product]` (ถ้าเป็น object) · ไฟล์รุ่นเก่าที่ `p` เป็นคำตอบตรงๆ (มี `print_method` / `sizes` / `qty` / `items` ที่ชั้นบนสุด) ให้ยังอ่านได้
- `print_method` เป็น string เดี่ยวได้ (ไฟล์รุ่นเก่า) · ค่า `อื่นๆ` ใช้ `print_method__other` แทน เหมือน `route()` ในฟอร์ม
- จำนวน: ลำดับเดียวกับ `totalQty()` ในฟอร์ม — ตารางไซซ์ `sizes` → ตารางรายการ `items` (คอลัมน์ `qty`) → ช่อง `qty`
- เส้นทาง: `suggestRoute` ต้องให้ผลตรงกับ `route()` ในฟอร์มทุกกรณี (DTF · DTG · สกรีน · ปัก + ซับ/ดิจิทัล = `print_emb` · ปัก · ซับ/ดิจิทัล = `normal` · ไม่มี = `plain`) · ระวัง regex ซับ: ฟอร์มใช้ `/ซับ|ดิจิทัล/` แอปใช้ `/ซับลิเมชั่น|ดิจิทัล/` ให้ตรงกัน
- `spare` อ่านจากคำตอบของสินค้า

### ข. ฟอร์มบันทึกผลสรุปลงไฟล์ (`production-confirmation.html`)
- ตอนบันทึก `.json` เพิ่ม `summary: { qty: totalQty(), route: route().code }` · หน้ารับงานใช้ `summary` ก่อน (ถ้า `route` เป็นรหัสเส้นทางที่รู้จัก และ `qty` > 0) แล้วค่อยคำนวณเองเมื่อไม่มี (ไฟล์เก่า)
- เหตุผล: ฟอร์มรู้ว่าไซซ์ไหนแสดงอยู่ (`size_sets`) แต่แอปไม่รู้ · ตารางไซซ์อาจมีค่าค้างของชุดไซซ์ที่ยกเลิกไปแล้ว
- `route().code` เป็น `custom` หรือว่าง → หน้ารับงานคำนวณเอง

### ค. ทดสอบ (`receive.test.mjs`)
- แก้ข้อมูลตัวอย่าง `form()` ให้เป็นรูปแบบจริง (`p: { polo: { ... } }`) · ทดสอบเดิมต้องผ่านด้วยรูปแบบใหม่
- เพิ่มกรณีจากบั๊กจริง: เสื้อยืด · `['งานปัก', 'ซับลิเมชั่น พิมพ์ทั้งตัว (All-over)']` · M = 20 → `print_emb` · 20 (ใช้ข้อความตัวเลือกจริงจากฟอร์ม)
- เส้นทางครบ 7 แบบที่ฟอร์มให้ได้ · `อื่นๆ` + `print_method__other` · `print_method` เป็น string · ตารางรายการ `items` · ไฟล์รุ่นเก่า (`p` ตรงๆ) · มี `summary` → ใช้ `summary` · `summary.route` = `custom` → คำนวณเอง
- **ทดสอบกับไฟล์จริง:** เปิดฟอร์มในเครื่อง สร้างไฟล์ `.json` 3 แบบ (ปัก + ซับ · DTF · สินค้าไม่ใช่เสื้อที่มีตารางรายการ) แล้วเก็บไว้เป็น fixture ใน `app/tests/fixtures/` (ลบ `imgs` ออก · ข้อมูลสมมติ ไม่ใช่ลูกค้าจริง) · ทดสอบว่าอ่านได้ถูก
