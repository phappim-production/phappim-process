**ผู้ทำ:** Codex · **branch:** `codex/c5-qr-label` ในโฟลเดอร์ `../pp142-c5` (Claude สร้างให้แล้ว) · **ส่งภายใน:** ศ. 20 พ.ย. 18:00 (ใช้ในวันทดลองจริง ส. 21)

## ทำไม
หน้างานติดใบปะไว้กับกองงาน · สแกน QR แล้วเปิดรายละเอียดงานนั้นทันที ไม่ต้องพิมพ์ค้นหา · ช่องเซ็นแต่ละสถานีใช้เป็นหลักฐานบนกระดาษคู่กับระบบในช่วงแรก

- `app/src/pages/job-label/qr.ts` + `qr.test.ts` (ใหม่) · ไฟล์ช่วยอื่นในโฟลเดอร์ `job-label/` ได้
- `app/src/pages/Dashboard.tsx` **เฉพาะ** ปุ่ม "พิมพ์ใบปะงาน" ในหัวแผงรายละเอียดงาน (ข้อ ค.)
- **ห้ามแก้** `App.tsx` (เส้นทาง `#/label?id=` และสิทธิ์เปิดหน้าต่อไว้แล้ว) และไฟล์อื่น · **ห้ามเพิ่ม dependency** · ไม่มี migration

## ต้องทำ
### ก. ตัวสร้าง QR `qr.ts` (pure function · ไม่แตะ DOM)
- เข้ารหัส byte mode (UTF-8) · error correction **M** · เลือก version เล็กสุดที่พอ ระหว่าง 1–10 · ยาวเกิน → `throw` ข้อความไทย
- ลิงก์จริงยาว 73 ตัวอักษร (`https://pp142.pages.dev/#/board?job=` + uuid 36 ตัว) → ต้องได้ **version 5** · ต้องมี Reed–Solomon · interleave block · เลือก mask ด้วยคะแนนโทษ 4 ข้อ · format info · version info (≥ 7 ถ้ารองรับ)
- ส่งออก `qrMatrix(text: string): boolean[][]` และ `qrSvgPath(matrix): string` (path เดียว · มีขอบว่าง 4 ช่อง) · หน้าจอวาดเป็น `<svg>` สีดำบนขาว (ข้อยกเว้นเรื่องสีของ AGENTS.md: QR ต้องดำ/ขาวเพื่อให้สแกนได้ · ใช้ `currentColor` + `text-ink` / `bg-white` ได้ ไม่ใส่ hex)
- ถ้าทำไม่ทันหรือสแกนไม่ติด → **หยุด** แล้วบอกในไฟล์ส่งงาน · Claude จะขออนุญาตเจ้าของใช้ไลบรารี (ห้ามเพิ่มเอง)

### ข. หน้า `#/label?id=<job id>` ขนาด A5 ตั้ง
- อ่าน `job_live` เลือกเฉพาะคอลัมน์ที่ใช้ (`id, confirmation_no, customer_name, job_name, product_type_code, qty, unit, due_date, route_code, needs_sample, sample_round`) · ชื่อสินค้าจาก `product_types` · ลำดับสถานีจาก `route_stations` (เรียง `seq`) + ชื่อจาก `stations` — **อ่านจากฐานข้อมูล ไม่ใช้ `ROUTES` ใน `proto/model.ts`** เพราะเจ้าของแก้เส้นทางในหน้าตั้งค่าได้
- เนื้อหา: เลขที่ใบยืนยัน **ตัวใหญ่** · ลูกค้า · ชื่องาน · สินค้า · จำนวน + หน่วย · กำหนดส่ง (วันที่ไทย พ.ศ. · ใช้ `dueDate()` จาก `app/src/data/live.ts` กันเขตเวลาเลื่อนวัน) · เส้นทาง · ขึ้นตัวอย่างหรือไม่ · ตารางสถานีตามลำดับ (ช่องว่าง วันที่ / ผู้รับ / ลายเซ็น) · QR ขนาดพิมพ์ ≥ 30 มม. · วันที่พิมพ์ใบ
- ปุ่ม "พิมพ์" (`window.print()`) สูง ≥ 48 px · `@media print`: `@page { size: A5 portrait; margin: 8mm }` · ซ่อนเมนู หัวหน้า ปุ่ม และทุกอย่างนอกใบ · พอดี **1 หน้า** สำหรับเส้นทางที่ยาวที่สุด (พิมพ์ + ปัก)
- สถานะ กำลังโหลด / ไม่พบงาน (id ผิด หรือไม่มี `?id=`) / ผิดพลาด (`thaiError()`) · จอ 375 px ไม่ล้นข้าง (ย่อใบให้พอดีจอ)

### ค. ปุ่มในรายละเอียดงาน (`Dashboard.tsx`)
- ลิงก์ "พิมพ์ใบปะงาน" ในหัวแผงรายละเอียดงาน → `#/label?id=<id>` (แท็บเดิม) · สูง ≥ 48 px · ใช้ไอคอนจาก `components/icons.tsx` · แก้ไม่เกิน ~10 บรรทัด

## ทดสอบ
- `qr.test.ts` (Vitest): เทียบ matrix กับคำตอบอ้างอิงที่รู้ผลอย่างน้อย 2 ข้อความ (เช่น ตัวอย่างใน ISO/IEC 18004 หรือที่สร้างจากเครื่องมือมาตรฐานแล้วฝังเป็นข้อความในไฟล์ทดสอบ) · ลิงก์จริง → version 5 ขนาด 37×37 · finder/timing pattern ถูกที่ · format bits ถอดกลับได้ระดับ M · ข้อความยาวเกิน → error ไทย
- ถ้ามีฟังก์ชันจัดรูปข้อมูลใบ (เช่น แปลงแถวเป็นข้อมูลใบ) ให้ทดสอบด้วย
- ชุดทดสอบเดิมทุกข้อยังผ่าน (Vitest 105 · node:test 108 · DB 493)
