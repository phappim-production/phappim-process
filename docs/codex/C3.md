# ใบสั่งงาน C3 — แจ้งเตือน LINE

**ผู้ทำ:** Codex · **branch:** `codex/c3-line-notify` (แตกจาก `main` หลัง PR #2 merge) · **ส่งภายใน:** พฤหัสบดี 19 พ.ย. 18:00
อ่านก่อน: `AGENTS.md` · `docs/api-workflow.md` · `supabase/migrations/20261117000001_workflow.sql`
**ต้องมี:** LINE Official Account + Messaging API channel (เจ้าของโปรเจกต์ใส่ secret เอง ห้ามใส่ token ในโค้ดหรือ PR)

## ทำไม
คนที่ต้องตัดสินใจ (แอดมิน ผู้ควบคุมงาน ผู้บริหาร) ไม่ได้เปิดหน้าจอตลอด · ต้องรู้ทันทีเมื่องานติดปัญหา เกินเวลา หรือใกล้กำหนดส่ง · ทีมใช้ LINE อยู่แล้ว

## ขอบเขต
**แก้ได้เฉพาะ:**
- migration ใหม่ **1 ไฟล์** `supabase/migrations/20261118200000_notify.sql`
- `supabase/functions/line-notify/**` (Edge Function · Deno · TypeScript)
- `supabase/tests/notify.mjs` (ใหม่) + เพิ่ม **2 บรรทัด** ใน `supabase/tests/run.mjs`
- `docs/codex/C3-setup.md` (ใหม่) วิธีตั้งค่าสำหรับเจ้าของโปรเจกต์

**dependency:** ห้ามเพิ่มใน `app/` · Edge Function ใช้ `fetch` ของ Deno เท่านั้น

## หลักการออกแบบ (ห้ามเปลี่ยน)
1. **ระบบหลักต้องไม่ช้าหรือพังเพราะ LINE:** trigger และงานตรวจตามรอบ **แค่เพิ่มแถวลงตาราง outbox** · การส่งจริงทำใน Edge Function แยก · ห้ามเรียก HTTP ภายใน transaction ของ RPC
2. **ไม่ส่งซ้ำ:** ทุกแถวมี `dedupe_key` unique · insert แบบ `on conflict do nothing`
3. **ส่งไม่สำเร็จต้องลองใหม่:** เก็บ `attempts`, `last_error` · ลองสูงสุด 5 ครั้ง แล้วหยุด

## ต้องทำ
### ก. ฐานข้อมูล
- ตาราง `notification_outbox(id, kind, job_id null, dedupe_key text unique, message text, created_at, sent_at null, attempts int default 0, last_error text)` · RLS เปิด · อ่านได้เฉพาะ owner · เขียนตรงไม่ได้ (ไม่มี policy เขียน)
- ตาราง `notify_settings(key text pk, value text)` สำหรับเปิด/ปิดแต่ละชนิด (`kind`) · owner แก้ได้
- **ส่งทันที (trigger บน `events` หลัง insert):**
  | kind | เมื่อ | dedupe_key |
  |---|---|---|
  | `hold` | event `hold` | `hold:{issue_id}` |
  | `delay_report` | event `delay_report` | `delay:{report_id}` |
  | `rework` | event `rework` | `rework:{event id}` |
- **ตรวจตามรอบ** (ฟังก์ชัน `private.notify_scan()` · เรียกทุก 15 นาที ช่วง 07:00–20:00 เวลาไทย):
  | kind | เงื่อนไข | dedupe_key |
  |---|---|---|
  | `sla_over` | `job_live.sla.station_over` หรือ `segment_over` = true และยังไม่รายงาน | `sla:{job}:{visit}` |
  | `film_late` | DTF ยังไม่ได้รับฟิล์ม และเลย `dtf_film_eta` | `film:{job}:{วันที่}` (วันละครั้ง) |
  | `materials_late` | อยู่ขั้นวัตถุดิบเกิน 2 วันทำงาน (`private.work_days(stage_entered_at, now())`) | `mat:{job}:{วันที่}` |
  | `due_soon` | ยังไม่เสร็จ และกำหนดส่งคือพรุ่งนี้หรือวันนี้ (ส่งรอบ 08:00) | `due:{job}:{วันที่}` |
- ตั้งรอบด้วย `pg_cron` (+ `pg_net` เรียก Edge Function) **ห่อด้วยเงื่อนไขว่ามี extension** (ชุดทดสอบ PGlite ไม่มี pg_cron/pg_net จะต้องไม่พัง) · key สำหรับเรียกฟังก์ชันเก็บใน Supabase Vault ไม่ใช่ใน migration
- ข้อความภาษาไทยสั้น บรรทัดแรกบอกเรื่อง เช่น:
  ```
  ⛔ งานติดปัญหา SC691521
  มูลนิธิรักษ์ป่า · ถุงผ้า 1,000 ใบ
  สถานี: เย็บงาน · สาเหตุ: จักรเสีย รอช่างซ่อม
  https://pp142.pages.dev
  ```
### ข. Edge Function `line-notify`
- รับ POST (ต้องมี header ลับตรงกับ secret `NOTIFY_CRON_SECRET` ไม่ตรง = 401)
- อ่านแถวที่ `sent_at is null and attempts < 5` เก่าสุดก่อน ครั้งละไม่เกิน 20 แถว · ส่งด้วย LINE Messaging API push (`LINE_CHANNEL_ACCESS_TOKEN`, ผู้รับ `LINE_TO`) · สำเร็จ = `sent_at` · ไม่สำเร็จ = `attempts + 1`, `last_error`
- ทดสอบด้วย `deno test` โดย mock `fetch` (ส่งสำเร็จ · LINE ตอบ 429/500 · secret ผิด)
### ค. ทดสอบฐานข้อมูล (`notify.mjs`)
- พักงาน 1 ครั้ง → outbox 1 แถว kind `hold` · เรียก trigger ซ้ำด้วย issue เดิม → ยังมี 1 แถว
- `notify_scan()` 2 ครั้งติดกัน → ไม่ซ้ำ · งานที่ไม่เข้าเงื่อนไข → ไม่มีแถว
- ปิด kind ใน `notify_settings` → ไม่สร้างแถว
- supervisor อ่าน/เขียน outbox ไม่ได้
- **RPC เดิมทุกตัวยังผ่าน** (ชุดทดสอบ workflow ต้องผ่านทั้งหมด)
