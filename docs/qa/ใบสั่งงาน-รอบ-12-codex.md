## ทำไม
วันทดลอง (ส. 21) มีงานที่โรงงานต่างประเทศผลิตทั้งหมด ต้องเลือกเส้นทาง "ไม่มีงานพิมพ์" แล้วส่งออกตัด + เย็บแทน · PR 143 เพิ่ม:
- สถานี `outside` "สั่งผลิตข้างนอก" + เส้นทาง `outside` "ผลิตข้างนอกทั้งหมด" = สั่งผลิตข้างนอก → QC + Packing (`supabase/migrations/20261121000000_outside_route.sql` · ลงฐานจริงแล้ว)
- `private.outsourceable` รวม `outside` · แอดมินใช้ `send_out` / `receive_back` เดิม · รับกลับแล้วไปรอ QC + Packing
- trigger `jobs_guard_outside_start` กันเปลี่ยนเป็น `doing` ที่ `outside` ทุกทาง
- หน้าเว็บ: ตัวเลือกเส้นทางในหน้ารับงาน · แถบสถานีคงเลข 1–7 · "สั่งผลิตข้างนอก" เป็นปุ่มไม่มีเลข · ปุ่มเริ่มเปลี่ยนเป็นข้อความ · ประมาณวันเสร็จนับ `LEAD.outside` = 7 วันและไม่ต่อคิวกัน

**รายงานแผนก:** รอบสถานีมาจาก view `station_visits` (เหตุการณ์ `station_start` / `station_done` เท่านั้น) · `outside` กดเริ่มไม่ได้ จึงไม่มีรอบและไม่ขึ้นในรายงาน (Claude ลองบน PGlite แล้ว: งานผลิตข้างนอกครบวงจรมีรอบแค่ `qc_pack`) · ตรวจซ้ำได้ ไม่ต้องรายงานว่า `outside` ไม่อยู่ในรายงาน

## สิ่งที่ต้องทดสอบ

### A. ฐานข้อมูล (`flow-r12.mjs` · ธุรกรรมเดียว rollback ตอนจบ · บัญชีตามจริง: แอดมิน · ฝ่ายผลิต · ผู้บริหาร · staff จับคู่ `qc_pack` ทำ QC · staff หลายสถานี)
1. **เดินครบ:** รับงาน → รอที่ `outside` → ส่งออก → รับกลับ → QC บันทึกผ่าน → เสร็จ → จัดส่ง · ทุกขั้นมี `events` 1 แถว · `job_live` / `job_sla_flags` ถูกทุกขั้น
2. **กดเริ่มที่ `outside` ไม่ได้ทุกทาง** ทุกบทบาท (รวมเจ้าของระบบ และ staff ที่จับคู่สถานี `outside`): `start_station` · `start_in_queue` (มี/ไม่มีเหตุผล) · `close_issue` หลังพักงาน · ฟังก์ชันอื่นที่ตั้ง `station_status = 'doing'` (ไล่หาใน migrations) · ถูกปฏิเสธแล้วไม่มี `events` เกิน
3. **ขอบของส่งออก:** ส่งถึง `qc_pack` ไม่ได้ · `forward_out` จาก `outside` ไป QC ไม่ได้ · `update_out_plan` · ส่งออกงานที่พักอยู่ไม่ได้ · ส่งซ้ำไม่ได้ · บริษัทที่ปิดแล้วเลือกไม่ได้ · `add_vendor` ที่รับงาน `outside` ได้
4. **งานแก้:** QC ส่งแก้กลับ `outside` (ทั้งจำนวน / บางส่วน) → ส่งออกรอบแก้ → รับกลับเข้า QC · ส่งแก้ไปสถานีที่ไม่อยู่ในเส้นทางไม่ได้ · ยอด QC ไม่เกินจำนวน
5. **ขึ้นตัวอย่าง:** ตัวอย่างรอที่ `outside` → ส่งออก → QC → `sample_review` → ไม่ผ่าน (รอบ 2 กลับ `outside`) → ผ่าน → เข้าผลิตจริงที่ `outside`
6. **แบ่งงาน:** `split_job` ที่ `outside` → งานลูกอยู่ `outside` · ส่งออกแยกบริษัท · รับกลับคนละวัน · จัดส่งแยกกัน
7. **ยกเลิกงาน:** ยกเลิกตอนรอที่ `outside` ได้ · ตอนอยู่ข้างนอกต้องรับกลับก่อน · หลังยกเลิกส่งออกไม่ได้
8. **คิว:** งานหลายงานรอที่ `outside` ไม่ขวางคิวกันเอง (ส่งออกงานที่ไม่ใช่คิวแรกได้ไหม · ควรได้หรือไม่ ให้รายงานสิ่งที่เห็น) · รับกลับแล้วต่อคิว QC ถูกลำดับ · `move_job_ahead` ที่ QC
9. **ไม่กระทบเส้นทางเดิม:** ทุกเส้นทางเดิม (ปกติ · DTF · DTG · สกรีน · ปัก · พิมพ์+ปัก · ตัดงานลูกค้า · ไม่พิมพ์) ยังเริ่ม/เสร็จ/ส่งออกได้เหมือนเดิม · งานเดิมที่อยู่ข้างนอกด้วยเส้นทาง `plain` (แบบ SC690015-0002 · ส่งตัด+เย็บ) รับกลับแล้วเข้า QC
10. **ค่าคงที่หลังทุกขั้น** (แบบ `invariant` ใน `flow-r8.mjs`): ไม่มีงาน `doing` ที่ `outside` · งาน `out` ต้องมีรอบส่งออกเปิด 1 รอบ · `events` ไม่ถูกแก้
11. `supabase/scripts/live-check.sql` และ `golive-cleanup.sql` รันบนฐานที่มีงาน `outside` แล้วไม่ error (อ่านอย่างเดียว ห้ามแก้)

### B. หน้าเว็บ (Vitest `flow-r12.test.ts` + เบราว์เซอร์กับ API จำลอง)
1. **หน้ารับงาน:** เลือก "ผลิตข้างนอกทั้งหมด" → ลำดับสถานีถูก · ไม่มีคำเตือนสูตรจักร (ลองสินค้า หมวก / หมอน) · กล่องคาดว่าเสร็จสมเหตุผล
2. **บอร์ด / แถบสถานี:** ทุกบทบาท · เลข 1–7 คงเดิม · ปุ่ม "สั่งผลิตข้างนอก" จำนวนถูก · กดแล้วหัวสถานีถูก · staff ที่ไม่ได้จับคู่ `outside` เห็นหรือไม่เห็นตามที่ควร (ให้รายงาน)
3. **คิวสถานี / รายละเอียดงาน:** งานรอที่ `outside` ไม่มีปุ่มเริ่ม แต่มีข้อความบอกเหตุผล · แอดมินเห็นปุ่มส่งออก · บทบาทอื่นไม่เห็นปุ่มส่งออก · ระหว่างอยู่ข้างนอกกล่องแสดงบริษัท/วันกลับ · "รับเข้า" บอกว่าไปรอ QC + Packing · ไม่มีปุ่มส่งต่อ
4. **ภาพรวม / รายงาน / คิวการผลิต:** การ์ด "สถานีตอนนี้" · การ์ด "งานส่งออกข้างนอก" · "งานค้างแต่ละสถานี" ไม่มี `outside` เป็นคอขวด · รายงานแผนกไม่มี `outside` และเวลารอ QC ของงานผลิตข้างนอกไม่เพี้ยน · ไม่มี `NaN` / `Infinity` บนจอ (`CAPACITY.outside = Infinity`)
5. **ตั้งค่า:** หน้าจับคู่สถานี (Station Assignment) และบริษัทภายนอก มี/ไม่มี "สั่งผลิตข้างนอก" ตามที่ควร (ให้รายงาน)
6. ทุกหน้าที่เกี่ยวข้อง 375 / 768 / 1440 px ไม่ล้น · console ไม่มี error (ยกเว้น websocket realtime ของ API จำลอง) · ภาพหลักฐาน `docs/qa/img/r12-cx-*.png`
