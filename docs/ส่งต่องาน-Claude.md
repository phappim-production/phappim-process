## Flow จริงในโรงงาน (ระบบทำตามนี้แล้ว)
1. แอดมินดีลงาน เตรียมวัตถุดิบครบ → กรอกฟอร์ม `pp142.pages.dev/confirmation` → **บันทึกเข้าระบบ** (ใบยืนยันร่าง) → ส่งออก PDF A4 ให้ลูกค้าเซ็น
2. แอดมิน **รับงานใหม่** → เลือกใบจากรายการ → เห็นวันคาดว่าเสร็จ (แดงถ้าไม่ทันกำหนดส่ง) → รับงาน · **PDF ที่เซ็นไม่บังคับ** แนบทีหลังที่รายละเอียดงาน
3. งานไปสถานีแรกทันที (หรือขึ้นตัวอย่าง) · ไม่มีขั้นวัตถุดิบ · แต่ละสถานี **เริ่ม → เสร็จ** + พักงาน · ฝ่ายผลิตคุมทุกสถานี · QC คุม QC + Packing
4. เย็บแบบไลน์: เริ่มเย็บ = จ่ายจักรประจำไลน์ (เข็มเดี่ยว ฯลฯ) · **จักรลา · โพ้ง 4 เส้น · ติดกระดุม · เจาะรังดุม = ใช้ร่วม** (owner สลับได้ในตั้งค่า) · ไม่จำกัดจำนวนไลน์ (หัวหน้าคุมเอง)
5. ระบบยังบังคับ: รีดฟิล์มรอแอดมินบันทึกได้รับ · QC ผ่านครบจำนวนก่อนเสร็จ · ชิ้นไม่ผ่านส่งแก้ · เกินเวลามาตรฐานต้องรายงานก่อนเสร็จ · ข้ามสถานีไม่ได้

## งานถัดไป (เรียงตามความสำคัญ)
1. **เจ้าของลองใช้จริง:** บันทึกใบยืนยัน 1 ใบจากฟอร์ม → ส่งงานเข้า → แนบ PDF ทีหลัง · Claude ยังไม่เคยกดด้วยบัญชีแอดมินจริง (แผงเบราว์เซอร์ไม่ได้ล็อกอิน) → ถ้าเจ้าของส่งภาพ/อาการมา แก้ทันที
2. **เจ้าของต้องทำเอง:** เปิด Supabase → Authentication → Passwords → **Leaked password protection** · ส่งเวลาเย็บต่อชิ้นสินค้าอื่น (ใส่ `SEW_MINUTES` ใน `app/src/proto/capacity.ts`) · ชื่อสถานี "รีดฟิล์ม" ของเส้นทางสกรีนตรงที่หน้างานเรียกไหม
3. **วันทดลอง ส. 21:** ทุกเครื่อง**ปิดแท็บ/แอปทั้งหมดแล้วเปิดใหม่ 1 ครั้ง** (รุ่นก่อน G5 ไม่รับรุ่นใหม่เอง) · เลือกสถานีประจำเครื่อง · สแกน QR iPhone + Android · พิมพ์ใบปะ A5 · ลองเน็ตหลุด + 2 เครื่องกดงานเดียวกัน · บั๊กระดับ 1 แก้ภายในวัน
4. **ก่อนเปิดใช้ (อา. 22):** ยกเลิก/ลบงาน `TEST-` ทั้งหมด (รวม `TEST-SIM-*` · ปล่อยจักรที่ผูกอยู่ · ใบร่าง `confirmation_drafts` ที่เป็นทดสอบ · ไฟล์ PDF `TEST-G4-N/…` ใน Storage หลังลบงาน) · ข้อความกล่องจดหมายของงานทดสอบ · ปิดบัญชี `@pp142.test` · สร้างบัญชีจริงให้ทีม (Supabase → Add user → หน้าตั้งค่ากำหนดบทบาท)
5. **ทำได้ถ้ามีเวลา (เจ้าของยังไม่ได้ขอ):** รายการ "งานที่ยังไม่มี PDF ที่ลูกค้าเซ็น" · ช่อง PDF ใบยืนยันยังมีช่องเซ็น "ผู้ควบคุมงานรับงาน" · เวลาสิ้นวันกำหนดส่งยังเป็น 17:00 (`live.ts` · `stationSteps.ts` · `Overview.tsx`) ทั้งที่เลิกงาน 18:00
6. **หลังเปิดใช้:** ช่อง "นาทีเย็บต่อชิ้น / ช่างต่อไลน์" ในหน้าตั้งค่าสินค้า (ย้าย `SEW_MINUTES` เข้า `product_types` · เจ้าของเลือกไว้แล้ว) · สำรองข้อมูลทุกวัน + `auth.users` + ไฟล์ PDF · ปุ่มย้อนสถานะงาน · แนบรูปในรายงานปัญหา

## วิธีทำงาน (ทำทุกครั้ง)
1. แตก branch จาก `origin/main` · แก้ · `cd app && npm run lint && npm test && npm run build` · `cd supabase/tests && npm test`
2. migration ใหม่: ชื่อ `YYYYMMDDHHMMSS_ชื่อ.sql` หลัง `20261119230000` · ห้ามแก้ไฟล์เดิม · ฟังก์ชันที่จะ `create or replace` ให้**คัดลอกจากไฟล์ migration ล่าสุดที่นิยามฟังก์ชันนั้น** (live ตรงกับไฟล์ ยกเว้นคอมเมนต์ที่ถูกตัดในไฟล์ที่ลงด้วยมือก่อนหน้า) · มีทดสอบทั้งผ่านและปฏิเสธ
3. ลงฐานข้อมูลจริง**ก่อน merge** (Cloudflare deploy ทันทีที่ merge): `apply_migration` → `update supabase_migrations.schema_migrations set version = '<ไฟล์>' where name = '<ชื่อ>'` → เทียบ `md5(replace(prosrc, chr(13), ''))` กับเนื้อ `$$…$$` ในไฟล์ (สคริปต์ Python ในไฟล์ · อย่าใช้ regex ใน `python -c` ผ่าน bash)
4. ตรวจกฎบนฐานข้อมูลจริงได้แบบ**ย้อนกลับ**: `do $$ … raise exception 'ROLLBACK%', log; end $$` + ฟังก์ชัน `pg_temp.act(uid, sql)` ที่ตั้ง `request.jwt.claims` เป็นบัญชีทดสอบ (ดูตัวอย่างใน `docs/qa/รอบ-3.md` หัวข้อ 3) · uid บัญชีทดสอบ: admin `63ad8527-…` · production `34d97810-…` · qc `088bd56e-…` · manager `60c2aa77-…`
5. ลองหน้าจริง: `.claude/launch.json` ชั่วคราวพอร์ต **5176** → `preview_start` → คืนด้วย `git checkout -- .claude/launch.json` · แผงเบราว์เซอร์**ยังไม่ได้ล็อกอิน** (ใส่รหัสผ่านให้ไม่ได้) · ห้ามกดปุ่มบันทึกข้อมูลถ้าล็อกอินบัญชีเจ้าของจริง
6. สคริปต์ยาวใน bash heredoc มักพัง (`unexpected EOF`) → เขียนไฟล์ Python ลง scratchpad ด้วย Write แล้วรัน
7. PR: `gh pr create` → รอ `gh pr checks --watch` → ถามเจ้าของ → `gh pr merge <n> --merge`
8. ไฟล์ `docs/ใบมอบหมายงานฝึกงาน-ทดลองระบบผลิต.pdf` ของเจ้าของไม่อยู่ใน git · **ห้าม `git add docs`** add ทีละไฟล์

## เรื่องค้าง / ข้อจำกัดที่รู้
- **ไม่มีปุ่มย้อนสถานะงาน:** "แจ้งว่ากดผิด" แค่บันทึก · ต้องย้อนจริง Claude แก้ใน DB (ถามเจ้าของก่อน)
- `resume_sewing` ไม่ตรวจจักรใช้ร่วม (ตั้งใจ) · แอดมินแก้เลขที่ใบในหน้ารับงานให้ต่างจากใบร่าง → ใบร่างเดิมค้าง ต้องยกเลิกเอง (`cancel_confirmation_draft` · หน้าเว็บยังไม่มีปุ่ม)
- Realtime ไม่ฟัง `machine_types` / `confirmation_drafts` (เปลี่ยนแล้วเห็นเมื่อโหลดใหม่)
- ใบปะงานพิมพ์ได้แม้งานถูกยกเลิก · `capacity.ts` นับวันตามเขตเวลาเครื่อง · `npm audit` ระดับกลาง 4 รายการ (แพ็กเกจ PWA)
