# สำรองและกู้ข้อมูล

## อะไรสำรองอยู่ที่ไหน
| ข้อมูล | สำรองโดย | เก็บที่ |
|---|---|---|
| โครงสร้างฐาน ฟังก์ชัน กฎ ค่าตั้งต้น (สถานี เส้นทาง สินค้า จักร) | git (`supabase/migrations/`) | GitHub |
| งาน ประวัติ ปัญหา QC ใบร่าง บริษัทภายนอก โปรไฟล์ ฯลฯ (schema `public`) | `db-backup` ทุกอาทิตย์ 02:00 | Artifact `pp142-db-backup` ไฟล์ `pp142-<วันที่>.dump` (90 วัน) |
| รายการไฟล์ที่แนบ (`private.file_objects`) | `db-backup` | ไฟล์ `pp142-<วันที่>-files.dump` |
| บัญชีผู้ใช้ + รหัสผ่าน (แฮช) (`auth.users`, `auth.identities`) | `db-backup` | ไฟล์ `pp142-<วันที่>-auth.dump` |
| **ไฟล์ PDF ใบยืนยัน + รูปม็อคอัพ (R2)** | **`tools/r2-backup` บนเครื่อง PC** (ต้องตั้งครั้งแรก ↓) | โฟลเดอร์ที่เลือก |
| ค่าลับ Worker (`private.file_settings`, Worker secret) | ไม่สำรองโดยตั้งใจ | สำเนาในโฟลเดอร์ `.pp142-r2` ของผู้ใช้ PC |

- Artifact อยู่ได้ 90 วัน → **ดาวน์โหลดเก็บไว้นอก GitHub เดือนละครั้ง** (GitHub → Actions → db-backup → รันล่าสุด → Artifacts)
- ไฟล์สำรองมีข้อมูลลูกค้าและบัญชีผู้ใช้ · repo ต้องเป็น Private · เก็บไฟล์ที่ดาวน์โหลดในที่ที่คนนอกเปิดไม่ได้
- ไฟล์ R2 ไม่สำรองใน GitHub เพราะโควตา Artifact ของแพ็กเกจฟรีมี 500 MB ไม่พอ

## ตั้งสำรองไฟล์ R2 ลงเครื่อง (ทำครั้งเดียว · เจ้าของทำ)
1. Cloudflare → R2 → **Manage API tokens** → Create API token
   - Permissions: **Object Read only** · Specify bucket: **`pp142-files`** · TTL: Forever
   - กด Create → จด **Access Key ID** · **Secret Access Key** · และ **Account ID** (อยู่ในที่อยู่ `https://<Account ID>.r2.cloudflarestorage.com`)
2. สร้างไฟล์ `C:\Users\PC\.pp142-r2\r2-backup.env` (โฟลเดอร์เดียวกับค่าลับ R2 เดิม · ห้ามใส่ใน git · ห้ามส่งในแชต):
   ```
   R2_ACCOUNT_ID=<Account ID>
   R2_ACCESS_KEY_ID=<Access Key ID>
   R2_SECRET_ACCESS_KEY=<Secret Access Key>
   ```
3. รันครั้งแรก (เลือกโฟลเดอร์ที่มีสำรองต่อ เช่น โฟลเดอร์ Google Drive หรือฮาร์ดดิสก์ภายนอก · ไม่ใส่ `--to` = `C:\Users\PC\pp142-backup\r2`):
   ```
   node tools/r2-backup/pull.mjs --to "D:\pp142-backup\r2"
   ```
   ขึ้น `ไฟล์ใน R2 … · โหลดใหม่ … · ไม่สำเร็จ 0` = ใช้ได้
4. ตั้งให้รันเองทุกวันอาทิตย์ 03:00 (PowerShell · แก้ path ให้ตรง):
   ```
   schtasks /Create /SC WEEKLY /D SUN /ST 03:00 /TN "pp142 R2 backup" /TR "node \"C:\Users\PC\Desktop\รีเสิร์ทข้อมูล\Phappim-Process\tools\r2-backup\pull.mjs\" --to \"D:\pp142-backup\r2\""
   ```
   เครื่องต้องเปิดอยู่ · ปิดเครื่อง = รอบนั้นข้าม รอบหน้าโหลดที่ขาดให้เอง

### สคริปต์ทำอะไร
- อ่านรายการไฟล์ทั้งหมดใน bucket → โหลดเฉพาะไฟล์ที่ยังไม่มีในเครื่อง (ไฟล์ใน R2 ไม่ถูกแก้ทับ เพราะชื่อไฟล์ = ลายนิ้วมือเนื้อไฟล์)
- ตรวจขนาด + ตรวจเนื้อไฟล์กับชื่อ · ไฟล์เสียไม่บันทึก และนับเป็น "ไม่สำเร็จ"
- **ไม่ลบไฟล์ในเครื่อง** แม้ใน R2 จะลบไปแล้ว · กุญแจเป็นแบบอ่านอย่างเดียว แก้/ลบไฟล์ใน R2 ไม่ได้
- จดผลแต่ละรอบใน `last-run.txt` ในโฟลเดอร์สำรอง (เวลา · จำนวนไฟล์ · โหลดใหม่ · ไม่สำเร็จ)
- ทดสอบ: `cd tools/r2-backup && npm test`

## กู้ข้อมูล (ยังไม่ได้ซ้อมกับข้อมูลจริง)
ลำดับ: สร้างฐานจาก migration → บัญชี (`-auth.dump`) → ข้อมูลงาน (`.dump`) → รายการไฟล์ (`-files.dump`) → อัปโหลดโฟลเดอร์ R2 กลับเข้า bucket ตามชื่อเดิม (`confirmations/…` `mockups/…`)
- ข้อควรระวัง: migration ใส่ค่าตั้งต้นไว้แล้ว → ข้อมูลจาก `.dump` ชนกับค่าตั้งต้น ต้องล้างตารางก่อนลงข้อมูล · trigger ตอนลงข้อมูลอาจสร้างแถวซ้ำ (เช่น กล่องจดหมาย)
- ก่อนกู้จริงควรซ้อมบนเครื่องด้วย Docker (เหมือน `tools/load-test`) แล้วเขียนขั้นตอนเป็นคำสั่งไว้ที่นี่
