# สำรองและกู้ข้อมูล

## อะไรสำรองอยู่ที่ไหน
| ข้อมูล | สำรองโดย | เก็บที่ |
|---|---|---|
| โครงสร้างฐาน ฟังก์ชัน กฎ ค่าตั้งต้น (สถานี เส้นทาง สินค้า จักร) | git (`supabase/migrations/`) | GitHub |
| งาน ประวัติ ปัญหา QC ใบร่าง บริษัทภายนอก โปรไฟล์ ฯลฯ (schema `public`) | `db-backup` ทุกอาทิตย์ 02:00 | Artifact `pp142-db-backup` ไฟล์ `pp142-<วันที่>.dump.gpg` (เข้ารหัส · 90 วัน) |
| รายการไฟล์ที่แนบ (`private.file_objects`) | `db-backup` | ไฟล์ `pp142-<วันที่>-files.dump.gpg` |
| บัญชีผู้ใช้ + รหัสผ่าน (แฮช) (`auth.users`, `auth.identities`) | `db-backup` | ไฟล์ `pp142-<วันที่>-auth.dump.gpg` |
| **ไฟล์ PDF ใบยืนยัน + รูปม็อคอัพ (R2)** | **`tools/r2-backup` บนเครื่อง PC** ทุก 2 อาทิตย์ วันอาทิตย์ 03:00 (ตั้งแล้ว 20 พ.ย. 2569) | `C:\Users\PC\pp142-backup\r2` |
| ค่าลับ Worker (`private.file_settings`, Worker secret) | ไม่สำรองโดยตั้งใจ | สำเนาในโฟลเดอร์ `.pp142-r2` ของผู้ใช้ PC |

- Artifact อยู่ได้ 90 วัน → **ดาวน์โหลดเก็บไว้นอก GitHub เดือนละครั้ง** (GitHub → Actions → db-backup → รันล่าสุด → Artifacts)
- ไฟล์สำรองมีข้อมูลลูกค้าและบัญชีผู้ใช้ → **เข้ารหัสด้วยรหัส `BACKUP_PASSPHRASE`** (GitHub Secret) ก่อนอัปโหลด เพราะ repo สาธารณะใครก็ดาวน์โหลด Artifact ได้ · **รหัสนี้หาย = กู้ไฟล์สำรองไม่ได้** เก็บไว้ในที่ปลอดภัยนอก GitHub ด้วย · ไม่มี Secret นี้ งานสำรองจะหยุดเอง (ไม่อัปโหลดไฟล์เปล่า)
- ถอดรหัสก่อนใช้: `gpg -d -o pp142-<วันที่>.dump pp142-<วันที่>.dump.gpg` (Windows: ติดตั้ง Gpg4win) แล้วใส่รหัส
- ไฟล์ R2 ไม่สำรองใน GitHub เพราะโควตา Artifact ของแพ็กเกจฟรีมี 500 MB ไม่พอ

## ตั้งสำรองไฟล์ R2 ลงเครื่อง (ตั้งแล้วบนเครื่อง PC · ทำใหม่เมื่อเปลี่ยนเครื่องหรือเปลี่ยนกุญแจ)
1. Cloudflare → R2 → **Manage API tokens** → Create API token
   - Permissions: **Object Read only** · Specify bucket: **`pp142-files`** · TTL: Forever
   - กด Create → จด **Access Key ID** (32 ตัว) และ **Secret Access Key** (64 ตัว) · **Token value ไม่ใช้**
   - **Account ID** = `f2c354fe6cc1dbb059d48057d736168b` (ไม่ใช่ค่าลับ · ดูได้ที่ R2 → Overview หรือเลขหลัง `dash.cloudflare.com/`)
2. สร้างไฟล์ `C:\Users\PC\.pp142-r2\r2-backup.env` (ห้ามใส่ใน git · ห้ามส่งในแชต) · ใส่ค่าตรงๆ **ไม่มี `<>` ไม่มีเครื่องหมายคำพูด**:
   ```
   R2_ACCOUNT_ID=f2c354fe6cc1dbb059d48057d736168b
   R2_ACCESS_KEY_ID=ใส่ Access Key ID ตรงนี้
   R2_SECRET_ACCESS_KEY=ใส่ Secret Access Key ตรงนี้
   ```
3. รันครั้งแรก (ไม่ใส่ `--to` = เก็บที่ `C:\Users\PC\pp142-backup\r2` · อยากเก็บที่อื่น เช่น Google Drive ใส่ `--to "D:\pp142-backup\r2"`):
   ```
   node tools/r2-backup/pull.mjs
   ```
   ขึ้น `ไฟล์ใน R2 … · โหลดใหม่ … · ไม่สำเร็จ 0` = ใช้ได้ · ขึ้น `Invalid URL` = Account ID ผิด หรือมี `<>` ติดอยู่
4. ตั้งให้รันเองทุก 2 อาทิตย์ วันอาทิตย์ 03:00 (PowerShell):
   ```
   $action = New-ScheduledTaskAction -Execute (Get-Command node).Source -Argument '"C:\Users\PC\Desktop\รีเสิร์ทข้อมูล\Phappim-Process\tools\r2-backup\pull.mjs"'
   $trigger = New-ScheduledTaskTrigger -Weekly -WeeksInterval 2 -DaysOfWeek Sunday -At 3:00AM
   $settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Hours 2)
   Register-ScheduledTask -TaskName "pp142 R2 backup" -Action $action -Trigger $trigger -Settings $settings
   ```
   ปิดเครื่องตอนถึงเวลา = รันเองเมื่อเปิดเครื่องครั้งถัดไป · ลองรันทันที: `Start-ScheduledTask -TaskName "pp142 R2 backup"` แล้วดูบรรทัดล่าสุดใน `last-run.txt`

### สคริปต์ทำอะไร
- อ่านรายการไฟล์ทั้งหมดใน bucket → โหลดเฉพาะไฟล์ที่ยังไม่มีในเครื่อง (ไฟล์ใน R2 ไม่ถูกแก้ทับ เพราะชื่อไฟล์ = ลายนิ้วมือเนื้อไฟล์)
- ตรวจขนาด + ตรวจเนื้อไฟล์กับชื่อ · ไฟล์เสียไม่บันทึก และนับเป็น "ไม่สำเร็จ"
- **ไม่ลบไฟล์ในเครื่อง** แม้ใน R2 จะลบไปแล้ว · กุญแจเป็นแบบอ่านอย่างเดียว แก้/ลบไฟล์ใน R2 ไม่ได้
- จดผลแต่ละรอบใน `last-run.txt` ในโฟลเดอร์สำรอง (เวลา · จำนวนไฟล์ · โหลดใหม่ · ไม่สำเร็จ)
- ทดสอบ: `cd tools/r2-backup && npm test`

## กู้ข้อมูล (ยังไม่ได้ซ้อมกับข้อมูลจริง)
ลำดับ: สร้างฐานจาก migration → บัญชี (`-auth.dump`) → ข้อมูลงาน (`.dump`) → รายการไฟล์ (`-files.dump`) → อัปโหลดโฟลเดอร์ R2 กลับเข้า bucket ตามชื่อเดิม (`confirmations/…` `mockups/…`)
- ข้อควรระวัง: migration ใส่ค่าตั้งต้นไว้แล้ว → ข้อมูลจาก `.dump` ชนกับค่าตั้งต้น ต้องล้างตารางก่อนลงข้อมูล · trigger ตอนลงข้อมูลอาจสร้างแถวซ้ำ (เช่น กล่องจดหมาย)
- ก่อนกู้จริงควรซ้อมบนเครื่องด้วย Docker (เหมือน `tools/load-test`) แล้วเขียนขั้นตอนเป็นคำสั่งไว้ที่นี่
